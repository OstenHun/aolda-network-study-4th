# 새 교재 작성 안내

요약: 새 교재는 Markdown·과정 등록으로 생성하고 기존 교재는 필요한 범위에서 고친다. 공개 전 내부 맥락·접속 정보를 분리하고 원문·최종 출력·실제 화면과 다운로드를 확인한다. 빌드만으로 배포하지 않는다.

## 제작 순서

새 주차는 Astro로 제작하는 것을 기본으로 한다. 기존 정상 교재는 필요한 변경 범위에서 유지하며 이 결정을 일괄 이전으로 확대하지 않는다.

1. 실제 제작할 주차나 심화 모듈의 범위를 정한다. 미제작 전체 주차를 빈 화면으로 만들지 않는다.
2. `tools/templates/lesson.md` 또는 `review.md`를 필요한 `content/materials/` 폴더로 복사해 작성한다. 첫 H1 다음에 `요약:` 한 문장을 1~200자로 쓴다. 제목·요약을 별도 설정에 중복 입력하지 않는다.
3. `config/site.json`에 과정과 페이지를 등록한다. 기존 과정에 추가할 때는 `lessons`만 추가한다. HTML 출력 경로는 기존 파일과 겹칠 수 없다.
4. [공개 전 내용 검수](#공개-전-내용-검수)를 거쳐 원문·생성 결과·실제 화면을 확인한다. 배포는 별도 승인 범위로 진행한다.

## 공개 전 내용 검수

새 교재 작성과 기존 교재 수정에 모두 적용한다. 진행자 안내·출처·학습 홈·다운로드 원문도 같은 공개 범위다. 이 절이 검수 순서를 소유하며 공개 정보의 경계는 [운영 안내](OPERATIONS.md#공개-경계)를 따른다.

### 1. 작성 전에 자료를 나눈다

- 공개 교재에는 학습 질문·개념·명령·예제 조건·관찰 해석·공식 출처를 쓴다. 진행자 안내에는 재사용 가능한 준비·질문·대안만 둔다.
- 요청 날짜·개편 경위·제작/검수/게시 상태·실제 일정과 팀 편성·자원 준비 현황·참가자 수행 결과는 공개 저장소 밖의 운영·검수 기록에 둔다. 내부 기록을 복사한 뒤 이름만 지우는 방식으로 교재를 만들지 않는다.
- 내부 문서와 원시 증거는 공개 폴더에 임시로 넣지 않는다. 링크를 없앤 뒤 ‘팀 내부 안내’ 같은 대체 문구를 학습 화면에 남기지 않는다.

### 2. 학습자가 사용할 문장으로 작성한다

‘무엇을 언제 반영했는가’ 대신 ‘무엇을 배우고 어떤 조건에서 확인하는가’를 쓴다. 예를 들어 날짜가 붙은 적용 이력은 ‘핵심 개념과 질문 연결’로 바꾸고, 제작 진행 상황은 삭제한다. 자료의 범위가 일부라면 다루는 주제를 명확히 안내한다.

공식 자료의 발행일·확인일·정확한 인용, 실험의 측정 구간·조건, 예제와 직접 관찰의 구분은 유지한다. 날짜나 ‘미관찰’이라는 단어만 보고 일괄 삭제하지 않는다. 실습 권한·중단 조건·복구·대안도 보존한다.

실제 계정·접속 주소·VPN/VM 식별자·인증 정책은 일반 예제나 본인 값의 자리 표시로 바꾼다. 주소·접두사·포트·그림·질문·해설은 서로 일치시킨다. 실제 값을 그대로 두고 ‘설명용’이라는 표시만 붙이지 않는다. 가공한 예시는 가공 사실을 밝히고, 실제로 측정한 결과로 제시하지 않는다. 비밀번호·키·토큰은 예제에도 넣지 않는다.

#### 문장도 함께 검수한다

학습자가 한 번 읽고 무엇을 할지 알 수 있는지 확인한다. AI가 썼는지를 추측하거나 특정 단어를 일괄 금지하는 검사가 아니다. 초안과 수정문을 문단 단위로 비교하며 다음을 확인한다.

- 주어와 행동을 분명히 쓴다. ‘필수 완료 근거 보관’처럼 명사를 쌓기보다 ‘실행한 명령과 출력을 파일에 보관한다’처럼 할 일을 쓴다.
- 한 문장에 준비·실행·해석·예외가 겹치면 나눈다. 같은 주의사항이 반복되면 처음 필요한 위치에서 설명하고, 뒤에서는 필요한 조건만 짧게 짚는다.
- 낯선 용어는 처음 나올 때 뜻을 풀어 쓴다. ‘앱의 건강 상태’ 같은 직역은 ‘앱이 정상인지’처럼 문맥에 맞게 고친다. 표준 용어·명령·오류 메시지는 정확히 유지한다.
- ‘연결한다·확인한다·활용한다’로 끝나는 추상적인 안내는 무엇을 연결하고 어느 출력에서 확인하는지 밝힌다. 근거 없는 홍보 문구와 불필요한 제작 설명은 줄인다.
- 문장을 줄인 뒤에도 필수·선택·금지, 조건·예외·복구 방법, 수치·단위·부정 표현, 출처와 예제/실측의 구분이 같은지 대조한다. 인용문·코드·식별자·링크를 문체 교정 때문에 바꾸지 않는다.

이미 명확한 문장은 유지한다. 문서의 말투와 학습 순서를 불필요하게 바꾸지 않고, 질문 수·기록 칸·학습 부담도 늘리지 않는다. 주요 피드백은 위치·수정 전후·이유를 공개 저장소 밖의 검수 기록에 남긴다. 화면에서는 바뀐 문장뿐 아니라 앞뒤 문단과 표·그림도 함께 읽는다.

### 3. 변경 파일과 주변 문맥을 대조한다

원문의 수정 줄뿐 아니라 해당 절·목록·표 전체를 읽는다. 내부 문구를 지우면서 학습 조건·권한 확인·예제의 한계를 함께 삭제하지 않았는지 확인한다.

- 기존 교재는 Markdown과 대응 HTML을 함께 확인한다. 새 Astro 교재는 Markdown·등록 정보를 고치고 생성된 HTML을 확인한다.
- 학습 홈·진행자 안내·README·출처·다운로드 파일·코드 주석·예제 출력까지 검토한다. 파일명·숨은 주석·HTML 속성·링크·이미지 설명에도 내부 정보가 남지 않아야 한다.
- 화면 캡처·패킷·첨부 파일은 본문과 별도로 확인한다. 기기/인터페이스 메타데이터·사용자명·호스트명·다른 사람의 트래픽·인증 정보가 남지 않았는지 보고 필요한 부분만 가리거나 제외한다. 비공개 원본을 공개 검수의 첨부 근거로 넣지 않는다.
- 공통 템플릿·과정 설정을 바꾸었다면 홈·메뉴·목차·검색 결과·머리말/꼬리말처럼 그 설정을 사용하는 화면도 검토한다.

### 4. 자동 검사 후 실제 출력을 읽는다

```sh
npm ci --ignore-scripts
npm test
npm run build
```

공개 정보 검사는 저장소 원문을 확인하고, 조립된 HTML·다운로드 Markdown에도 내부 문구 검사를 적용한다. 홈·메뉴·검색에 합쳐진 문구도 빌드 실패 대상이다. 기존 CI가 같은 테스트·빌드를 실행하므로 실패하면 Pages 아티팩트 업로드·배포 단계로 넘어가지 않는다.

자동 검사는 알려진 패턴과 파일 형식을 확인한다. 실제 주소·새로운 내부 표현·이미지 속 글자·문장의 적절성까지 판정하지 못하므로 통과 후에도 사람이 확인한다. 검출되면 원문을 고치고 재생성한다. 검사를 끄거나 생성물만 고쳐 통과시키지 않는다. 정상적인 출처나 학습 예제가 오탐이면 그 근거와 허용 사례 테스트를 함께 확인해 검사 범위를 좁힌다.

변경된 각 페이지를 데스크톱·모바일의 실제 읽기 크기로 열어 제목·본문·안내·표·그림·출처·푸터를 읽는다. 한국어 줄바꿈·잘림·겹침과 링크·검색·메뉴·원문/답안 다운로드를 확인한다. 공통 요소를 바꾸면 영향을 받는 페이지도 포함하고, 교정 후 해당 화면을 다시 확인한다. 다운로드 파일은 실제로 열어 화면에서 제거한 정보가 남지 않았는지 확인한다.

### 5. 확인 결과와 공개 반영을 구분한다

검수 기록에는 변경 범위, 제외/일반화한 정보의 종류, 보존한 학습 조건, 실행한 검사와 결과, 읽은 페이지·화면 폭, 남은 미확인 범위를 적는다. 실제 민감 값·원시 출력·개인 수행 자료는 다시 붙이지 않는다. 기록은 공개 저장소 밖에서 보관하고 커밋할 파일 목록도 확인한다.

원문·자동 검사·실제 출력 중 하나라도 미확인이면 그 범위를 남기고 검수 완료로 처리하지 않는다. 배포는 승인된 범위에서 진행하며 Actions 성공과 실제 사이트·다운로드·검색 반영을 각각 확인한다. 과거 커밋·검색 캐시·이미 전달된 사본에서의 삭제는 현재 파일 수정과 별도 작업이다.

## 과정과 페이지 등록 예시

다음은 설정 형식을 설명하는 예시다. 해당 자료를 실제로 작성한 뒤 기존 배열에 항목을 추가한다. 번호·상태·주제는 실제 제작 범위에 맞춘다.

`groups`에 들어가는 과정:

```json
{
  "id": "week-05",
  "label": "5주차 · DNS",
  "prefix": "materials/week-05/",
  "entry": "materials/week-05/concepts.html",
  "section": "common",
  "number": "05",
  "sidebar_title": "DNS",
  "nav": [],
  "home": {
    "title": "5주차 · 이름으로 서버 찾기",
    "description_html": "DNS · 캐시 · 조건 변경",
    "tag": "교재 · 복습",
    "arrow": "→"
  }
}
```

`lessons`에 들어가는 페이지:

```json
[
  {"id":"week05-concepts","source":"materials/week-05/CONCEPTS.md","output":"materials/week-05/concepts.html","group":"week-05","kind":"lesson","label":"개념 교재"},
  {"id":"week05-review","source":"materials/week-05/REVIEW.md","output":"materials/week-05/review.html","group":"week-05","kind":"review","label":"복습 문제"},
  {"id":"week05-answers","source":"materials/week-05/ANSWERS.md","output":"materials/week-05/answers.html","group":"week-05","kind":"lesson","label":"분리 해설"}
]
```

페이지 등록 순서가 하위 메뉴 순서다. 제목은 Markdown H1에서 읽고 메뉴에는 `label`을 쓴다. 새 페이지를 `nav`에 다시 적을 필요는 없다. 기존 HTML만 별도로 연결할 때 `nav`에 `path`·`label`을 넣는다. `documents`는 기존 Markdown과 HTML의 대응표이며 새 교재는 자동 등록한다.

후속 심화는 과정의 `section`을 `advanced`로, `number`를 `S01` 등의 표시로 정한다. 같은 페이지 생성·검색·검사를 사용한다. `partial`은 기존 본문 일부를 표시하는 구분이며 완료된 주차로 바꾸지 않는다. `home`은 홈에 노출할 실제 자료가 있을 때 추가한다. 설명은 일반 문장을 쓰고 필요한 경우에만 `keep-phrase` span을 사용한다.

## 링크·목차·복습 답안

- H2·H3로 목차를 자동 생성한다. Astro의 제목 앵커를 사용하며 기존 수동 HTML의 앵커는 바꾸지 않는다. 안정된 짧은 앵커가 필요하면 본문에 `<span id="rtt"></span>`처럼 명시하고 중복을 피한다.
- 새 Markdown에서 `[분리 해설](ANSWERS.md)`처럼 원문 기준 상대 링크를 쓴다. 등록된 교재는 생성된 `.html`로 연결한다. 기존 교재는 `documents` 대응표를 사용한다. HTML 화면 링크도 상대 경로로 쓸 수 있다.
- 원문 다운로드는 `<a download href="CONCEPTS.md">교재 원본</a>`처럼 명시한다. 각 새 교재 하단에도 원본 다운로드를 제공한다. 코드 블록 속 링크 문자열은 바꾸지 않는다.
- `kind: "review"`는 `## Q1. 질문` 또는 `### Q1. 질문` 형태의 고유 번호마다 입력칸을 붙인다. 답안 다운로드·저장 확인·수정 후 이동 경고는 기존 복습 방식과 같다. 입력은 서버나 브라우저 저장소에 자동 저장하지 않는다. 해설은 별도 `lesson` 페이지로 작성한다.
- Markdown 표에는 가로 스크롤을 붙인다. 공통 CSS와 16px 본문·한국어 어절 줄바꿈을 적용한다. 새 대화형 모형은 별도 구현·검증 대상이며 Astro가 학습 기능을 자동으로 만들어 주지는 않는다.

## 로컬 검사와 미리보기

```sh
npm ci --ignore-scripts
npm test
npm run build
python -m http.server 8000 --directory dist
```

`http://localhost:8000`에서 연다. 정적 파일의 상대 경로를 사용하므로 실제 Pages 하위 경로에서도 같은 연결을 유지한다. 검수할 때는 하위 경로를 포함한 로컬 경로에서도 깊은 링크·새로고침·목차·검색·메뉴·원본/답안 다운로드를 확인한다.

빌드는 공개 소스와 캡처 형식, 중복 출력·경로 이탈, 존재하지 않는 내부 링크·HTML 앵커, 새 교재의 중복 ID·복습 번호를 검사한다. 검사 실패를 무시해 게시하지 않는다. 외부 URL의 현재 응답·기술 내용의 정확성·실제 실습·화면 읽기는 별도로 확인한다.

자동 테스트는 실제 Astro로 비공개 심화 예시 네 페이지를 만들고 중첩 `index.html`·공통 홈·메뉴·검색·다운로드·링크 변환을 확인한다. 시험 입력은 특정 주차 본문에 의존하지 않으며 실제 교재가 늘어도 함께 검사한다. 동시에 기존 페이지의 본문·스타일·스크립트가 변하지 않는지 검사한다. 예시는 메모리에서만 넣으므로 정상 `dist/`나 학습 메뉴에 게시되지 않는다.

## 변경 경계

기존 1주차는 Astro로 옮기지 않는다. 4주차 실제 제작에서는 기존 일부 초안의 Markdown을 이어 쓰고 대응 수동 HTML 두 개만 제거해 같은 공개 경로를 Astro로 생성한다. 새 교재와 이 전환 대상에 Astro를 사용하고 Python은 나머지 기존 파일 조립과 검사를 유지한다. 수동 HTML이 남아 있으면 등록 출력과 충돌하므로 빌드가 실패한다. 생성된 HTML·임시 `.astro-input/`·`.astro-output/`·`dist/`는 수정하거나 커밋하지 않는다. 공통 디자인·동작을 바꿀 때는 기존 페이지를 포함해 회귀 확인한다.

잠금 파일을 커밋하고 설치는 `npm ci --ignore-scripts`로 재현한다. 원격 CI와 배포 상태는 로컬 검사 결과와 구별한다. `main`에 push하면 기존 Pages 워크플로가 배포하므로 배포 승인이 없을 때는 push하지 않는다.
