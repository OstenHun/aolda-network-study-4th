# 사이트 운영과 공개 범위

요약: 공개 원본을 GitHub에서 관리하고 검사된 정적 파일을 Pages에 배포한다. 내부 운영 자료는 분리하며 새 사이트 검증 동안 기존 ChatGPT 사이트를 유지한다.

## 공개 경계

이 저장소에는 학습에 필요한 공개 교재·HTML·실습 코드·공통 디자인·빌드 도구만 둔다. 내부 프로젝트의 명단·일정·실제 접속 정보·Notion 링크·원시 운영 증거·기존 Git 이력과 개인 설정은 옮기지 않았다. 제공 캡처는 루프백 IPv4 학습 트래픽이며 기기·인터페이스 메타데이터를 제거했다.

공개 정보 검사는 비밀키·토큰·이메일·개인 경로·내부 서비스 링크와 예제 캡처의 형식을 확인한다. 자동 검사만으로 모든 개인정보를 판정할 수 없으므로 새 파일과 스크린샷은 커밋 전에 내용을 직접 확인한다. 공개 저장소의 소스도 누구나 읽을 수 있다.

## 자료를 추가할 때

`content/`의 필요한 주차에 Markdown과 HTML을 추가한다. 새 주차 탐색은 `tools/study_site_theme.py`의 주차 정의와 홈 템플릿에 연결한다. 빌드는 공개 소스만 읽으며 과거 ZIP이나 로컬 내부 프로젝트를 참조하지 않는다. 새 파일은 빌드·링크 검사를 통과해야 한다.

공개 화면은 이 저장소를 직접 수정한다. 별도 내부 기록은 내부 프로젝트에 보관하고 공개 저장소를 덮어쓰는 자동 복사 작업을 두지 않는다. 기존 1주차 자료를 마이그레이션을 이유로 개편하지 않는다.

## 배포와 확인

`main` 변경 → 공개 정보·링크 검사 → Pages 아티팩트 업로드 → 배포 순서다. PR은 검사만 수행한다. Actions 성공과 실제 사이트 반영을 각각 확인한다. 사이트 주소는 README에서 확인한다.

배포 후 홈·주차별 깊은 링크·앵커·검색·모바일 메뉴·실습 모형·답안 Markdown 다운로드를 확인한다. 관련 전체 페이지를 100% 읽기 크기로 확인하고, 화면 변경이 없을 때도 데스크톱과 모바일에서 경로·자산 누락을 점검한다. 소스는 공개되지만 배포에는 `dist/`만 포함한다.

## 이전과 복구

기존 ChatGPT 사이트는 이번 이전으로 변경하거나 종료하지 않는다. 새 사이트 검증을 마친 뒤 Pages 주소를 기본 안내로 사용한다. 기존 주소의 종료·리디렉션은 별도 요청 때 진행한다.

잘못된 변경은 원인 커밋을 `git revert`한 뒤 `main`에 반영한다. 자동 검사·재배포 후 실제 URL에서 복구를 확인한다. 호스팅을 다시 옮길 때는 같은 빌드로 생성한 `dist/`를 사용한다. 로그인·온라인 진도 저장 등 서버 기능이 필요해지면 운영 구성을 다시 검토한다.

## 출처와 재사용

교재마다 공식 자료와 참고 출처를 유지한다. 공개 저장소 생성이 외부 자료의 재배포 권한을 바꾸지는 않는다. 기존 인용·예제와 직접 수행의 경계를 유지하며 라이선스가 필요한 새 외부 코드·이미지를 추가할 때 출처와 조건을 확인한다.
