# 14주차 · 복습 문제

요약: 두 계산 묶음의 단위·가정과 고전 혼잡 그래프를 확인하고, 실제 요청의 지연·분산·제외·복구 근거를 읽는다. 먼저 자기 설명을 만든 뒤 별도 해설과 비교한다. 입력은 자동 저장하지 않는다.

## 풀기 전에

[교재](CONCEPTS.md)·[직접 실습](LINUX.md)에서 배운 범위의 자체 문항이다. [해설](ANSWERS.md)은 별도 페이지다. 실제 실험을 못 했다면 제공 분석으로 표시하고 본인 수행은 보충한다. 수치에는 bit/byte·초/ms와 측정 경계를 붙인다.

## Q1. 두 링크의 첫 패킷

1,500byte 패킷을 저장 후 전달한다. R1=10Mbps, R2=100Mbps, 두 링크 각각200km, 전파속도200,000km/s. 출발 노드와 중간 라우터 각각 처리0.1ms·큐잉0.4ms, 목적지 추가 처리와 다른 비용은 제외한다. L에는 헤더가 포함됐다. 두 전송·두 전파 지연과 합을 계산하라.

## Q2. 빠른 링크만 더 빠르게

Q1에서 R2만1Gbps가 된다. 충분히 긴 패킷열의 이상적 병목 속도와 첫 패킷 지연은 각각 어떻게 바뀌는가? 서로 다른 두 수치를 구별하라.

## Q3. BDP·유효 윈도

100Mbps·RTT100ms, cwnd80,000byte·rwnd200,000byte다. BDP, W, W/RTT 상한, 아직 ACK되지 않은30,000byte를 뺀 추가 송신 여유를 계산하라. 고정 윈도·충분한 데이터·손실/헤더/다른 비용 생략 조건을 붙여라.

## Q4. 한 조건씩 바꾸기

Q3에서 rwnd만40,000byte로 줄인다. 다음에는 그 상태에서 RTT만50ms로 줄인다. 각 상한과 실제 HTTP 속도를 보장할 수 없는 이유를 설명하라.

## Q5. 제공 혼잡 그래프

[그래프](CONCEPTS.md#window)의 라운드0\~3,3\~7,7→8,10→11을 설명하라. 세 중복 ACK 뒤 복구와 타임아웃 뒤 반응을 구별하고, rwnd=4SMSS이면 무엇이 달라지는지 말하라. 이 모형으로 현재 OS의 모든 TCP를 설명할 수 있는가?

## Q6. 첫 응답 시간이 늘었다

[제공 사례](../../labs/week-14/observations.txt)의 latency에서 요청 수·HTTP 오류 수와 각 단계 시간 범위를 읽어라. `first_s−connect_s`가 순수 망 RTT인지 판단하고 서로 다른 가설 두 개·구별할 관찰을 말하라. 본인 실험이 있으면 실제 명령/로그와도 대조하라.

조건을 바꿔 [가공 분포](CONCEPTS.md#operational-bridge)의 A·B를 비교하라. 평균·p95·p99를 주어진 nearest-rank 방식으로 구하고, 평균과 HTTP 오류 수만으로 일부 사용자의 대기를 판단할 수 있는지 설명하라.

## Q7. 살아 있지만 제외된 서버

enabled=[a], health={a:true,b:true}, eligible=[a]다. 실제 요청6회의 X-Backend는 모두a이고 HTTP200이다. b가 고장났다고 결론 낼 수 있는가? 복귀를 확인할 구체적 근거는 무엇인가?

다른 조건에서 기존 연결의 GET은200, 같은 출발지·목적지의 새 TCP 연결은 timeout이다. [연결 사례](CONCEPTS.md#operational-bridge)에서 정책·상태와 자원 부족을 경쟁 가설로 세우고, 둘을 구별할 다음 관찰을 골라라. 증상만으로 원인을 확정하지 않는다.

## Q8. 상태 조회와 서비스

enabled=[a,b], health는 둘 다false, eligible=[]다. `/status`는200이고 `/echo`는503이다. 이 결과를 설명하고 복구 확인 순서를 말하라. 상태 확인 직후 선택한 서버가 멈추면 어떤 오류도 가능한가?

## Q9. 직접 수행과 진단의 범위

한 Linux호스트의 두 포트에서 분산·제외·정지·복구를 직접 확인했다. 어떤 장애 범위를 검증했는가? O04/O05에 필요한 본인 요청 수·오류·시간·양쪽 로그·두 원인 가설·복구 근거를 짚어라. 제공 출력만 읽었거나 아직 실행하지 않았다면 남은 수행을 구별하라.
