# 14주차 · 느린 요청과 서버 분산을 근거로 설명하기

요약: 지연 네 성분·병목·BDP·윈도 제한을 계산하고 고전 혼잡 그래프를 읽는다. 같은 HTTP 요청의 정상·서버 지연을 비교한 뒤 준비된 프록시와 두 서버에서 분산·제외·복구를 직접 확인한다.

## 이번 주의 질문

**요청이 느리면 네트워크가 느린 걸까? 서버 하나를 제외하면 서비스가 정상으로 돌아올까?** [6주차 HTTP 시간](../week-06/CONCEPTS.md)과 [13주차 양끝 요청·로그](../week-13/LINUX.md)를 재사용한다. TCP가 연결되거나 상태 확인이 성공했다는 사실만으로 실제 요청까지 정상이라고 판단하지 않는다.

## 함께 공부하는 순서

1. [공동 질문 W14-D1](WORKSHEET.md)에서 먼저 비교할 관찰을 고른다.
2. [교재 K1\~K3](CONCEPTS.md)와 [짧은 공식 지정 절](SOURCES.md)을 함께 읽는다. 두 작은 계산 묶음과 제공 그래프를 설명한다.
3. 한 명이 근거로 설명한 뒤 다른 사람이 윈도나 서버 대기 조건 하나를 바꿔 묻는다. 다음 설명자는 교대한다.
4. [실험 A](LINUX.md#delay-lab)에서 같은 요청을 정상→서버 대기→정상으로 제한 반복한다. [실험 B](LINUX.md#proxy-lab)에서 두 서버의 응답 분산·한 서버 제외·복귀와 정지·복구를 직접 대조한다.
5. [복습 문제](REVIEW.md)를 먼저 풀고 [분리 해설](ANSWERS.md)에서 조건·근거를 대조한다. [진행자 안내](FACILITATOR.md)는 막힐 때 돌아갈 설명과 시간 배치를 제공한다.

## 필수와 선택

| 구분 | 이번에 할 일 |
| --- | --- |
| 필수 계산·제공 분석 | 지연 성분·L/R·병목, BDP·이상화한 W/RTT의 두 묶음과 cwnd/rwnd·고전 혼잡 그래프 |
| 필수 직접 수행 A | 동일한 짧은 HTTP GET을 각 단계 5회, 정상·서버 대기 0.2초·복구로 비교. 상태·시간·서버 로그를 대조 |
| 필수 직접 수행 B | 준비된 프록시/서버 두 프로세스 조회·실행, 식별자별 요청 수·상태·시간, 한 서버 제외·복귀와 정지·복구 |
| 선택·후속 | 독립 프록시 초기 구축, Nginx 등 운영 제품, 대규모 부하·p99·재시도 증폭·관측 플랫폼 |

필수 실험은 자기 허가된 Linux 한 대의 루프백에서 가능하다. 서로 다른 포트의 두 프로세스는 호스트 장애 검증이 아니다. 접속·실행이 안 되면 [제공 사례](../../labs/week-14/observations.txt)로 분석하되 직접 수행은 보충한다. 한 사람의 시연·제공 출력만으로 각자의 분산·전환이나 O04/O05 운영 확인을 마치지 않는다.
