# 1주차 핵심 정리 — 요청·응답·실행 위치

요약: 실행 위치·IP와 포트·응답과 연결 실패를 세 문장으로 정리한다. localhost와 원격 VM, 404와 연결 실패를 구별하고 개발 상황을 기존 공통 질문에 연결한다.

- 사용법: 기존 개념 읽기의 마지막 5분과 공통 질문 하나를 이 자료로 대체한다. 별도 발표·활동지·필수 기록은 추가하지 않는다. 기존 실습 완료 기준은 유지한다.

## 꼭 기억할 개념 세 개

### W01-K1 · localhost는 실행 중인 호스트 자신이다

**기억 문장:** 같은 `127.0.0.1:8080`도 curl을 실행한 호스트가 바뀌면 다른 통신 끝점을 가리킨다.

SSH 터미널 안의 curl은 VM에서 실행되고, PC 터미널의 curl은 PC에서 실행된다. 창이 보이는 위치와 명령 실행 위치를 구별한다. ‘localhost는 항상 내 노트북’이라는 설명은 원격 셸에서 성립하지 않는다. [교재 1~2절](CONCEPTS.md).

### W01-K2 · IP·포트·프로세스는 서로 다른 단위다

**기억 문장:** IP는 통신 위치, TCP/UDP 포트는 해당 프로토콜의 통신 끝점을 구별하며 PID와 다르다.

같은 호스트에도 여러 주소·프로세스·소켓이 있고 프로세스 하나가 여러 소켓을 사용할 수 있다. 포트 번호만으로 실제 프로세스나 외부 접근 가능 여부를 확정하지 않는다. 1주차에서는 주소·서버 포트·임시 포트의 방향을 읽으면 된다. [교재 4절](CONCEPTS.md).

### W01-K3 · HTTP 응답과 연결 실패는 실패한 단계가 다르다

**기억 문장:** 404는 HTTP 응답이며, 연결 거부·연결 시간 초과와 구별한다.

404 응답의 의미와 실제 서버 로그를 함께 본다. 일반 서비스에서는 프록시가 응답했을 수도 있어 404만으로 원 서버 도달까지 확정하지 않는다. timeout만으로 서버 중지도 단정하지 않는다. [교재 5~7절](CONCEPTS.md), [RFC 9110 §15.5.5](https://www.rfc-editor.org/rfc/rfc9110.html#section-15.5.5).

## 헷갈리는 부분 두 가지

| 자주 섞는 설명 | 구별하는 방법 |
| --- | --- |
| 같은 URL이면 같은 서버다 | 명령을 실행한 호스트·이름 해석·포트·경로를 함께 확인한다. 이번 localhost 예제는 DNS 없이 호스트가 달라진다 |
| TCP로 도착하거나 HTTP 200이면 업무 처리가 끝났다 | 전송·HTTP 응답·업무 상태는 별도다. 404도 전달된 응답이고, 업무 성공은 API 계약과 응답 내용·상태 근거로 확인한다 |

## 개발 상황으로 설명하기

**출처 구분: 스터디 자체 문항.** 아래는 개념 확인용 사례이며 특정 기업의 실제 출제 문제·빈출 문항을 뜻하지 않는다.

VM 안에서 `/echo`는 200, `/missing`은 404다. PC 터미널에서 `http://127.0.0.1:8080/echo`를 호출하면 연결이 거부된다. 모두 설명용 조건이며 실제 참가자 결과가 아니다.

1. **W01-D1 · 설명:** 세 결과를 실행 위치와 실패 단계로 나누어 설명하라.
2. **W01-D2 · 조건 변경:** PC 요청을 VM IP로 바꾸면 반드시 성공할까? 아직 모르는 조건은?
3. **W01-D3 · 진단:** 서버 코드를 고치기 전에 가장 먼저 대조할 근거 두 가지는?

기존 질문 세 개 중 관련 질문 하나의 후속 발문으로 사용한다. 먼저 말하거나 짧게 적은 뒤 [개발 질문 해설](ANSWERS.md#개발-질문-해설)을 연다. 해설을 읽었다는 사실로 직접 수행·독립 설명 완료를 표시하지 않는다.

## 다음 주에 다시 설명하기
