1주차 학습 묶음 — 요청 하나를 끝까지 따라가기

요청·응답·실패를 함께 찾아 공부하고 Linux 실습으로 확인한다. 중심 질문에서 필요한 개념을 찾고 한 명이 설명한 뒤 조건을 바꾸어 비교한다. 실습 근거는 개인 파일에 보관한다.

함께 풀 질문에서 시작하기

같은 서버 주소에 요청했는데, 정상 응답·404·연결 실패는 어떻게 다를까? 함께 찾을 질문에서 출발한다. 교재와 공식 자료에서 필요한 설명을 함께 찾고 한 명이 근거로 설명한다. 다른 사람은 경로·서버 실행 상태를 바꾸어 물으며, 다음 질문에서는 설명자를 교대한다.

VM 접속이 처음이면 SSH 학습 홈에서 실행 위치와 접속 경로를 확인한다. HTTP 요청을 실행할 셸이 PC에 있는지 VM에 있는지 짧게 설명한 뒤 시작한다. 막히면 개념 교재의 호스트·루프백 설명을 찾아본다.

환경 준비는 필요에 따라 20~40분을 별도로 잡는다. 기본 개인 학습은 주 2~3시간을 제안하며 긴 발표 자료를 추가로 만들지 않는다. 진행자 안내에서 준비·진행·대안을 확인한다.

주제 하나만 찾아 읽기

  • 실행 위치와 localhost가 헷갈리면 개념 교재와 SSH 교재를 읽는다.
  • 같은 IP에서 프로그램을 구별하는 방법은 핵심 정리와 원문으로 배우기에서 찾는다.
  • 정상·404·연결 실패의 출력은 Linux 안내, 처리 흐름은 코드 읽기와 연결한다.
  • 직접 캡처가 막히면 제공 캡처 분석으로 패킷을 읽는다. 예제 분석과 본인 실행을 구분한다.

전체 개념 색인과 외부 참고자료에서도 필요한 개념을 찾을 수 있다. 선택 탐구와 CCNA 연계 연습·해설은 필수 실습을 마친 뒤 고른다.

이번 주 완료 기준과 근거 보관

각자 200·404·서버 중지·재시작의 명령과 양쪽 출력을 남긴다. 출력과 패킷을 주소·포트로 연결하고, 짝이 지정한 조건 하나를 바꿔 도움 없이 다시 실행한 뒤 복구한다. IP/포트, 루프백, 404와 연결 실패를 자기 말로 설명한다.

패킷 분석은 정상 요청 한 흐름이 필수다. 직접 캡처 또는 제공 예제 분석인지 표시한다. 추가 404·중지·복구 패킷 비교는 선택이며 못 본 항목은 미관찰로 둔다. 환경이 막혀 실행하지 못했다면 개념 활동을 이어가고 직접 실행은 보충으로 남긴다.

명령·로그·curl 출력·pcap은 개인 실습 기록이나 별도 파일에 한 번 보관한다. 함께 설명할 때 필요한 부분을 보여 주고, 메모는 필요에 따라 자유롭게 한다. 입력 화면을 사용했다면 이동 전에 내려받아 파일을 열어 확인한다.

실습 파일과 다음 질문

Python 서버가 기본이고 Node 클라이언트는 선택이다. 실행 키트에서 파일 역할을 확인한다.
