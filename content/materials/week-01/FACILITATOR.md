# 1주차 진행자 안내 — 요청과 응답 함께 확인하기

요약: 실행 위치·IP와 포트·HTTP 응답을 함께 설명하고 Linux 실습으로 확인한다. 환경 점검, 질문 연결, 오류별 대안과 개인별 확인 기준을 안내한다.

## 핵심 개념과 질문 연결

[핵심 정리](ESSENTIALS.md)를 읽고 공통 질문 하나에 설명 → 조건 변경 → 진단 발문을 연결한다. [분리 해설](ANSWERS.md#개발-질문-해설)은 먼저 답한 뒤 확인한다.

복습 질문: “지난 요청을 원격 셸 대신 PC 셸에서 실행하면 localhost의 대상이 어떻게 바뀌는가?”

## 시작 전 환경 점검

VM 접속이 처음이면 [SSH 준비와 해설](../ssh-top-down/FACILITATOR.md)부터 진행한다. 준비에 걸리는 시간에 맞춰 HTTP 실습을 나누어 사용한다.

| 확인 항목 | 확인할 근거 |
| --- | --- |
| 허용된 Linux 접속 | 본인이 셸을 열고 접속 대상·계정을 확인 |
| 같은 호스트의 두 셸 | 각 창의 hostname·현재 폴더 대조 |
| 실습 파일과 도구 | server.py 위치, Python·curl 버전 |
| 서버 시작·종료·복구 | listening·첫 200, Ctrl+C와 재시작 |
| 패킷 관찰 | lo와 캡처 권한, 불가하면 제공 캡처 준비 |
| 기록 보관 | 답안을 내려받고 실제 파일 열기 |

비밀번호·키·실제 접속 정보는 공동 기록에 적지 않는다. 실습 출력은 공유하기 전에 주소·호스트명 등 식별 정보를 가린다.

## 함께 읽고 설명하기

[개념 교재](CONCEPTS.md)의 실행 위치·IP/포트·HTTP와 TCP를 읽고 [팀 활동](WORKSHEET.md)의 질문을 함께 다룬다. 설명자는 질문마다 교대하고, 다른 사람은 조건 하나를 바꾸어 묻는다. 원출력은 한 번 보관하고 함께 설명할 때 필요한 근거를 찾는다.

## Linux에서 네 상태 비교하기

[Linux 안내](../../labs/week-01/LINUX.md)를 따라 정상 요청 → 404 → 서버 중지 → 같은 포트로 재시작을 각자 실행한다. 출력·서버 로그·패킷을 주소와 포트로 연결한 뒤 조건 하나를 독립 재현한다.

직접 캡처가 막히면 [제공 캡처](SAMPLE_CAPTURE.md)로 패킷을 분석한다. 제공 예제 분석과 본인 직접 캡처를 구분하고, 실제로 관찰하지 않은 항목은 채워 넣지 않는다.

## 흔한 오류와 대안

| 증상 | 먼저 확인할 것 | 이어갈 활동 |
| --- | --- | --- |
| 파일 없음 | pwd·ls·파일 전달 경로 | 파일 위치를 확인한 뒤 재실행 |
| 연결 실패 | 실행 호스트·서버 listening·URL | 같은 주소·포트로 중지와 복구 비교 |
| 포트 충돌 | 자기 서버 프로세스·사용 중인 포트 | 본인 서버만 종료하거나 양쪽 포트를 일관되게 변경 |
| 빈 캡처·권한 없음 | lo·캡처 시점·필터·권한 | 제공 캡처 분석, 직접 캡처는 별도 보충 |

자세한 명령은 [Linux 오류 표](../../labs/week-01/LINUX.md#환경이-막힐-때)를 따른다. 환경 문제 해결이 길어지면 시연·예제 분석으로 학습을 이어간다.

## 마무리 확인

각자 정상·404·연결 실패·복구의 차이, localhost의 실행 위치, 서버 포트와 임시 포트를 자기 말로 설명한다. [복습 문제](REVIEW.md)를 푼 뒤 [해설](ANSWERS.md)과 대조한다. 다른 사람의 실행이나 예제 열람을 본인 직접 수행으로 기록하지 않는다.
