1주차 팀 활동 — 함께 설명하고 이야기하기

개발 질문을 함께 다룰 때

핵심 정리의 개발 사례를 관련 질문 하나의 후속 발문으로 사용한다. 기존 세 질문과 팀 기록 세 항목·개인 마무리 두 줄 안에서 다루며 새 기록 칸을 추가하지 않는다. 시간이 부족하면 사례의 첫 질문만 설명하고 조건 변경·진단은 선택으로 둔다.

모임에서 사용하는 방법

개념 교재와 Linux 실습을 옆에 둔다. 개념 모임에서는 아래 질문 세 개를 함께 다루고, 실습 모임에서는 자기 출력으로 설명을 다시 확인한다. 팀당 4~5명을 기준으로 한 질문에 약 8분, 세 질문에 약 25분을 사용한다. 환경 준비와 실습 시간은 별도다.

모두 같은 질문을 생각한다. 질문마다 설명하는 사람을 바꾸고, 이번에 설명하지 못한 사람은 다음 회차에 먼저 기회를 갖는다. 긴 발표 자료는 준비하지 않아도 된다. 생각할 때 한 줄 메모는 선택이고, 기록은 이야기 뒤에 정리한다.

질문 하나를 다루는 순서

순서 시간 함께 할 일
각자 생각 1분 답과 이유를 먼저 생각한다. 바로 교재나 AI 답을 읽지 않는다.
한 사람 설명 2분 자기 말로 설명한다. 그림·명령·출력 중 하나를 보여줘도 좋다.
질문과 보완 3분 다른 사람은 궁금한 점, 다른 생각, 설명에 필요한 조건을 보탠다.
근거로 확인 2분 교재·실제 출력·패킷과 대조하고 함께 설명을 고친다.

설명이 막히면 진행자가 작은 질문으로 나눈다. 아직 실습하지 않은 결과는 예상이라고 말한다. 의견이 같아져도 근거가 없으면 확인할 질문으로 남긴다.

이번 주 함께 다룰 질문

1. 같은 IP에서 여러 서버 프로그램을 어떻게 구분할까?

  • 먼저 설명할 것: IP와 포트가 각각 무엇을 가리키는가?
  • 서로 물을 것: 서버 포트와 클라이언트의 임시 포트는 왜 다를까? 터미널 창 두 개가 호스트 두 대일까?
  • 확인할 근거: 정상 요청의 URL, 서버 listening 출력, 로그 또는 패킷의 양쪽 IP·포트. 교재의 IP·포트 설명과 대조한다.

2. 404가 나오면 서버 연결에는 성공한 걸까?

  • 먼저 설명할 것: 404 응답과 서버를 껐을 때의 연결 실패는 무엇이 다른가?
  • 서로 물을 것: HTTP 상태는 누가 보냈을까? curl 종료 코드와 HTTP 상태는 같은 값일까?
  • 확인할 근거: E2의 응답 상태·서버 로그와 E3의 curl 오류·HTTP 응답 유무. 교재의 네 상태 비교를 함께 읽는다.

3. 내 PC와 VM에서 127.0.0.1은 같은 곳일까?

  • 먼저 설명할 것: 요청을 실행한 호스트에서 127.0.0.1이 가리키는 곳은 어디인가?
  • 서로 물을 것: SSH로 연 두 셸은 어디에 있을까? VM 안의 통신을 관찰하려면 어느 인터페이스를 볼까?
  • 확인할 근거: 명령을 실행한 위치와 접속 대상, 정상 요청의 통신 그림, lo 캡처 또는 제공 예제. 서로 다른 실행의 주소·포트·패킷 번호를 한 그림에 섞지 않는다.

팀 기록 — 이야기 뒤 세 가지만

기록 담당 한 명을 정하고 회차마다 교대한다. 날짜·팀·참여자·설명한 사람은 첫 항목에 함께 적는다. 각 질문은 짧게 묶어서 기록하고, 파일이나 팀이 정한 공간에 공유한다. 이 페이지는 자동 저장·제출·팀 동기화를 하지 않으므로 입력했다면 내려받아 보관한다.

  1. 다룬 질문과 근거: 질문, 설명한 사람, 확인한 출력·그림·교재 위치. 실제 출력은 파일 이름·위치만 적어도 된다.
  2. 바뀐 설명: 처음 생각 → 확인 후 설명. 바뀌지 않았다면 무엇으로 확인했는지 적는다.
  3. 남은 질문: 아직 모르는 것과 다음에 확인할 방법. 없으면 ‘없음’으로 적는다.

개인 마무리 — 한 줄씩

  • 오늘 이해한 것 하나: 자기 말로 적는다.
  • 아직 헷갈리는 것 하나: 없으면 ‘없음’, 있으면 다음에 물어볼 질문으로 적는다.

팀 기록은 한 사람이 작성하되 개인 마무리는 각자 자기 사본에 남긴다. 팀 기록과 개인 메모를 한 파일에 넣어도 되며, 개인 메모의 공유 여부는 본인이 정한다.

실습 결과 보관과 미완료 구분

네 상태 직접 실행·정상 요청 한 흐름의 패킷 분석·조건 하나 독립 재현과 복구는 기존 실습 목표로 유지한다. 명령·서버 로그·curl 출력·pcap은 개인 실습 기록이나 별도 파일로 보관하고, 긴 원출력을 팀 활동 기록에 다시 옮겨 적지 않는다. 팀 활동에는 확인한 근거의 파일 이름·위치만 남겨도 된다. 근거 파일에는 수행자·실험 조건·직접 실행인지 제공 예제인지 구분할 수 있게 표시한다. 비밀번호·토큰은 기록하지 않는다.

함께 설명할 때 자기 근거를 보여주고 다른 사람의 질문에 답한다. 직접 실행하지 못한 항목은 팀 기록의 남은 질문에 이름·막힌 단계·보충할 행동을 남긴다. 팀 토론 참여와 본인 실습 완료는 구분한다. 제공 캡처 분석은 자기 Linux 실행과 다른 근거임을 표시한다.

상세 실습을 되짚고 싶다면 Linux 안내를 보며 예상·명령·관찰·바뀐 설명을 자유롭게 더 적는다. 추가 메모는 선택이다.
