중심 질문

같은 서버 주소에 요청했는데, 정상 응답·404·연결 실패는 어떻게 다를까?

먼저 지금의 예상을 짧게 말해 본다. 답이 막히면 개념 교재와 원문으로 배우기에서 필요한 부분을 함께 찾는다. 긴 발표 자료를 미리 준비할 필요는 없다.

함께 찾아 공부하는 순서

단계 함께 할 일 볼 자료
질문 고르기 요청을 어디서 실행하고 어떤 결과를 비교할지 정한다 중심 질문과 아래 보조 질문
공동 탐색 HTTP 상태와 연결 실패를 설명하는 절을 찾아 조건을 비교한다 개념 교재 · 공식 출처
한 명 설명 자료의 절과 출력에서 볼 위치를 가리키며 자기 말로 설명한다 실행 위치 그림·응답·로그
조건 변경 URL의 경로만 바꾸면 어떨지, 서버를 중지하면 어떨지 다른 사람이 묻는다 Linux 안내
직접 확인 정상 → 404 → 서버 중지 → 재시작을 각자 실행하고 예상과 비교한다 curl 출력·서버 로그·정상 요청의 패킷

설명자는 질문이나 회차마다 교대한다. 설명하지 않은 사람도 조건 변경에 답하거나 출력을 읽는다. 의견이 같아져도 근거가 없으면 다음에 확인할 질문으로 남긴다. AI 설명은 가설로 두고 공식 자료·실제 출력과 대조한다.

검색을 시작할 공식 절

  • RFC 9110 §15.3.1과 §15.5.5: 200과 404가 나타내는 상태를 읽는다.
  • curl 매뉴얼의 Exit codes: HTTP 상태 코드와 curl 종료 코드를 비교한다. 실습의 명령 옵션과 함께 읽는다.

원문이 어렵거나 열리지 않으면 한국어 교재와 원문 읽기 안내의 대응 설명을 사용하고, 원문을 읽은 것으로 표시하지 않는다.

선택 보조 질문

같은 IP에서 여러 서버 프로그램을 어떻게 구분할까?

IP와 포트가 가리키는 대상을 찾아본다. 서버 포트와 클라이언트 임시 포트는 어떻게 다를까? 서버의 listening 출력, 요청 URL, 로그·패킷의 양쪽 IP와 포트를 근거로 설명한다. 터미널 창 두 개를 호스트 두 대로 세지 않는다.

내 PC와 VM에서 127.0.0.1은 같은 곳일까?

명령을 실행한 호스트와 접속 대상을 먼저 그린다. SSH로 연 두 셸은 어디에 있을까? VM 내부 HTTP를 관찰할 인터페이스는 무엇일까? 실제 명령의 실행 위치와 lo 캡처 또는 제공 예제를 대조하며 서로 다른 실행의 주소·포트·패킷 번호를 섞지 않는다.

핵심 정리의 개발 사례는 관련 질문의 추가 발문으로 고른다. 모든 보조 질문을 같은 시간 안에 끝내는 것을 목표로 삼지 않는다.

실습 뒤 설명과 복습

네 상태를 직접 비교하고 정상 요청 한 흐름의 패킷을 읽는다. 조건 하나를 바꾸어 도움 없이 다시 실행한 뒤 복구한다. 복습 문제에 먼저 답하고 분리 해설과 대조한다. 상세 명령·출력·로그·pcap은 개인 파일이나 노트에 한 번 보관하고 함께 설명할 때 필요한 근거를 보여 준다. 메모는 선택이다.

직접 캡처가 막히면 제공 캡처 분석을 사용한다. 예제 분석·본인 직접 실행·미수행을 구분하며, 실행하지 못한 단계와 보충할 행동은 개인 실습 근거와 함께 남긴다. 비밀번호·토큰은 기록하지 않는다.
