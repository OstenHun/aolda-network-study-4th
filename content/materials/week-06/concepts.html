6주차 HTTP — 요청·응답과 연결 재사용

HTTP 요청·응답을 TCP 연결과 구별한 뒤 지속 연결이 줄이는 비용을 계산한다. RTT 정의·핸드셰이크는 4주차에 연결한다. 이번 본문은 6주차 교재 일부 초안이며 TLS·SSH 전체 교재와 실습은 준비 전이다.

W06-K1 · HTTP 요청과 응답을 연결 위에서 읽기

HTTP 요청은 메서드·대상 경로·헤더·필요한 본문을 담고, 응답은 상태 코드·헤더·필요한 본문으로 표현된다. 1주차의 200·404는 HTTP 응답이고 연결 거부는 그 응답 이전의 실패였다. 여기서는 TCP 위의 HTTP/1.1을 기준으로 연결 수립과 요청·응답을 나누어 본다. HTTPS라면 TLS 과정도 고려해야 한다. RFC 9110 §6.

기억 문장: HTTP 요청 하나가 TCP 연결 하나를 항상 뜻하지는 않는다. 이미 열린 연결에서 다음 요청을 보낼 수 있다.

W06-K2 · 같은 연결로 다음 요청 보내기

HTTP 지속 연결은 한 연결을 여러 요청·응답에 다시 쓰는 방식이다. 경로의 RTT 자체를 짧게 만드는 것과 구별한다. HTTP/1.1은 지속 연결이 기본이지만 서버·클라이언트가 닫거나 유휴 제한에 걸리면 재사용하지 못할 수 있다. RFC 9112 §9.3·§9.5.

연결 비용과 요청 비용 나누어 계산하기

4주차의 양방향 편도 50ms 모형을 이어 보자. 평문 HTTP 요청을 100ms에 보내면 이 모형에서 150ms에 서버에 도착하고 첫 응답 바이트가 약 200ms에 돌아온다. 그래서 새 연결의 작은 객체 비용을 연결 준비 1 RTT + 요청/첫 응답 1 RTT로 나눈다. 전체 본문 완료에는 전송 비용 등이 더해진다. HTTPS는 TCP 수립 뒤 TLS 조건까지 고려해야 한다.

아래 계산은 같은 서버의 작은 객체 N개, 캐시 없음, 병렬 연결 없음, 요청은 응답 뒤 하나씩 시작, HTTP 파이프라이닝·다중화 없음, DNS·TLS·처리·본문 전송·손실 무시를 전제로 한다. 첫 연결도 아직 없는 상태다.

방식 대기 비용 N=4, RTT=100ms
객체마다 새 TCP 연결 2N × RTT 8 RTT = 800ms
처음 한 번 연결 후 순차 재사용 (1+N) × RTT 5 RTT = 500ms
이미 열린 연결을 순차 재사용 N × RTT 4 RTT = 400ms

공식은 이 가정에서 직접 유도한 자체 계산이다. 실측·모든 웹페이지의 로딩 공식이 아니다. HTTP/2 다중화, 브라우저 병렬 연결, TLS, 자원 발견 순서, 서버 처리와 전송량이 바뀌면 별도 시간축을 그린다. HTTP/1.1의 파이프라이닝은 응답 순서를 지키며 HTTP/2 스트림 다중화와 다르다. MDN 연결 관리.

W06-K3 · 연결 재사용과 동시에 처리하기 구별

기억 문장: 연결을 다시 쓰는 것, 여러 요청을 겹쳐 전송하는 것, 로그인 상태를 기억하는 것은 각각 다른 기능이다.

혼동 구별과 반례
지속 연결이면 동시 요청·사용자 상태 유지까지 된다 연결 재사용·다중화·로그인 상태는 별개다. 순차 재사용도 지속 연결이다. 사용자 상태는 쿠키·세션 등 별도 설계와 연결된다
keepalive라는 이름이면 전부 연결 재사용 설정이다 HTTP keep-alive는 요청 사이 재사용, TCP keepalive는 유휴 연결의 반응 확인용 probe, fetch keepalive는 문서를 떠난 뒤에도 요청을 이어갈 수 있게 하는 옵션이다

TCP keepalive는 RFC 1122 §4.2.3.6, fetch 옵션은 MDN Request.keepalive를 확인한다. 이름만 보고 같은 기능으로 연결하지 않는다.

개발 상황으로 설명하기

자체 작성 사례: 같은 서버의 상품·리뷰 API가 각각 상품 ID만 필요하다. 현재 코드는 상품 응답이 끝난 뒤 리뷰 요청을 시작한다. 이 사례는 실제 서비스 측정 결과가 아니다.

  1. W06-D1 · 설명: 연결이 재사용돼도 왜 두 번째 요청이 기다릴까?
  2. W06-D2 · 조건 변경: 두 요청을 함께 시작하면 항상 전체 시간이 절반이 될까?
  3. W06-D3 · 진단: 브라우저 Network에서 무엇을 확인해야 개선을 판단할까?

답을 먼저 설명한 뒤 분리 해설을 읽는다. 기존 공통 질문의 후속 발문으로 사용하며 별도 활동지를 추가하지 않는다.

다음 학습과 준비 상태

현재 1주차 키트는 매 요청 연결을 닫는다. 반복 호출만으로 지속 연결을 관찰했다고 기록하지 않는다. 재사용 비교 실험은 HTTP 버전·본문 경계·클라이언트 재사용·캡처 조건을 맞추어 별도 준비·검증해야 한다. 이번 변경에서 실제 브라우저 성능이나 Linux 연결 재사용을 측정하지 않았다.

TLS의 암호화·서버 인증·인증서와 SSH의 사용자 인증은 6주차 커리큘럼의 남은 제작 범위다. HTTP/2·3와 WebSocket 심화도 현재 필수 본문을 늘려 모두 다루지 않는다. 전체 개념 색인.
