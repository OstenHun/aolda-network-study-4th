# 6주차 · HTTP·TLS·SSH

요약: HTTP 메시지·연결 재사용·캐시를 구별하고 TLS가 보호하는 내용과 서버 신원 검증을 확인한다. 같은 IP의 이름을 바꿔 실패·복구를 비교하며 SSH의 호스트 확인과 사용자 인증으로 이어 간다.

<span id="weekly-study"></span>

## 개인 공부와 오프라인 확인

오프라인 모임 전까지 아래 범위를 공부하고 실습을 시도한다. 모임은 그 주의 학습을 마무리하는 자리로, 막힌 이유와 조건을 바꾼 결과를 설명하고 남은 보충을 정한다. [공동 질문](WORKSHEET.md)은 개인 공부의 출발점으로 쓰고, 모임에서는 근거를 비교한다. 별도 사전 모임이나 발표 자료는 필요하지 않다.

- **개념·문제:** HTTP/1.1 메시지 경계·순차 재사용 비용, 신선한 캐시/304, TLS의 신뢰·SAN·기간·SNI, SSH 호스트/사용자 인증. [교재](CONCEPTS.md) → [공식 지정 절](SOURCES.md) → [복습](REVIEW.md) 순서로 읽고, 먼저 답한 뒤 [해설](ANSWERS.md)과 비교한다.
- **실습·분석:** HTTP 메시지·재사용 비교와 TLS 정상 이름→잘못된 이름→복구. 인증서 초기 생성은 준비자가 수행. SSH 인증 변경·HTTP/2·3 구축은 선택/후속. [실행 안내](LINUX.md)의 필수/선택과 제공 분석/직접 수행 구분을 따른다.
- **모임에 가져올 것:** 본인의 근거에서 고른 출력·풀이와 아직 설명이 막힌 질문. 개인 학습 노트에 한 번 정리하고 원시 로그·pcap은 파일 링크로 연결해도 된다. 새 제출 양식은 만들지 않는다.

### 개인 공부를 정리할 때

기존 개인 학습 노트에 아래 세 가지를 중심으로 정리한다. 모임 전에는 현재 답과 막힌 지점을 남기고, 모임 뒤에는 확인한 차이와 보충할 부분을 고친다. 정해진 개수·분량이나 새 제출물은 없다.

- **주요 질문과 내 답:** [공동 질문](WORKSHEET.md)과 아래 확인 질문에 먼저 내 말로 답한다. 이유·성립 조건과 공식 자료·실습 근거를 연결하고, [분리 해설](ANSWERS.md)은 시도 뒤에 비교한다.
- **헷갈리는 개념 비교:** [핵심 설명](CONCEPTS.md)에서 연결 재사용과 HTTP 캐시, 서버 신원과 사용자 인증의 역할·관찰 위치·성공 범위를 비교한다. 두 개념이 다른 결론을 내는 예를 들어 본다.
- **이번 주 꼭 기억하고 이해할 핵심 개념:** [핵심 정리](CONCEPTS.md)의 W06-K1~K3를 길잡이로 용어·역할·동작 순서를 추린다. 필요한 공식은 식·단위·성립 조건과 적용 이유를 함께 설명한다. 예제 주소·일회성 출력값을 외우는 목록으로 만들지 않는다.

실습 근거는 해당 질문·개념 아래에 예상·실제 관찰·수정한 이해와 함께 연결한다. 제공 분석과 직접 실행을 구별하고 관찰하지 않은 결과는 채우지 않는다. 입력 화면을 썼다면 이동 전에 답안을 내려받는다. [전체 개념 색인의 정리 방법](../CONCEPT_INDEX.md#personal-study)은 다른 주차에도 같은 방식으로 쓸 수 있다.

### 오프라인에서 확인할 질문

1. **중심 질문:** 같은 IP·CA인데 URL 이름만 다르면 TLS와 HTTP 관찰은 어떻게 달라질까?
2. **조건을 바꾸면:** 같은 연결을 재사용해도 요청이 순차로 기다릴 수 있는 이유는?
3. **앞 개념을 다시 쓰면:** 5주 DNS TTL, HTTP 캐시, 열린 연결은 각각 무엇을 재사용하는가?

중심 질문을 먼저 설명하고 나머지는 짧은 후속 질문으로 사용한다. [분리 해설](ANSWERS.md)과 실제 근거를 대조하되 답을 본 시도와 독립 설명을 구별한다. 개인 공부에서 마친 정상 실습을 전부 반복하지 않고, 막힌 항목과 한 조건 변경·복구를 각자 확인한다.

## 필수와 선택

필수 A는 HTTP 메시지·새 연결/재사용 RTT 계산·조건부 요청 제공 예제 분석이다. 실제 연결 재사용 실험 A2는 준비된 코드로 비교할 수 있다. 필수 B는 **각자 허가된 TLS 대상에 정상 요청→잘못된 이름→복구 요청**을 보내는 것이다. 진행자가 준비한 루프백 TLS 서버와 CA 공개 인증서를 사용하며 유료 도메인·외부 공개는 필요하지 않다. 준비가 막히면 제공 예제로 설명하고 직접 수행은 보충한다.

TLS 서버의 초기 구축, 추가 패킷 캡처, 새 SSH 접속·인증 방식 변경은 선택이다. 기존 SSH 경험 또는 제공 접속 기록에서 호스트 확인과 사용자 인증을 구별하는 설명은 필수다. 인증서 검증을 끄는 `-k`는 성공·복구 기준이 아니다. 전체 서비스 운영 능력은 이름·바인딩·정책 등 이후 근거까지 이어 확인한다.

## 무엇을 근거로 설명할까

HTTP의 메서드·경로·상태·헤더를 짚고, 재사용의 연결 식별자와 캐시 재검증의 ETag/304를 따로 읽는다. TLS는 URL 이름·신뢰 CA·SAN·유효기간·검증 결과와 정상 복귀를 보인다. 패킷에서 읽는 정보와 클라이언트가 복호화해 읽는 정보를 나눈다. SSH는 “서버를 믿을 근거”와 “사용자가 로그인할 근거”를 구별한다.

고정 팀 기록·개인 마무리 양식은 없다. 명령·출력은 개인 파일이나 노트에 한 번 보관하고 필요한 부분으로 설명한다. [전체 개념 색인](../CONCEPT_INDEX.md)에서 W06-K1~K3을 다시 찾는다.
