# 6주차 연결 재사용 본문 — 개발 질문 해설

요약: HTTP 교재의 개발 사례에서 연결 재사용·요청 의존성·측정 조건을 구별한다. 자체 작성 해설로 코드의 요청 순서와 프로토콜 동작을 나누어 설명한다.

- 먼저 [6주차 교재](CONCEPTS.md)의 W06-D1~D3을 설명한다.

## W06-D1~D3 · 요청 순서와 연결 재사용

1. 연결 재사용은 새 연결 비용을 줄이지만 코드에서 앞선 응답을 기다리도록 정한 순서는 바꾸지 못한다. 실제 데이터 의존성이 없다면 두 요청을 일찍 시작할 수 있다.
2. 항상 절반은 아니다. 프로토콜·연결 수·서버 처리·자원 경쟁·캐시·전송량과 시작 시점에 따라 달라진다. 동시에 시작하는 코드가 프로토콜 다중화를 직접 켜는 것은 아니다.
3. 같은 조건에서 프로토콜·연결 재사용·요청 시작 시점·의존 관계·Timing과 응답 완료 시간을 대조한다. 이 예시에는 실제 브라우저에서 측정한 성능 결과가 없다.

**흔한 오답:** 지속 연결이 RTT 자체를 줄인다, HTTP keep-alive와 TCP/fetch keepalive는 같다, 요청을 함께 시작하면 항상 절반으로 빨라진다. 코드 의존성·연결·프로토콜·처리·전송 조건을 붙여 설명한다.
