2주차 선택 탐구

필수 Linux 조회·두 카드 손계산·독립 설명을 마친 뒤 주소 조건과 경로 판단을 더 비교한다. 격리 마스크 변경은 권한·복구 사전 점검이 있을 때만 실행한다.

사용 방식A. 내 경로의 src와 via — 10~15분B. 주소 카드의 경계 — 10~15분C. 격리된 두 노드의 마스크 변경 — 사전 점검 뒤 15~20분D. 주소 분류와 접근 가능성 — 10분

사용 방식

함께 찾을 질문에서 더 확인하고 싶은 조건을 골라 아래 과제 하나로 이어 간다. 예상은 짧게 말해 보고 실제 출력·계산과 비교한다. 근거는 개인 파일이나 노트에 한 번 보관하고 별도 활동지 양식을 복사하지 않는다. 선택 과제는 공통 완료 조건을 늘리지 않는다. 제공된 출력·그림은 분석 자료로 표시하고 자기 Linux 실측으로 옮기지 않는다. 허용된 목적지만 조회하며 관리 NIC 주소·경로는 변경하지 않는다.

A. 내 경로의 src와 via — 10~15분

읽기 전용 ip -4 route get <허용된 목적지>에서 선택된 dev·src·via를 찾아 내 주소와 경로 조회의 ip -br -4 addr, ip -4 route와 맞춘다. 허용된 같은 망 목적지와 다른 망 목적지가 모두 있다면 둘의 출력을 비교한다. via가 없는 결과와 기본 경로가 없는 상태를 같은 뜻으로 일반화할 수 있는가? 출력이 알려 주는 것은 로컬 경로 선택이며 상대 도착·응답은 별도 확인이 필요하다는 점을 적는다. route get 자체를 통신 성공으로 기록하지 않는다.

B. 주소 카드의 경계 — 10~15분

192.0.2.63/26, .64/26, .127/26, .128/26을 각각 손으로 분류한다. 각 주소가 속한 네트워크와 브로드캐스트, 사용 가능한 호스트인지 먼저 쓰고 표준 라이브러리 검산기를 실행할 수 있다면 확인한다. 각 64개 묶음의 첫째·마지막 주소가 왜 일반 호스트 주소가 아닌지 설명한다. 이 카드는 문서 예제다.

C. 격리된 두 노드의 마스크 변경 — 사전 점검 뒤 15~20분

진행자가 사전 점검한 격리 VM의 네트워크 네임스페이스·veth 두 노드에 한정한다. 선택 시연 절차를 따라 .10/24와 .70/24의 양쪽 주소·경로표, A→B 경로 조회·ping을 확인하고, .10 쪽만 /26으로 바꾼다. 기본 경로가 없는 두 노드에서 같은 항목을 비교하고 .10/24로 복구한다. 주소 카드상 .10과 .70의 방향별 같은 망 판정, 실제 A→B 경로·ICMP 결과를 구분해 기록한다. B→A 조회·ping은 기본 시연에 없으며 직접 추가했다면 명령과 출력을 별도 기록한다. 반환 메시지를 미리 단정하지 말고 실측을 적는다.

관리용 SSH 인터페이스·기본 경로를 직접 바꾸지 않는다. VM·권한·격리·복구를 확인할 수 없다면 텍스트 모형으로 예상만 작성하고 구성 변경 실습은 미완료로 남긴다. 이 경우 선택 과제 C를 직접 수행했다고 표시하지 않는다. 선택 실험을 하지 않아도 필수 P1/P2는 완료할 수 있다.

D. 주소 분류와 접근 가능성 — 10분

내 조회 결과에서 루프백·사설 주소 여부를 분류하고, 나머지 주소가 보이면 출처를 확인한다. 주소 분류와 인터넷에서의 접근 가능성은 다른 질문이다. 실제 외부 접근 여부를 확인하지 않았다면 미확인으로 쓴다. 공개 IP 범위처럼 보이는 주소만으로 외부에서 연결된다고 말하지 않는다. RFC 1918의 사설 범위를 참고하되, 내 VM의 네트워크 정책은 실제 설정 근거가 있을 때만 설명한다.
