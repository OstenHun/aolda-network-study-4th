# 복습 · 변환·정책·서버를 구별하기

요약: 제공 NAT 표의 왕복 5튜플과 정책의 방향·순서·상태를 읽고, 허용·차단·서버 중지의 관찰 근거를 설명한다. 먼저 답한 뒤 별도 해설과 비교한다.

실행한 근거는 개인 파일을 재사용한다. 분석·실행·미수행을 구별하고 모르는 값은 만들어 넣지 않는다. [학습 홈](README.md) · [분리 해설](ANSWERS.md).

## Q1. PAT의 두 흐름

교재의 A·B는 내부 출발지 포트가 모두51000이다. 외부 주소도 같다. 두 흐름을 어떻게 구별하는가? B의 바깥 요청·바깥 응답·안쪽 응답의 TCP 5튜플을 적는다.

## Q2. UDP 응답

표의 C에 대해 원격 DNS 서버가 보낸 UDP 응답의 출발지·목적지 주소/포트를 바깥과 안쪽에서 각각 적는다. TCP B와 섞어 대응을 찾으면 왜 틀리는가?

## Q3. NAT와 허용

외부8080을 내부8080으로 DNAT하는 매핑이 있다. 이것만으로 HTTP 성공을 확정할 수 있는가? 추가로 확인할 두 조건과 정책을 읽을 관찰 위치를 말한다.

## Q4. 방향과 포트

A:51000이 서버:8080에 요청한다. 서버 input의 새 요청 규칙은 어느 주소·목적지 포트를 검사하는가? 상태 없는 반환 방향 규칙에서 목적지8080을 그대로 쓰면 어떤 점을 놓치는가?

## Q5. 규칙 순서

실습 input 체인의3번(.11만 accept)과4번(나머지8080 drop)의 순서를 뒤집는다. 새 A SYN은 어떻게 되는가? 앞쪽 established 규칙에 일치한 패킷도 같은 답인가?

## Q6. 상태와 규칙 변경

allow에서 block으로 바꿨는데 기존 연결이 계속 통신했다. 정책 변경 실패라고 바로 결론낼 수 있는가? 공용 추적 표를 비우지 않고 무엇을 비교할 것인가?

## Q7. 직접 비교와 복구

본인이 실행한 A1→A2→A3의 새 요청 결과·LISTEN·규칙 카운터·HTTP 로그를 설명한다. 정책 교체 후 카운터 초기화와 누적 로그를 어떻게 해석했는가? 직접 실행하지 않았다면 분석과 남은 수행을 나눈다.

## Q8. 중지와 DROP

같은 클라이언트에서 하나는 연결 거부, 하나는 제한 시간 실패였다. 어떤 원인을 우선 가정하며 무엇을 추가 조회할 것인가? HTTP404를 얻었다면 판단이 어떻게 달라지는가?
