# 진행자 안내 · 두 실패를 같은 조건에서 비교하기

요약: 개인 공부에서 개념·문제·실습을 준비하고 오프라인 한 번에서 설명·조건 변경·직접 수행을 확인한다. 준비·복구와 제공 분석의 경계를 지키며 막힌 필수 항목을 보충한다.

## 사전 준비

1. [실습 파일](LINUX.md#실행-환경과-파일)의 이름·LF·이미지 빌드를 확인한다. 각자 소유 프로젝트와 대역 충돌을 확인하고 다른 실습·관리망은 보존한다.
2. A의200, B의 DROP, A의 block/allow 복구와 서버 stop/start를 미리 재현한다. 실제 출력은 개인 파일에 한 번 보관한다.
3. [출처](SOURCES.md)의 필수 짧은 범위를 직접 열어 NAPT 대응과 input/forward·accept/drop을 찾는다. 긴 전체 RFC·매뉴얼 암기를 요구하지 않는다.
4. 접근 권한이 없으면 제공 분석과 남은 직접 수행을 구별한다. 도구 설치·공용 서버 권한 변경으로 모임 전체를 쓰지 않는다.

## 한 주의 개인 공부와 오프라인 확인

개인 준비는 [학습 홈의 정리 안내](README.md#personal-notes)에 따라 주요 질문과 내 답·헷갈리는 개념 비교·꼭 기억하고 이해할 핵심을 살핀다. 노트 분량을 평가하지 않고 이유·조건 변경·관련 실습 근거로 확인한다. 모임 뒤에는 틀린 설명과 남은 보충만 기존 개인 노트에서 고치며 중복 제출을 요구하지 않는다.

[학습 홈의 개인 공부 범위와 세 확인 질문](README.md#weekly-study)을 오프라인 모임 전까지 준비한다. 모임은 그 주 학습을 마무리하고 남은 보충을 정하는 자리다. 개념·공식 지정 절·복습과 준비된 실습의 정상→변경→복구는 개인 공부에서 시도한다. 모임 전 완성 답안·발표 자료를 요구하지 않으며 막힌 질문과 본인 근거를 가져오게 한다. 진단 원인을 가리는 과제는 정상 기준과 도구까지만 준비한다.

오프라인은 한 번의 모임에서 **설명 → 새 조건 → 본인 실습/분석 확인 → 보충 결정**으로 진행한다. 아래 60분은 시간 배분 예시이며 모임 길이나 추가 회차를 확정하는 표가 아니다.

| 시간 예시 | 진행자가 확인할 것 |
| --- | --- |
| 0~10분 | 개인 공부에서 막힌 질문과 2~4학습 단위 전 개념 하나를 골라 근거로 설명 |
| 10~25분 | 학습 홈의 중심 질문 → 조건 변경. 각자 시도한 근거·막힌 이유 비교 |
| 25~50분 | 제공 NAT 대응표 분석과 준비된 격리 정책의 허용→차단→복구. 이미 수행했다면 근거를 보고 다른 한 조건의 판단·변경·복구 확인 |
| 50~60분 | 정상 복구·받은 도움·미완료 구분, 개인 학습 노트에 필요한 보충과 다음 질문 연결 |

개인 학습 시간을 고정된 2~3시간으로 제한하지 않는다. 필수 범위를 먼저 공부하고 실제 막힘에 따라 시간을 배분한다. 주차를 미리 분할하거나 필수 기준을 낮추지 않으며, 개인 공부 후에도 해결되지 않는 항목만 보충한다. C04/C08/C12/C16은 해당 주 기존 설명·실습을 대체하고 점검을 별도로 더하지 않는다. 한 사람의 답·팀 합의·파일 제출은 개인 이해/직접 수행의 증거가 아니다.

## 막히는 지점에 줄 설명

- **8080을 양쪽 목적지로 적는다:** 요청과 응답의 화살표를 따로 그리고 화살표 오른쪽 포트를 읽게 한다.
- **표를 실제 캡처로 읽는다:** NAT CSV는 자체 제공 사례, 방화벽 요청은 직접 실행으로 구분한다. 실습의172.30 대역과 NAT 표의10.11 대역을 섞지 않는다.
- **타임아웃이면 서버 중지라고 한다:** LISTEN과 .11 DROP 카운터, 같은 시점의 로그를 보여 두 가설을 구별하게 한다.
- **허용을 먼저 찾고 끝낸다:** 좁은 accept 앞에 넓은 drop을 둔 작은 사례로 규칙 순서를 다시 묻는다. SG의 허용 집합과 일반화하지 않는다.
- **규칙 변경 후 기존 연결 성공을 실패로 본다:** established 앞 규칙을 찾고 새 TCP 연결로 다시 비교한다.

## 판정과 다음 단계

W11-K1~K3와 혼동 두 개는 교재·복습·개발 질문에서 확인한다. NAT 분석에는 관찰 위치·프로토콜·왕복 포트가 필요하다. 직접 수행에는 본인 규칙 전후·새 요청·서버 근거·복구가 필요하다. 결과를 설명하지 못하거나 명령을 대신 실행했다면 도움 후 보충 필요로 남긴다. 새 팀 기록·개인 마무리·발표 문서를 요구하지 않는다.

C12에서는 VLAN/STP/LACP·OSPF·NAT·정책이 바꾸는 것을 구별하며 앞 실습 근거를 재사용한다. 클라우드 O01/O03은 자기 자원에서 실제 설정·변경/원복을 확인할 때 연결한다. 컨테이너 결과로 클라우드 전체 수행을 완료 처리하지 않는다. 실제 NAT 구축·IDS/IPS·세부 위협 분석은 선택·후속으로 둔다.
