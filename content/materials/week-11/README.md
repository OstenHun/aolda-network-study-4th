# 11주차 · 주소가 바뀌는 것과 접속을 허용하는 것

요약: NAT/PAT 대응표에서 왕복 주소·포트를 읽고, 격리된 HTTP 서버의 접근 규칙을 직접 바꿔 허용·차단·복구를 비교한다. 경로·정책·서버 대기를 나누어 진단한다.

<span id="weekly-study"></span>

## 개인 공부와 오프라인 확인

오프라인 모임 전까지 아래 범위를 공부하고 실습을 시도한다. 모임은 그 주의 학습을 마무리하는 자리로, 막힌 이유와 조건을 바꾼 결과를 설명하고 남은 보충을 정한다. [공동 질문](WORKSHEET.md)은 개인 공부의 출발점으로 쓰고, 모임에서는 근거를 비교한다. 별도 사전 모임이나 발표 자료는 필요하지 않다.

- **개념·문제:** NAT/PAT 왕복 5튜플, input/forward/output, 방향·포트·규칙 순서, conntrack·기존/새 연결, SG/NACL 차이. [교재](CONCEPTS.md) → [공식 지정 절](SOURCES.md) → [복습](REVIEW.md) 순서로 읽고, 먼저 답한 뒤 [해설](ANSWERS.md)과 비교한다.
- **실습·분석:** 제공 NAT 대응표 분석과 준비된 격리 정책의 허용→차단→복구. 새 연결·LISTEN·카운터·로그 대조. 실제 NAT 구축·공용 추적 표 초기화는 하지 않음. [실행 안내](LINUX.md)의 필수/선택과 제공 분석/직접 수행 구분을 따른다.
- **모임에 가져올 것:** 본인의 근거에서 고른 출력·풀이와 아직 설명이 막힌 질문. 개인 학습 노트에 한 번 정리하고 원시 로그·pcap은 파일 링크로 연결해도 된다. 새 제출 양식은 만들지 않는다.

<span id="personal-notes"></span>

### 개인 공부를 정리할 때

기존 개인 학습 노트에 아래 세 가지를 중심으로 정리한다. 모임 전에는 현재 답과 막힌 지점을 남기고, 모임 뒤에는 확인한 차이와 보충할 부분을 고친다. 정해진 개수·분량이나 새 제출물은 없다.

- **주요 질문과 내 답:** [공동 질문](WORKSHEET.md)과 아래 확인 질문에 먼저 내 말로 답한다. 이유·성립 조건과 공식 자료·실습 근거를 연결하고, [분리 해설](ANSWERS.md)은 시도 뒤에 비교한다.
- **헷갈리는 개념 비교:** [핵심 설명](CONCEPTS.md)에서 주소 변환과 접근 허용, 기존 연결과 새 연결의 역할·관찰 위치·성공 범위를 비교한다. 두 개념이 다른 결론을 내는 예를 들어 본다.
- **이번 주 꼭 기억하고 이해할 핵심 개념:** [핵심 정리](CONCEPTS.md)의 W11-K1~K3를 길잡이로 용어·역할·동작 순서를 추린다. 필요한 공식은 식·단위·성립 조건과 적용 이유를 함께 설명한다. 예제 주소·일회성 출력값을 외우는 목록으로 만들지 않는다.

실습 근거는 해당 질문·개념 아래에 예상·실제 관찰·수정한 이해와 함께 연결한다. 제공 분석과 직접 실행을 구별하고 관찰하지 않은 결과는 채우지 않는다. 입력 화면을 썼다면 이동 전에 답안을 내려받는다. [전체 개념 색인의 정리 방법](../CONCEPT_INDEX.md#personal-study)은 다른 주차에도 같은 방식으로 쓸 수 있다.

### 오프라인에서 확인할 질문

1. **중심 질문:** 같은 서버에서 A는 성공하고 B는 timeout이면 어느 위치의 어떤 근거로 가설을 나눌까?
2. **조건을 바꾸면:** 규칙을 바꿔도 기존 연결이 통신한다면 새 연결과 무엇을 비교할까?
3. **앞 개념을 다시 쓰면:** 6주 연결 재사용과 7주 왕복 경로가 정책 변경 결과 해석에 어떤 영향을 주는가?

중심 질문을 먼저 설명하고 나머지는 짧은 후속 질문으로 사용한다. [분리 해설](ANSWERS.md)과 실제 근거를 대조하되 답을 본 시도와 독립 설명을 구별한다. 개인 공부에서 마친 정상 실습을 전부 반복하지 않고, 막힌 항목과 한 조건 변경·복구를 각자 확인한다.

## 이번 주의 질문

**경로가 있는데 HTTP 요청은 왜 실패할까?** 10주차에서 경로가 설치되었는지 확인했다. 이번에는 그 경로를 지나는 패킷의 주소가 어디서 바뀌고, 어느 정책에서 허용되며, 서버가 실제로 기다리는지 확인한다.

시작 전에 1주차의 IP·포트·서버 대기, [6주차 HTTP와 로그](../week-06/CONCEPTS.md), [7주차 왕복 경로](../week-07/CONCEPTS.md), [10주차 경로와 요청의 구별](../week-10/CONCEPTS.md)을 떠올린다. 포트 8080에서 응답하는 서버와 클라이언트의 임시 포트는 각각 누가 사용하는가?

## 함께 공부하는 순서

1. [중심 질문](WORKSHEET.md)을 읽고 두 원인 가설을 말한다.
2. [개념 교재](CONCEPTS.md)와 [지정 공식 절](SOURCES.md)을 함께 찾는다. 각자 변환 전후와 정책 판단 위치를 설명한다.
3. 출발지·규칙 순서·서버 상태 중 한 조건을 바꿔 확인한다.
4. [격리 실습](LINUX.md)에서 각자 정상 요청→차단 규칙→비교→복구를 직접 실행한다. 제공 NAT 표 분석도 필수다.
5. [복습](REVIEW.md)을 먼저 풀고 [분리 해설](ANSWERS.md)과 비교한다. 모임에서는 각자 시도한 근거를 비교하고 상세 근거는 개인 파일에 한 번 보관한다.

## 필수와 선택

| 구분 | 이번에 할 일 |
| --- | --- |
| 필수 설명·분석 | NAT/PAT·변환 전후 5튜플·역변환, 상태 추적과 허용 규칙의 차이, 방향·출발지·목적지·포트·순서, 서버 중지와 DROP 구별 |
| 필수 직접 수행 | 준비된 서버의 테스트용 규칙 한 항목을 직접 바꾸고, 새 요청·포트·로그·카운터를 비교한 뒤 복구 |
| 선택·후속 | NAT 초기 구축·패킷 캡처·conntrack 상세·IDS/IPS. 클라우드의 실제 보안 그룹 변경은 자신의 권한과 복구 조건을 갖춘 뒤 별도 수행 |

NAT 표는 설명용 자료이며 패킷 실측이 아니다. 방화벽 실습은 Linux 커널의 nftables와 실제 HTTP를 사용한다. 표 읽기만으로 필수 직접 수행을 마쳤다고 하지 않는다. Docker 컨테이너 수행을 학교 VM이나 클라우드 설정 변경 경험으로 대신 쓰지 않는다.

## 실행 전에

진행자는 [다섯 파일과 준비 절](LINUX.md#실행-환경과-파일)을 확인한다. Docker 사용 권한·고정 대역 충돌·개인 프로젝트 소유를 먼저 확인하고 이미지 설치는 모임 전에 한다. 기존 VM·서비스는 보존한다. SSH 관리 규칙이나 호스트 방화벽 전체를 변경하지 않는다.

[진행자 안내](FACILITATOR.md)는 개인 공부의 준비 범위와 한 번의 오프라인 확인 순서를 안내한다. 시간이 부족하면 선택 범위를 줄이고 필수 수행을 보충한다. 새 팀 기록·개인 마무리·발표 양식은 없다.

다음에는 무선·VPN의 경계를 같은 관찰 위치 질문으로 읽는다. 단계 점검에서 VLAN·OSPF·NAT·정책이 각각 무엇을 바꾸는지 설명할 수 있도록 이번 근거를 재사용한다.
