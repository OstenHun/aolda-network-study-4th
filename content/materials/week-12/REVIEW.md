# 12주차 복습 · 연결·전달·보호를 나누기

요약: 무선 상태·매체 접근·VPN 전후 경로와 작은 망을 설명하는 아홉 문항이다. 먼저 제공 자료로 추론하고 분리 해설과 비교하며 C12의 기존 직접 수행 근거를 재사용한다.

## 답하기 전에

[네 입력 파일](LINUX.md#실행-환경과-파일)을 열어도 된다. 모두 가공 자료이며 실측으로 바꾸어 쓰지 않는다. 입력은 자동 저장하지 않으므로 필요한 답은 Markdown으로 내려받아 직접 보관한다. 자세한 실습 근거를 여러 양식에 반복 입력할 필요는 없다. [분리 해설](ANSWERS.md)은 먼저 시도한 뒤 연다.

## Q1. 연결 표시와 요청 결과

`wifi-state.txt` A/C는 같은 AP·주소·경로·신호를 보인다. 각 위치의 근거로 무엇까지 알 수 있는가? C의 원인을 좁히는 필드와 ‘Wi-Fi 연결이니 서버도 정상’이라는 주장의 문제를 설명한다.

## Q2. 신호·채널·보안

A/B의 -48/-76 dBm과 tx bitrate를 비교한다. HTTP 성공과 지연 차이에 관해 무엇을 말할 수 있고 무엇을 확정할 수 없는가? SSID 이름 변경·숨김, 무선 암호화, 서버 HTTPS의 역할도 구별한다.

## Q3. 백오프의 멈춤과 재시도

`medium-access.txt` M1에서 A가 송신할 때 B의 남은 수는 얼마인가? 언제 다시 감소하는가? B의 첫 선택만 4→2인 M2의 첫 결과와 다음 A=1/B=3의 순서를 설명한다. 실제 trace의 ACK 없음만으로 같은 원인을 확정할 수 있는가?

## Q4. CSMA/CD·CSMA/CA·전이중

공유 반이중 Ethernet, 기본 DCF 무선, 전이중 점대점 스위치 링크에서 매체 접근은 어떻게 다른가? 회피가 충돌을 0으로 만드는지, 전이중이면 혼잡 손실까지 사라지는지도 말한다.

## Q5. VPN 전후 목적지별 경로

V0/V1에서 서버 `10.60.30.20`, VPN 끝점 `198.51.100.20`, 외부 서비스 `203.0.113.80`의 경로를 읽는다. V2/V3의 실패를 구별한 뒤 복원·종료 기준을 말한다. `/25` 추가 카드와 전체 IPv4 터널 카드에서는 어떤 행을 고르는가?

## Q6. 안쪽·바깥쪽과 암호화·접근

V1의 안쪽 요청과 응답의 주소·포트, 단말 LAN에서의 바깥 IP 목적지를 짚는다. 서버 반환 경로와 VPN 보호 구간은 어디인가? 이 자료로 DNS·IPv6·모든 애플리케이션 보호를 확정할 수 있는가? 원격 접속과 사이트 연결의 양끝도 비교한다.

## Q7. 작은 망 구성도

`design-brief.txt`로 그린 본인 구성도에서 유선 직원·직원/게스트 SSID·VLAN/서브넷·게이트웨이·서버·VPN 끝점을 짚는다. 허용 요청/응답과 차단 경로, 암호화 경계, 장치 하나의 고장 영향을 설명한다. 그림 파일은 개인 보관하고 필요한 설명만 여기에 적어도 된다.

## Q8. C12와 앞 주차 직접 근거

VLAN/STP/LACP·OSPF·NAT/PAT·정책·CRC의 역할을 구별한다. A-B=2/B-C=3/A-C=9일 때 LS의 A→C 최단 경로와, B가 C비용 8을 광고한 한 번의 DV 비교를 계산한다. AS·IGP·eBGP/iBGP와 정책 선택을 설명한다. 기존 본인 STP/LACP·OSPF 전환·복구와 정책 변경 근거는 어디에 있는가? 없는 항목은 제공 분석과 구분해 보충할 행동을 말한다.

## Q9. W12-D1~D3 개발 사례

[개발 질문](WORKSHEET.md#development)의 설명→정책 한 항목 변경→다음 진단을 자기 말로 답한다. 연결 표시·로컬 경로·복호화 뒤 카운터·서버 로그가 각각 무엇을 증명하는지 조건과 함께 말한다.
