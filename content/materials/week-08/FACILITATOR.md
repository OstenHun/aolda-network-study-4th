# 진행자 안내 · C08과 단일 장애 준비

요약: 개인 공부에서 개념·문제·실습을 준비하고 오프라인 한 번에서 설명·조건 변경·직접 수행을 확인한다. 준비·복구와 제공 분석의 경계를 지키며 막힌 필수 항목을 보충한다.

## 준비와 범위

[학습 홈](README.md)·[교재](CONCEPTS.md)·[실습](LINUX.md)을 먼저 읽는다. Linux의 iproute2·iputils ping·curl·Python 3.10 이상과 파일 전달 경로를 확인한다. IPv6 주소/경로 조회와 `::1`이 가능한지 사전 확인한다. 통신 불가 시 [제공 IPv6 trace](../../labs/week-08/ipv6-trace.txt)를 사용하고 설정을 임의로 활성화하지 않는다. 신뢰 전송은 제공 분석이며 새 구현 실습을 만들지 않는다.

기존 1주차 200/404·서버 중지, 3주차 다음 홉/제공 캡처, 4주차 ACK·타이머, 5주차 이름, 6주차 HTTP/TLS 루프백, 7주차 반환 경로를 재사용한다. 첫 두 예제의 출력과 패킷은 [1주차](../week-01/README.md)·[3주차](../week-03/README.md)에서 필요할 때 찾으며 다른 사람의 실행을 참가자의 완료 근거로 쓰지 않는다.

## 공동 탐색과 막힐 때 안내

중심 질문은 [W08-D1](WORKSHEET.md)이다. 공식 필수 읽기는 [RFC 8446 §2 그림 1](https://www.rfc-editor.org/rfc/rfc8446.html#section-2)과 [RFC 9111 §4 첫 목록](https://www.rfc-editor.org/rfc/rfc9111.html#section-4)이다. 전자는 TLS 메시지 순서, 후자는 저장 응답을 바로 쓸 조건을 찾는다. 영문 전체를 읽히지 않는다. ClientHello/Finished·fresh(신선함)·validation(재검증)을 교재 시간축/캐시 표에 대응한다. SR/GBN은 교재의 자체 시간축으로 먼저 공부하고 공식 저자 3.4 노트는 필요한 슬라이드만 참고한다. [공식 읽을 범위](SOURCES.md).

설명이 막히면 “주소를 이미 아는가, 연결이 열려 있는가, 응답을 다시 써도 되는가”를 차례로 묻는다. 재전송은 수신자가 2·3을 버렸는지 보관했는지부터 비교한다. IPv6는 주소 비트와 범위를 먼저 보고 실제 NDP 메시지 유형을 구별한다. 선택 보조 질문·SLAAC 상세·실제 NDP 캡처를 줄이며 필수 개념을 보충한다.

## C08의 단일 장애를 가리는 절차

이 절과 [해설](ANSWERS.md)은 참가자의 최초 진단이 끝날 때까지 공유 화면에서 닫는다. 소스 저장소가 공개이므로 기술적 비밀 유지가 아니라 **평가 중 원인/해설을 보지 않는 절차**다. 공개된 답을 본 참가자는 새 포트/경로 조건으로 다시 확인한다. 각자 개인 루프백 프로세스를 쓰고 현재 대상·소유자를 확인한다. 같은 호스트에서 동시에 실습하면 각자 다른 비특권 포트로 정상 계약을 맞춘다.

1. <a download href="../../labs/week-06/http_server.py">기존 http_server.py</a>를 참가자 개인 폴더에 두고 `ss -ltn 'sport = :8086'`으로 빈 포트를 확인한다. 이미 남의 listener가 있으면 다른 포트를 골라 아래 URL·ss·서버 명령을 모두 맞춘다.
2. 셸 A에서 `python3 http_server.py --port 8086`을 켠다. 셸 B에서 아래 정상 요청으로 200·본문·로그를 확인한다. 준비 실패를 숨긴 장애로 삼지 않는다.

```sh
curl --noproxy '*' --http1.1 --connect-timeout 3 --max-time 5 -iv http://127.0.0.1:8086/resource
```

3. 다음 카드 중 **하나만** 골라 준비한다. 최초 참가자에게는 원인 열과 명령을 숨기고 정상 계약·사례 URL·실제 증상만 전달한다. 시행착오로 여러 조건이 바뀌면 정상으로 초기화하고 다시 한 조건만 고른다.

| 준비자만 볼 원인 | 한 조건 만들기·전달 URL | 복구 기준 |
| --- | --- | --- |
| HTTP 경로 오류 | 서버를 유지하고 URL만 `/resorce` 등 존재하지 않는 경로로 전달 | `/resource`로 돌아가 200·본문·로그 |
| 서버 중지 | 본인 서버 셸 Ctrl+C, URL은 정상 `/resource` 유지 | 같은 서버/포트 재시작 후 정상 요청 |
| 요청 포트 불일치 | 서버 유지, listener 없는 다른 비특권 루프백 포트를 ss로 확인한 뒤 URL의 포트만 변경 | URL 포트를 정상 계약으로 복구 |

4. 최초 진단 중에는 “서버가 꺼졌다” 같은 답을 알려 주지 않는다. 참가자가 URL·대기 포트·서버 셸 로그를 조회할 수 있게 한다. 명령 도움말·공식 문서는 찾아도 되지만 AI가 만든 답/명령을 그대로 따라 했다면 독립 수행으로 쓰지 않는다.
5. 참가자의 최초 가설·선택한 관찰·결론을 확인한 뒤 원인을 공개한다. 참가자가 같은 한 조건을 재현하고 정상으로 복구하게 한다. 정상 URL 200과 로그·최종 listener 정리까지 본다. 상세 원출력은 개인 파일 한 곳에 보관한다.

혼자 진행해 정답을 가릴 수 없거나 환경이 없으면 제공 분석/도움 후 연습으로 남긴다. 그 사정 때문에 독립 수행 기준을 낮추지 않는다. 선택 경로 사례는 [7주차](../week-07/LINUX.md#simulator)의 별도 복습으로만 사용하고 위 HTTP 사례와 동시에 장애를 섞지 않는다. 실제 DNS 설정·주소·라우터·SSH 관리 경로를 바꾸지 않는다.

## 한 주의 개인 공부와 오프라인 확인

개인 준비는 [학습 홈의 정리 안내](README.md#personal-notes)에 따라 주요 질문과 내 답·헷갈리는 개념 비교·꼭 기억하고 이해할 핵심을 살핀다. 노트 분량을 평가하지 않고 이유·조건 변경·관련 실습 근거로 확인한다. 모임 뒤에는 틀린 설명과 남은 보충만 기존 개인 노트에서 고치며 중복 제출을 요구하지 않는다.

[학습 홈의 개인 공부 범위와 세 확인 질문](README.md#weekly-study)을 오프라인 모임 전까지 준비한다. 모임은 그 주 학습을 마무리하고 남은 보충을 정하는 자리다. 개념·공식 지정 절·복습과 준비된 실습의 정상→변경→복구는 개인 공부에서 시도한다. 모임 전 완성 답안·발표 자료를 요구하지 않으며 막힌 질문과 본인 근거를 가져오게 한다. 진단 원인을 가리는 과제는 정상 기준과 도구까지만 준비한다.

오프라인은 한 번의 모임에서 **설명 → 새 조건 → 본인 실습/분석 확인 → 보충 결정**으로 진행한다. 아래 60분은 시간 배분 예시이며 모임 길이나 추가 회차를 확정하는 표가 아니다.

| 시간 예시 | 진행자가 확인할 것 |
| --- | --- |
| 0~10분 | 개인 공부에서 막힌 질문과 2~4학습 단위 전 개념 하나를 골라 근거로 설명 |
| 10~25분 | 학습 홈의 중심 질문 → 조건 변경. 소그룹에서 설명자/확인자 교대 |
| 25~50분 | 개인 준비 근거로 캐시/연결·전송 모형·IPv6를 설명하고 C08의 처음 보는 단일 장애를 진단·복구. 미수행 직접 실습은 보충으로 구별 |
| 50~60분 | 정상 복구·받은 도움·미완료 구분, 개인 학습 노트에 필요한 보충과 다음 질문 연결 |

개인 학습 시간을 고정된 2~3시간으로 제한하지 않는다. 필수 범위를 먼저 공부하고 실제 막힘에 따라 시간을 배분한다. 주차를 미리 분할하거나 필수 기준을 낮추지 않으며, 개인 공부 후에도 해결되지 않는 항목만 보충한다. C04/C08/C12/C16은 해당 주 기존 설명·실습을 대체하고 점검을 별도로 더하지 않는다. 한 사람의 답·팀 합의·파일 제출은 개인 이해/직접 수행의 증거가 아니다.

C08은 기존 설명·진단 시간 일부를 대체한다. Q1~Q6의 개인 풀이를 재사용하고, 정답 비노출 단일 장애의 독립 진단은 오프라인에서 확인한다. 새 시험지·발표·팀 기록을 추가하지 않는다.

## 확인할 것과 다음 복습

필수 요소는 단계 생략의 조건·RTT 단위/범위, 세 모형의 재전송 집합/버퍼, IPv4/IPv6·ARP/NDP, 최초 단일 장애 가설과 구별 관찰·재현/복구다. 해설 노출/도움과 제공 분석/본인 실행을 각 항목에서 구별한다. “IPv6 없음”은 설정 결함/권한과 개념 미이해를 나누어 본다. [복습](REVIEW.md)·[분리 해설](ANSWERS.md)을 사용한다.

다음 주 시작에는 “같은 /64 또는 /24 계산이 맞는데도 링크에서 분리되어 있다면 무엇을 더 확인할까?”를 물어 9주차로 잇는다. STP/LACP·OSPF의 설명이나 성능 계산을 이번 C08 통과 조건으로 앞당기지 않는다.
