# 8주차 복습 · 흐름과 진단

요약: 캐시·연결·RTT, 손실 모형·IPv6 비교를 조건과 함께 설명한다. C08 단일 장애는 정답을 보지 않은 진단·재현·복구 근거로 확인한다. 먼저 답하고 분리 해설과 대조한다.

[교재](CONCEPTS.md) · [실습](LINUX.md) · [해설은 답한 뒤 열기](ANSWERS.md). 답안은 자동 저장되지 않으므로 내려받은 파일을 직접 연다. 기존 복습/C08 시간에 사용하며 새 기록 제출을 요구하지 않는다.

## Q1. 전체 흐름과 조건

주소·경로가 준비된 TCP 기반 HTTPS의 작은 객체 요청을 DNS→TCP→TLS→HTTP 그림으로 설명하라. DNS 캐시만 있는 경우와 사용 가능한 같은 origin TLS 연결이 있는 경우를 각각 바꾸고 생략할 교환을 표시하라. 신선한 HTTP 저장 응답은 없다.

## Q2. 단위를 붙여 계산하기

교재와 같은 TLS 1.3·순차 단계·첫 응답 바이트 모형에서 D=30ms, R=60ms다. (a) DNS 캐시/연결/HTTP 캐시 모두 없음, (b) DNS 캐시만 있음, (c) TLS 연결 사용 가능, (d) 신선한 HTTP 저장 응답으로 처리 가능일 때 추가 네트워크 비용을 구하라. 제외한 비용 두 개도 말하라.

## Q3. 304와 재사용

열린 TLS 연결에서 저장 응답을 재검증해 304를 받았다. “HTTP 캐시를 썼으니 이번에는 네트워크 왕복이 없었다”는 설명을 평가하라. DNS TTL이 만료되면 이 열린 연결도 즉시 끊긴다고 할 수 있을까?

## Q4. 손실 하나의 재전송

제공 시간축과 같은 창 4·번호 0\~3·첫 1만 손실·ACK 손실 없음의 조건이다. stop-and-wait/GBN/SR에서 재전송 집합과 2·3의 송신/수신 상태를 각각 설명하라. 모형의 ACK n을 실제 TCP의 바이트 ACK와 같다고 할 수 있을까?

## Q5. 마지막 단위가 손실되면

Q4의 손실 번호만 3으로 바꾼다. 0\~2 ACK가 모두 먼저 돌아온 뒤 타이머가 끝난다면 세 모형의 재전송 집합은? 이 결과로 SR은 언제나 GBN보다 재전송 수가 적다고 할 수 있을까?

## Q6. IPv6와 관찰 위치

`2001:db8:8:1::10/64`의 접두사를 쓰고 `2001:db8:8:2::20`의 포함 여부를 판단하라. `::1`, `fe80::1`, `::/0`의 역할, ARP/NDP 차이, 제공 L1/L2와 E1/E2가 각각 확인하는 것을 설명하라. `::1` 성공이 외부 IPv6 성공의 증거인지도 말하라.

## Q7. 단일 장애의 독립 진단

실습 B에서 원인 공개 전 세운 가설 둘, 둘을 가른 관찰과 최초 결론을 보이라. HTTP 404와 연결 거부를 어떻게 구별했는가? 직접 실행하지 않았다면 제공 분석과 남은 수행을 명시하라. 해설을 보거나 원인을 들은 상태도 구별한다.

## Q8. 재현·복구와 남은 질문

진단한 한 조건을 본인이 다시 바꿨을 때 같은 증상이었는가? 정상으로 복구한 요청·서버 로그·정리 결과를 짚어라. 사용한 환경과 도움 여부를 밝히고 그 관찰로 아직 알 수 없는 DNS/TLS/외부 경로의 범위를 설명하라.
