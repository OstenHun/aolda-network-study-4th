# 16주차 · 처음 보는 작은 장애를 진단하기

요약: 기존 서비스의 정상 기준을 잡고 배운 범위의 단일 장애를 각자 조사·복구한다. 두 원인 가설을 관찰로 구별하고 같은 요청으로 정상화를 확인한다. 앞선 계산·코드·운영 근거를 재사용해 공통 과정의 남은 보충을 찾는다.

## 이번 주에 할 일

**중심 질문: 요청이 실패했다. 무엇을 먼저 확인해야 두 원인 가설을 구별할 수 있을까?**

13주차의 서비스·양끝 로그, 14주차의 정상 기준·분산/복구, 15주차의 제한 반복 점검을 이어 쓴다. 새 앱을 만들거나 전체 환경을 다시 구축하지 않는다. 처음 보는 사례란 배운 개념으로 풀되 해당 주입·정답을 미리 보지 않은 사례다. 같은 사례를 따라 복구한 뒤 다시 성공한 것은 독립 진단과 구별한다.

[진행자 안내](FACILITATOR.md)는 준비·시간 배치·판정 방법이다. 학습자는 실습 전 정답을 찾아 읽지 않고 증상·허용 범위만 받아 시작한다. 공개 교재의 해설은 학습을 돕지만 그것을 읽었다는 사실이 독립 이해를 증명하지는 않는다.

## 필수와 선택

필수는 두 묶음이다. **A:** Linux 한 대에서 정상 기준과 처음 보는 단일 장애 하나를 직접 조사·복구한다. **B:** 앞서 보관한 계산·코드 읽기·필수 실습과 O01\~O05 근거를 연결하고 막힌 항목만 새 조건으로 확인한다. 자세한 근거는 개인 파일에 한 번 보관하며 새 팀 기록·개인 마무리 양식은 요구하지 않는다.

VM 간 경로·정책 사례는 이미 해당 환경에서 직접 수행한 경우에 선택한다. 복합 장애·부하 시험·큰 서비스 설계·Ansible/Terraform 자원 변경은 후속 범위다. 관리 SSH·공용망을 바꾸거나 유료 자원을 추가하지 않는다. 제공 자료만 분석했다면 직접 복구는 보충으로 남긴다.
