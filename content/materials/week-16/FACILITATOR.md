# 16주차 진행자 안내 · 답을 가리고 준비하기

요약: 개인 공부에서 개념·문제·실습을 준비하고 오프라인 한 번에서 설명·조건 변경·직접 수행을 확인한다. 준비·복구와 제공 분석의 경계를 지키며 막힌 필수 항목을 보충한다.

## 시작 전에 준비할 것

13\~15주차의 동일 서비스·설정·로그·점검기를 확인한다. [학습자 실습](LINUX.md)의 세 파일과 두 셸·허가된 루프백·미사용 비특권 포트로 정상 기준을 재현한다. 기본 사례는 Linux 한 대다. 새 앱·전체 환경 재구축·추가 유료 자원은 필요하지 않다.

배운 이름·바인딩/포트·서버 중지·경로·정책 중 **단일 원인 하나**를 고른다. 기본 사례는 루프백 프로세스의 실행 조건만 다루고, 경로/정책은 해당 격리 환경에서 이미 직접 실습한 경우에만 선택한다. 관리 SSH·기본 경로·공용 자원을 바꾸지 않는다. 진행자는 사용 전 정상→주입→구별 관찰→최소 복구→동일 원래 요청 정상·정리까지 직접 리허설한다.

## 두 자료 경로를 실제로 나눈다

- **진행자용:** 사례별 주입 명령·바뀐 한 값·예상 증상/가설별 관찰·정답·복구/정리·중단 조건을 별도 보관한다. 학습자의 공개 교재·검색 색인·코드 다운로드·공유 폴더·화면에 섞지 않는다.
- **학습자용:** 실행 호스트·정상 URL/기대 본문·실패 증상·관찰 가능한 위치·본인 테스트 프로세스의 변경 허용 범위·지원/중단 경로만 준다. 원인명이나 정답이 드러나는 파일명·로그 꼬리표를 쓰지 않는다.

학습자에게 사례의 주입 명령을 실행시키지 않는다. 정상화 후에는 본인이 고른 관찰과 실제 변경을 설명하게 한다. 셸 A의 **현재 리스너·실행 인자·요청 로그**는 선택한 관찰로 제공할 수 있지만 주입 당시의 답안 설명/명령 이력을 처음부터 보여 주지는 않는다. 정상 준비 명령은 공개돼도 되며 실제로 바꾼 값과 해결 순서는 진단 전에 공개하지 않는다.

같은 계정·호스트를 쓰는 절차적 분리는 기술적 접근 통제가 아니다. 공개 해설·이전 코드·명령 이력이나 짝의 답에서 해당 사례를 이미 봤다면 학습용 시도로 구분하고 다른 처음 보는 단일 사례를 준비한다. 새 사례를 준비하지 못하면 독립 진단은 미확인으로 남긴다. 공개 자료가 있다는 사실을 정답 비노출 또는 참가자 이해의 증거로 쓰지 않는다.

## 한 주의 개인 공부와 오프라인 확인

개인 준비는 [학습 홈의 정리 안내](README.md#personal-notes)에 따라 주요 질문과 내 답·헷갈리는 개념 비교·꼭 기억하고 이해할 핵심을 살핀다. 노트 분량을 평가하지 않고 이유·조건 변경·관련 실습 근거로 확인한다. 모임 뒤에는 틀린 설명과 남은 보충만 기존 개인 노트에서 고치며 중복 제출을 요구하지 않는다.

[학습 홈의 개인 공부 범위와 세 확인 질문](README.md#weekly-study)을 오프라인 모임 전까지 준비한다. 모임은 그 주 학습을 마무리하고 남은 보충을 정하는 자리다. 개념·공식 지정 절·복습과 준비된 실습의 정상→변경→복구는 개인 공부에서 시도한다. 모임 전 완성 답안·발표 자료를 요구하지 않으며 막힌 질문과 본인 근거를 가져오게 한다. 진단 원인을 가리는 과제는 정상 기준과 도구까지만 준비한다.

오프라인은 한 번의 모임에서 **설명 → 새 조건 → 본인 실습/분석 확인 → 보충 결정**으로 진행한다. 아래 60분은 시간 배분 예시이며 모임 길이나 추가 회차를 확정하는 표가 아니다.

| 시간 예시 | 진행자가 확인할 것 |
| --- | --- |
| 0~10분 | 개인 공부에서 막힌 질문과 2~4학습 단위 전 개념 하나를 골라 근거로 설명 |
| 10~25분 | 학습 홈의 중심 질문 → 조건 변경. 소그룹에서 설명자/확인자 교대 |
| 25~50분 | 처음 보는 단일 장애에서 각자 두 원인 가설·구별 관찰·최소 변경·같은 요청의 복구를 확인. 앞서 본 사례는 연습으로 구별하고 새 사례 또는 보충으로 진행 |
| 50~60분 | 정상 복구·받은 도움·미완료 구분, 개인 학습 노트에 필요한 보충과 다음 질문 연결 |

개인 학습 시간을 고정된 2~3시간으로 제한하지 않는다. 필수 범위를 먼저 공부하고 실제 막힘에 따라 시간을 배분한다. 주차를 미리 분할하거나 필수 기준을 낮추지 않으며, 개인 공부 후에도 해결되지 않는 항목만 보충한다. C04/C08/C12/C16은 해당 주 기존 설명·실습을 대체하고 점검을 별도로 더하지 않는다. 한 사람의 답·팀 합의·파일 제출은 개인 이해/직접 수행의 증거가 아니다.

장애를 주입/복구하는 사람과 진단하는 사람을 구별한다. 개인 공부에서 실제 주입/정답을 먼저 노출하지 않고 오프라인에서 사례당 단일 원인만 쓴다. C16은 기존 근거·진단 시간 일부를 대체하며 새 시험지·발표를 추가하지 않는다.

## 막힐 때 설명하는 순서

개념이 막히면 [K1의 증거 표](CONCEPTS.md#W16-K1)에서 ‘이 출력으로 어디까지 알까’를 먼저 설명한다. 도구를 모르면 `ss --help`·curl 도움말·[공식 참조](SOURCES.md)를 찾게 한다. 원인이나 복구 명령을 알려 줬다면 받은 도움을 남기고 같은 사례를 독립 통과로 쓰지 않는다. 안전·권한·복구 경로를 숨겨 독립성을 시험하지 않는다.

[복습 해설](ANSWERS.md)은 개념 설명용이고 실제 주입 사례의 정답표가 아니다. 앞 계산·코드·운영 근거는 [C16 지도](CHECKPOINT.md)로 재사용한다. LF 한 연결 한 메시지·256 UTF-8 byte·지속 연결 미지원, 개별 블로킹 timeout과 전체 마감의 차이, HTTP/업무 성공·서버 수신/로컬 쓰기/클라이언트 수신을 구별한다.

## 종료 판단

두 가설·구별 관찰·허가된 최소 변경·원래 입력 복구와 받은 도움을 실제 근거로 확인한다. O01\~O05·STP/LACP·OSPF의 필수 직접 수행과 제공 분석 항목을 앞 근거에서 확인한다. 참가자별 빠진 항목은 필요한 환경·다음 행동과 함께 보충한다. 자료를 읽거나 정상 응답 하나를 얻은 것으로 전체 완료를 판정하지 않는다. 이후 학습은 부분/복합 장애·부하·설계로 확장할 수 있으나 이번 공통 종료의 누락을 숨기지 않는다.

## 원격 서비스로 적용하는지 확인하기

13주의 실제 양끝 요청·테스트 정책과 6주의 TLS 신원 확인을 직접 마친 사람에게는, 같은 허가된 환경의 단일 이름/신원/정책 사례로 바꿔 볼 수 있다. 진행자는 원인·주입·복구를 별도 준비하고 학습자에게는 정상 기준·증상·허용 범위만 준다. 루프백 기본 사례와 원격 사례를 모두 새 필수 시험으로 추가하지 않는다. 환경·권한·복구가 없으면 원격 전이는 미확인으로 남기고, C16의 기존 기본 진단과 O01~O05 판정은 그대로 구별한다.
