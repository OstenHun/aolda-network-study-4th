# 4주차 · 프로그램 사이에 데이터를 전하기

요약: TCP와 UDP가 맡는 일을 소켓·연결·메시지 경계에서 찾는다. 함께 질문을 탐색하고 작은 송수신 예제와 제공 시간축으로 전달·애플리케이션 처리·손실 복구를 구별한다.

<span id="weekly-study"></span>

## 개인 공부와 오프라인 확인

오프라인 모임 전까지 아래 범위를 공부하고 실습을 시도한다. 모임은 그 주의 학습을 마무리하는 자리로, 막힌 이유와 조건을 바꾼 결과를 설명하고 남은 보충을 정한다. [공동 질문](WORKSHEET.md)은 개인 공부의 출발점으로 쓰고, 모임에서는 근거를 비교한다. 별도 사전 모임이나 발표 자료는 필요하지 않다.

- **개념·문제:** 소켓·대기/연결, TCP/UDP 경계, SEQ/ACK·재전송, RTT 시간축, 흐름 제어/혼잡 제어, FIN/RST·EOF. [교재](CONCEPTS.md) → [공식 지정 절](SOURCES.md) → [복습](REVIEW.md) 순서로 읽고, 먼저 답한 뒤 [해설](ANSWERS.md)과 비교한다.
- **실습·분석:** TCP/UDP 송수신 비교와 포트 한 조건 변경→복구. 코드의 recv 누적/종료 조건 읽기. GBN/SR·윈도 성능 계산은 뒤 주차에서 진행. [실행 안내](LINUX.md)의 필수/선택과 제공 분석/직접 수행 구분을 따른다.
- **모임에 가져올 것:** 본인의 근거에서 고른 출력·풀이와 아직 설명이 막힌 질문. 개인 학습 노트에 한 번 정리하고 원시 로그·pcap은 파일 링크로 연결해도 된다. 새 제출 양식은 만들지 않는다.

<span id="personal-notes"></span>

### 개인 공부를 정리할 때

기존 개인 학습 노트에 아래 세 가지를 중심으로 정리한다. 모임 전에는 현재 답과 막힌 지점을 남기고, 모임 뒤에는 확인한 차이와 보충할 부분을 고친다. 정해진 개수·분량이나 새 제출물은 없다.

- **주요 질문과 내 답:** [공동 질문](WORKSHEET.md)과 아래 확인 질문에 먼저 내 말로 답한다. 이유·성립 조건과 공식 자료·실습 근거를 연결하고, [분리 해설](ANSWERS.md)은 시도 뒤에 비교한다.
- **헷갈리는 개념 비교:** [핵심 설명](CONCEPTS.md)에서 TCP ACK와 앱 처리 완료의 역할·관찰 위치·성공 범위를 비교한다. 두 개념이 다른 결론을 내는 예를 들어 본다.
- **이번 주 꼭 기억하고 이해할 핵심 개념:** [핵심 정리](CONCEPTS.md)의 W04-K1~K3를 길잡이로 용어·역할·동작 순서를 추린다. 필요한 공식은 식·단위·성립 조건과 적용 이유를 함께 설명한다. 예제 주소·일회성 출력값을 외우는 목록으로 만들지 않는다.

실습 근거는 해당 질문·개념 아래에 예상·실제 관찰·수정한 이해와 함께 연결한다. 제공 분석과 직접 실행을 구별하고 관찰하지 않은 결과는 채우지 않는다. 입력 화면을 썼다면 이동 전에 답안을 내려받는다. [전체 개념 색인의 정리 방법](../CONCEPT_INDEX.md#personal-study)은 다른 주차에도 같은 방식으로 쓸 수 있다.

### 오프라인에서 확인할 질문

1. **중심 질문:** sendall 성공·TCP ACK·앱 응답은 각각 어느 단계까지 확인한 것일까?
2. **조건을 바꾸면:** 클라이언트→서버 편도30ms, 반대 방향70ms라면 SYN 출발 뒤 클라이언트 송신 가능 시각과 서버 연결 수립 시각은? 처리·직렬화·손실·TLS·Fast Open은 무시한다.
3. **앞 개념을 다시 쓰면:** 3주 다음 홉 MAC과 TCP 연결의 양쪽 IP/port는 같은 단위인가?

중심 질문을 먼저 설명하고 나머지는 짧은 후속 질문으로 사용한다. [분리 해설](ANSWERS.md)과 실제 근거를 대조하되 답을 본 시도와 독립 설명을 구별한다. 개인 공부에서 마친 정상 실습을 전부 반복하지 않고, 막힌 항목과 한 조건 변경·복구를 각자 확인한다.

## 함께 풀 질문에서 시작하기

**데이터를 보냈다는 것은 상대 프로그램이 일을 끝냈다는 뜻일까?** [함께 찾을 질문](WORKSHEET.md)에서 출발해 필요한 공식 절과 교재를 함께 읽는다. 각자 근거로 설명하고 포트·수신 크기 조건을 바꾸어 확인한다. 모임에서는 각자 시도한 근거와 해석을 비교한다.

1주차의 IP·port·HTTP 응답, 2주차의 경로, 3주차의 다음 홉을 다시 쓴다. “서버에서 실행한 localhost 요청은 어느 호스트와 인터페이스를 지나는가?”를 먼저 설명해 본다. 막히면 [1주차 핵심 정리](../week-01/ESSENTIALS.md)와 [3주차 핵심 정리](../week-03/ESSENTIALS.md)로 돌아간다.

필수 직접 실습은 TCP/UDP 송수신 비교 한 묶음과 포트 조건 변경·복구 한 묶음이다. 손실·재전송은 교재의 **설명용 가상 시간축**으로 분석할 수 있다. 정상 UDP 실행에서 손실이 나와야 하는 것은 아니다. 실행한 명령·출력·캡처는 개인 파일에 한 번 보관하며 정해진 팀 기록이나 마무리 양식을 작성하지 않는다.
