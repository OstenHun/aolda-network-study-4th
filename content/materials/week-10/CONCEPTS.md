# 동적 라우팅 · 지도를 나누고 경로를 다시 계산하기

요약: 링크 상태는 연결 정보를 나누어 각자 경로를 계산하고, 거리 벡터는 이웃의 목적지별 거리를 받아 갱신한다. OSPF의 이웃·cost·수렴과 AS 간 BGP 정책을 작은 계산과 장애 전환에 연결한다.

## 정적 경로에서 동적 경로로

[7주차](../week-07/CONCEPTS.md)의 정적 경로는 관리자가 다음 홉을 지정했다. 선택한 길 중간이 끊겨도 다른 라우터가 그 사실을 자동으로 알려 주는 기능은 정적 경로 자체에 없다. 인터페이스 down에 따른 경로 제거·별도 추적 기능은 있을 수 있지만 모든 원격 장애를 알아내는 것은 아니다.

**동적 라우팅**은 라우터들이 도달 정보를 교환하고 변화에 맞춰 경로를 갱신하는 방식이다. 이 정보 교환과 계산은 제어 과정이고, 실제 패킷 전달은 설치된 경로를 참조하는 과정이다. 경로의 학습 방식이 달라도 패킷은 목적지 IP의 최장 접두사로 조회한다. OSPF는 HTTP 요청마다 최단 경로를 새로 계산하는 프록시가 아니다.

## W10-K1 · 같은 지도를 받아도 출발지가 다르면 다음 홉이 다르다

기억 문장: **링크 상태(LS)는 연결과 비용을 알리고, 각 라우터는 자신을 출발점으로 최단 경로를 계산한다.**

링크는 두 노드의 연결, 가중치는 연결을 지날 때 더하는 비용이다. 아래는 양방향 비용이 같은 자체 학습 그래프다. 단위는 없는 양수이며 시간·거리·대역폭의 실측값이 아니다. 선에 없는 연결은 없다.

```text
        2          5
    A ------- B ------- D
     \        |        /
    5 \     1 |     1 /
       \      |      /
              C

연결: A-B=2, A-C=5, B-C=1, B-D=5, C-D=1
```

### Dijkstra를 A에서 따라가기

`d(X)`는 A에서 X까지 현재 찾은 가장 작은 비용, `∞`는 아직 모르는 값이다. 먼저 A=0, 나머지=∞로 둔다. 매번 **미확정 노드 중 d가 가장 작은 노드를 확정**하고, 그 노드를 거치는 후보가 더 싸면 값을 낮춘다. 확정값이 다시 낮아지지 않는 성질에는 음수 비용이 없다는 조건이 필요하다.

| 확정한 순서 | B의 후보 | C의 후보 | D의 후보 | 이번에 비교한 것 |
| --- | --- | --- | --- | --- |
| A(0) | 2, 이전 A | 5, 이전 A | ∞ | A에 직접 연결된 두 선 |
| B(2) | 확정2 | 3, 이전 B | 7, 이전 B | C는 min(5,2+1), D는 2+5 |
| C(3) | 확정2 | 확정3 | 4, 이전 C | D는 min(7,3+1) |
| D(4) | 확정2 | 확정3 | 확정4 | 미확정 노드 없음 |

따라서 A→D는 A→B→C→D, 비용4, A의 다음 홉은 B다. C에서는 D가 다음 홉이다. 지도가 같아도 모든 라우터의 경로표가 같은 것은 아니다. 출발점을 C로 바꾸어 설명해 본다. A-C의 직접 비용5가 더 적은 홉 수를 주더라도 비용3인 A-B-C보다 싸지는 않다.

이 계산은 LS의 핵심만 보여 준다. OSPF에는 정보 전달·동기화·재전송·타이머와 경로 설치도 필요하다. Dijkstra 한 번이 OSPF 전체 구현은 아니다. [RFC 2328 §1.1·§2.2](https://www.rfc-editor.org/rfc/rfc2328.html#section-1.1)가 근거다.

### 거리 벡터는 이웃이 알려 준 거리에서 시작한다

**거리 벡터(DV)** 방식의 라우터는 이웃이 알려 준 목적지별 비용에 그 이웃까지의 비용을 더한다. 목적지 D에 대해 다음과 같이 갱신한다. `v`는 직접 이웃, `c(A,v)`는 그 이웃까지의 링크 비용, `D_v(D)`는 이웃이 광고한 D까지의 거리다.

```text
D_A(D) ← min over neighbors v [ c(A,v) + D_v(D) ]
```

같은 그래프의 **초기 직접 연결 정보만 가진 상태**를 잡는다. A의 D 비용은 ∞, B가 광고하는 D 비용은5, C가 광고하는 D 비용은1이다. A가 이 두 초기 광고를 받아 한 차례 갱신하면 `min(2+5, 5+1)=6`, 다음 홉은 C다. 이 갱신 안에서 B나 C의 새 값을 먼저 끼워 넣지 않는다.

다음 차례에 B가 C의 초기 광고를 받아 D 비용을2로 알리고, A가 그것을 받으면 `min(2+2,5+1)=4`, 다음 홉 B로 바뀔 수 있다. **한 차례 갱신과 최종 수렴을 구별**한다. DV가 전체 링크 지도를 먼저 가져야 하는 것은 아니다. 실제 DV 프로토콜의 주기·장애 처리·루프 방지와 count-to-infinity 상세는 선택이다. 이 식은 Bellman-Ford 원리를 익히는 예이며 RIP의 홉 제한이나 패킷을 구현한 실험은 아니다. [RFC 2453 §3.4](https://www.rfc-editor.org/rfc/rfc2453.html#section-3.4).

## W10-K2 · OSPF 이웃, 경로표, 요청 성공은 따로 확인한다

기억 문장: **이웃과 연결 정보를 갱신해 경로를 설치해도, 왕복 전달과 프로그램 응답은 별도로 확인해야 한다.**

OSPF(Open Shortest Path First)는 AS 내부에서 쓰는 링크 상태 라우팅 프로토콜이다. Hello로 이웃 관계를 유지하고 링크 상태 광고(LSA)를 교환한다. 이를 모은 링크 상태 데이터베이스(LSDB)를 바탕으로 각자 경로를 계산한다. 같은 영역에서 수렴한 라우터들은 그 영역의 연결 정보를 동기화한다. 이번에는 영역0 하나만 쓴다. 영역은 IP 서브넷과 같은 단위가 아니며, 한 영역에 여러 서브넷이 있다.

이웃은 OSPF 메시지를 주고받는 상대다. 인접 관계가 `Full`이면 필요한 데이터베이스 동기화를 마친 상태다. 모든 토폴로지의 모든 이웃이 반드시 Full이어야 하는 것은 아니지만, **이번 준비 구성의 각 라우터에서는 두 이웃 모두 Full**이 정상이다. Router ID는 OSPF에서 라우터를 식별하는 값이며, 실제 다음 홉 IP와 같다고 가정하지 않는다.

**cost**는 OSPF가 경로 계산에 더하는 비용이다. 이번에는 인터페이스 비용을 명시한다. 큰 비용은 나쁜 경로라는 뜻일 수 있지만 큰 RTT를 측정했다는 뜻은 아니다. 110은 FRR에서 OSPF의 기본 관리 거리이고 경로 비용과 구별한다. 같은 목적지의 서로 다른 학습 출처를 비교하는 기준과 OSPF 안에서의 비용 비교는 역할이 다르다.

### 실습의 삼각형

```text
          cost10         cost10
     R1 ---------- R2 ---------- R3
       \_______________________/
                  cost50

R1 lo: 192.0.2.1/32  R2 lo: 192.0.2.2/32  R3 lo: 192.0.2.3/32
단일 영역: 0.0.0.0, 모든 주소는 격리 실습용 예제
```

4노드 계산 그림과는 별개의 3라우터 실습이다. `lo`는 라우터 안의 논리 인터페이스이며 그 주소를 목적지로 삼아 라우터 사이의 경로를 확인한다. 정상 R1→R3는 R2 경유, R2-R3 연결 단절 뒤에는 R1-R3 직접 연결을 사용한다. 끊긴 링크가 도로 지도에서 빠져야 하므로 다음 과정이 필요하다.

1. 해당 인터페이스 또는 Hello 중단으로 장애를 발견한다.
2. 바뀐 연결 정보를 전달하고 각 라우터가 경로를 다시 계산한다.
3. 경로를 설치하고 패킷을 전달한다. 왕복 확인이 그 뒤에 성공할 수 있다.

이 과정이 안정되는 것을 **수렴**이라고 부른다. 장애 발생 시각, 각 관찰 지점의 경로 변경 시각, 첫 ping 응답 시각은 같다고 단정할 수 없다. 장비·타이머·장애 종류에 따라 달라지므로 “OSPF는 항상 몇 초”라고 외우지 않는다. 경로가 바뀌었어도 중간 손실이0이었다는 증거는 아니다. [RFC 2328 §7.1·§10.1](https://www.rfc-editor.org/rfc/rfc2328.html#section-7.1), [FRR OSPF](https://docs.frrouting.org/en/stable-10.5/ospfd.html).

## W10-K3 · AS 간 경로는 정책도 결정한다

기억 문장: **AS 내부의 비용 계산과 AS 사이의 광고·선택 정책을 구별한다.**

AS(Autonomous System, 자율 시스템)는 하나의 관리·라우팅 정책 아래 운영하는 네트워크 집합이다. OSPF 같은 IGP는 AS 내부 경로를 계산한다. BGP는 네트워크 도달 정보와 AS 경로 같은 속성을 교환하며, 어떤 경로를 선택하고 누구에게 광고할지 정책을 적용한다. BGP는 AS 간 연결에 쓰이고, 같은 AS 안에서도 iBGP로 BGP 정보를 전달할 수 있다. “BGP는 무조건 다른 AS끼리만 실행한다”는 설명은 틀리다.

자체 정책 예를 보자. AS65001이 목적지 `203.0.113.0/24`를 제공자 P와 Q에게 배운다. P 경로의 AS 수는2, Q 경로는3이다. 운영 정책이 **사용 가능한 Q를 우선**하도록 정했다면 Q가 선택될 수 있다. 도달 정보를 배우는 것과 외부 이웃에게 다시 광고하는 것도 별개다. Q에게 배운 경로를 P에게 전달하지 않는 정책이 있을 수 있다. 이 예는 특정 BGP 속성의 전체 비교 순서나 실제 인터넷 설정을 재현한 것이 아니다. [RFC 4271 §1.1·§3·§9.1.1·§9.1.3](https://www.rfc-editor.org/rfc/rfc4271.html#section-3).

## 헷갈리는 두 가지

| 구별 | 조건·반례 |
| --- | --- |
| STP/LACP와 OSPF | STP는 L2 루프를 피할 전달 트리를 만들고 LACP는 멤버를 논리 링크로 묶는다. OSPF는 IP 연결 정보를 교환해 L3 경로를 계산한다. LACP 한 멤버 단절이 언제나 OSPF 이웃 단절을 뜻하지는 않는다 |
| 이웃 Full·경로 설치와 서비스 성공 | Full은 동기화 상태, 경로는 다음 홉 선택 근거다. ping은 ICMP 왕복, HTTP는 앱 응답이다. 역방향 경로·접근 정책·서버 대기·이름/TLS 문제까지 Full 하나로 증명할 수 없다 |
