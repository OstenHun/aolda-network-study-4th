# 10주차 · 링크가 끊기면 경로표는 누가 고칠까?

요약: 작은 그래프로 링크 상태·거리 벡터 계산을 비교하고, 준비된 세 라우터의 OSPF 이웃·경로·ping을 조회한다. 각자 링크 하나를 끊고 우회 경로와 요청 결과를 비교한 뒤 복구한다.

<span id="weekly-study"></span>

## 개인 공부와 오프라인 확인

오프라인 모임 전까지 아래 범위를 공부하고 실습을 시도한다. 모임은 그 주의 학습을 마무리하는 자리로, 막힌 이유와 조건을 바꾼 결과를 설명하고 남은 보충을 정한다. [공동 질문](WORKSHEET.md)은 개인 공부의 출발점으로 쓰고, 모임에서는 근거를 비교한다. 별도 사전 모임이나 발표 자료는 필요하지 않다.

- **개념·문제:** LS/Dijkstra·DV/Bellman-Ford 한 차례 계산, OSPF 이웃·Router ID·cost·수렴, AS/IGP/eBGP/iBGP·정책. [교재](CONCEPTS.md) → [공식 지정 절](SOURCES.md) → [복습](REVIEW.md) 순서로 읽고, 먼저 답한 뒤 [해설](ANSWERS.md)과 비교한다.
- **실습·분석:** 4노드 계산과 준비된 3라우터의 정상→R2-R3 링크 단절→우회→복구. Docker/이미지는 모임 전에 점검. 라우터 전체 중지·공용망 변경은 하지 않음. [실행 안내](LINUX.md)의 필수/선택과 제공 분석/직접 수행 구분을 따른다.
- **모임에 가져올 것:** 본인의 근거에서 고른 출력·풀이와 아직 설명이 막힌 질문. 개인 학습 노트에 한 번 정리하고 원시 로그·pcap은 파일 링크로 연결해도 된다. 새 제출 양식은 만들지 않는다.

<span id="personal-notes"></span>

### 개인 공부를 정리할 때

기존 개인 학습 노트에 아래 세 가지를 중심으로 정리한다. 모임 전에는 현재 답과 막힌 지점을 남기고, 모임 뒤에는 확인한 차이와 보충할 부분을 고친다. 정해진 개수·분량이나 새 제출물은 없다.

- **주요 질문과 내 답:** [공동 질문](WORKSHEET.md)과 아래 확인 질문에 먼저 내 말로 답한다. 이유·성립 조건과 공식 자료·실습 근거를 연결하고, [분리 해설](ANSWERS.md)은 시도 뒤에 비교한다.
- **헷갈리는 개념 비교:** [핵심 설명](CONCEPTS.md)에서 경로 수렴과 서비스 회복의 역할·관찰 위치·성공 범위를 비교한다. 두 개념이 다른 결론을 내는 예를 들어 본다.
- **이번 주 꼭 기억하고 이해할 핵심 개념:** [핵심 정리](CONCEPTS.md)의 W10-K1~K3를 길잡이로 용어·역할·동작 순서를 추린다. 필요한 공식은 식·단위·성립 조건과 적용 이유를 함께 설명한다. 예제 주소·일회성 출력값을 외우는 목록으로 만들지 않는다.

실습 근거는 해당 질문·개념 아래에 예상·실제 관찰·수정한 이해와 함께 연결한다. 제공 분석과 직접 실행을 구별하고 관찰하지 않은 결과는 채우지 않는다. 입력 화면을 썼다면 이동 전에 답안을 내려받는다. [전체 개념 색인의 정리 방법](../CONCEPT_INDEX.md#personal-study)은 다른 주차에도 같은 방식으로 쓸 수 있다.

### 오프라인에서 확인할 질문

1. **중심 질문:** OSPF 이웃 Full과 경로 변경만으로 서비스 복구를 확정할 수 있을까?
2. **조건을 바꾸면:** 인터페이스 단절·경로표 변경·첫 ping 성공의 시각이 왜 같지 않을 수 있을까?
3. **앞 개념을 다시 쓰면:** 7주 반환 경로와 9주 STP/LACP 전환은 이번 OSPF와 어느 계층에서 다른가?

중심 질문을 먼저 설명하고 나머지는 짧은 후속 질문으로 사용한다. [분리 해설](ANSWERS.md)과 실제 근거를 대조하되 답을 본 시도와 독립 설명을 구별한다. 개인 공부에서 마친 정상 실습을 전부 반복하지 않고, 막힌 항목과 한 조건 변경·복구를 각자 확인한다.

### 같은 개념을 더 깊게 연결하기

수동 경로를 정보 교환/수렴으로 넓힌다. 12주 설계와 13주 실제 서비스에서 경로와 정책을 따로 확인한다. [핵심 개념의 단계별 연결](../CONCEPT_INDEX.md#operations-progression)에서 앞뒤 학습을 찾는다.

## 앞에서 배운 것으로 시작하기

[7주차](../week-07/CONCEPTS.md)에서는 정적 경로와 최장 접두사, 왕복 경로·TTL을 읽었다. [9주차](../week-09/CONCEPTS.md)는 STP가 L2 루프를 막고 LACP가 여러 멤버를 논리 링크로 묶는 원리를 다뤘다. 이번에는 **라우터가 IP 경로 정보를 서로 알리고 다시 계산하는 과정**을 본다. 링크 차단이나 집성과 IP 경로 갱신은 서로 다른 일이다.

## 함께 사용할 순서

1. [중심 질문](WORKSHEET.md)을 정하고 지정한 공식 절에서 근거를 찾는다.
2. [개념 교재](CONCEPTS.md)에서 W10-K1~K3·4노드 계산·혼동 두 가지를 읽고 한 사람이 설명한다.
3. [필수 실습](LINUX.md)에서 각자 OSPF 이웃·경로·도달성을 조회하고 링크 하나를 변경·복구한다. 초기 구축은 진행자가 준비한다.
4. [복습 문제](REVIEW.md)에 먼저 답하고 [분리 해설](ANSWERS.md)과 비교한다. [진행자 안내](FACILITATOR.md)와 [공식 출처](SOURCES.md)는 필요한 곳에서 찾는다.

## 필수와 선택

필수 이론은 Dijkstra 최단 경로와 Bellman-Ford 갱신 한 차례, LS/DV·정적/동적·AS/BGP 정책 역할이다. 필수 직접 실습은 준비된 **FRRouting 10.5.1 세 라우터·단일 영역**에서 정상→한 링크 단절→경로 재선택→복구다. 구성 파일 일곱 개와 실제 명령을 [실습 안내](LINUX.md)에서 내려받는다.

OSPF 독립 구축, 다중 영역·LSA 형식 상세·재분배, BGP 속성·설정은 선택이다. 제공 출력을 읽기만 했다면 분석과 본인 직접 수행을 구분해 실습을 보충한다. 12주차 설명에 쓸 본인 명령·출력은 개인 파일에 한 번 보관한다. 별도 팀 기록·마무리 양식은 없다.
