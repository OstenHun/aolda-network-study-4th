# 진행자 안내 · 계산에서 실제 OSPF 전환까지

요약: 개인 공부에서 개념·문제·실습을 준비하고 오프라인 한 번에서 설명·조건 변경·직접 수행을 확인한다. 준비·복구와 제공 분석의 경계를 지키며 막힌 필수 항목을 보충한다.

## 먼저 준비할 것

[학습 홈](README.md)의 필수/선택과 [실습](LINUX.md)의 일곱 파일·Docker/Compose 조건을 읽는다. 소유한 격리 환경에서 세 이웃표·양 방향 경로·lo 출발 ping의 정상 기준과 shutdown/no shutdown을 리허설한다. 공용망·SSH 관리 NIC는 변경하지 않는다. 참가자마다 준비한 프로젝트 소유자를 정하고 같은 엔진에서 이름·서브넷이 충돌하는지 확인한다.

처음 구축하는 작업과 필수 실습을 분리한다. 이미지 다운로드·설치가 실습 시간을 차지하면 미리 준비한다. 준비되지 않은 사람에게 고정 출력을 읽게 한 뒤 직접 수행 완료로 표시하지 않는다. 분석·미완료·보충 환경을 구별한다. 7주의 정적 route_sim과 9주의 switch_sim은 OSPF를 제공하지 않는다.

## 한 주의 개인 공부와 오프라인 확인

개인 준비는 [학습 홈의 정리 안내](README.md#personal-notes)에 따라 주요 질문과 내 답·헷갈리는 개념 비교·꼭 기억하고 이해할 핵심을 살핀다. 노트 분량을 평가하지 않고 이유·조건 변경·관련 실습 근거로 확인한다. 모임 뒤에는 틀린 설명과 남은 보충만 기존 개인 노트에서 고치며 중복 제출을 요구하지 않는다.

[학습 홈의 개인 공부 범위와 세 확인 질문](README.md#weekly-study)을 오프라인 모임 전까지 준비한다. 모임은 그 주 학습을 마무리하고 남은 보충을 정하는 자리다. 개념·공식 지정 절·복습과 준비된 실습의 정상→변경→복구는 개인 공부에서 시도한다. 모임 전 완성 답안·발표 자료를 요구하지 않으며 막힌 질문과 본인 근거를 가져오게 한다. 진단 원인을 가리는 과제는 정상 기준과 도구까지만 준비한다.

오프라인은 한 번의 모임에서 **설명 → 새 조건 → 본인 실습/분석 확인 → 보충 결정**으로 진행한다. 아래 60분은 시간 배분 예시이며 모임 길이나 추가 회차를 확정하는 표가 아니다.

| 시간 예시 | 진행자가 확인할 것 |
| --- | --- |
| 0~10분 | 개인 공부에서 막힌 질문과 2~4학습 단위 전 개념 하나를 골라 근거로 설명 |
| 10~25분 | 학습 홈의 중심 질문 → 조건 변경. 소그룹에서 설명자/확인자 교대 |
| 25~50분 | 4노드 계산과 준비된 3라우터의 정상→R2-R3 링크 단절→우회→복구. 이미 수행했다면 근거를 보고 다른 한 조건의 판단·변경·복구 확인 |
| 50~60분 | 정상 복구·받은 도움·미완료 구분, 개인 학습 노트에 필요한 보충과 다음 질문 연결 |

개인 학습 시간을 고정된 2~3시간으로 제한하지 않는다. 필수 범위를 먼저 공부하고 실제 막힘에 따라 시간을 배분한다. 주차를 미리 분할하거나 필수 기준을 낮추지 않으며, 개인 공부 후에도 해결되지 않는 항목만 보충한다. C04/C08/C12/C16은 해당 주 기존 설명·실습을 대체하고 점검을 별도로 더하지 않는다. 한 사람의 답·팀 합의·파일 제출은 개인 이해/직접 수행의 증거가 아니다.

OSPF 지정 읽기는 RFC 전체가 아니다. [출처](SOURCES.md)의 두 문단·Hello 첫 문단·Full 항목만 시작점으로 삼고, 영어가 막히면 K2와 출력의 Router ID/Address/State를 먼저 연결한다. DV에서는 “한 번 받은 초기 광고”와 “이미 수렴한 값”을 섞지 않도록 한다.

“라우터 하나를 통째로 꺼도 될까?”로 필수 조건을 임의 바꾸지 않는다. R2를 끄는 것과 R2-R3 한 링크를 내리는 것은 장애 범위가 다르다. 시간 초과 시 다중 영역·LSA 필드 상세·BGP 속성·독립 구축을 줄이고 필수 직접 변경·복구는 나누어 보충한다.

## 막힐 때의 짧은 설명

- 비용4가 막히면 확정 노드와 임시 후보를 다른 칸에 쓴다. A-C가 직접 연결이어도 A-B-C가 싼 이유를 두 합으로 비교한다.
- DV에 바로4를 쓰면 처음 B의 광고가5였다는 입력으로 돌아간다. 이웃의 다음 차례 광고를 미리 알 수 없다.
- Full을 성공으로 읽으면 경로표와 ping을 따로 보여 준다. 관찰 대상과 증명하는 범위를 한 문장씩 설명한다.
- 경로는 바뀌는데 ping이 실패하면 역방향·출발 주소·실제 Docker 구성을 확인한다. 동작하지 않는 명령을 환경 문제로만 넘기지 않는다.
- STP와 섞이면 L2 프레임 전달 트리와 L3 목적지 경로를 나란히 그린다. LACP 멤버 하나가 사라져도 논리 링크가 살아 있으면 OSPF 이웃은 유지될 수 있다.

## 설명·직접 수행의 확인

기존 [복습](REVIEW.md)과 [해설](ANSWERS.md)로 계산·정책을 확인하고 본인의 정상→단절→우회→복구 근거를 나중의 C12 설명에 재사용한다. 모든 사람이 새 발표·팀 기록을 만들 필요는 없다. 설명자 한 명의 성공을 전원 독립 수행으로 보지 않는다. 아직 직접 하지 못한 사람의 상태와 보충 행동은 따로 남긴다.
