# 15주차 복습 · 경계·시간제한·자동 판정

요약: 수신 조각과 메시지, EOF와 시간제한, HTTP 응답과 통신 실패를 구별한다. 코드 분기와 직접 변경·원복의 근거를 설명하고, timeout 뒤 재시도 횟수·멱등성의 조건을 확인한다. 답은 분리 해설에서 대조한다.

먼저 [교재](CONCEPTS.md)와 [직접 실습](LINUX.md)을 떠올려 답한다. 출력은 개인 근거를 가리키면 되며 다시 전부 옮길 필요는 없다. [분리 해설](ANSWERS.md)은 답한 뒤 연다.

## Q1. recv 크기로 알 수 있는 것

`hello`와 LF를 한 번의 sendall로 보냈다. 서버는 recv(3)으로 3바이트, 3바이트를 읽었다. 메시지 수·읽기 호출 수·TCP 세그먼트 수 중 무엇을 판단할 수 있는가? 이유를 설명한다.

## Q2. 한글과 누적

UTF-8 한글 한 글자의 바이트가 두 recv 사이에 나뉘었다. 이번 서버는 어느 시점에 디코딩하며 왜 그런가? 메시지 최대 길이의 단위도 말한다.

## Q3. EOF의 의미

같은 `hello`에서 line을 eof로 바꿨다. 서버의 종료 분기와 응답을 설명한다. 보내기만 닫았는데 클라이언트가 응답을 받을 수 있는 이유는 무엇인가? EOF가 항상 오류인지도 조건을 붙인다.

## Q4. 시간제한의 위치

hold 입력에서 서버는 어떻게 계속 기다리지 않도록 하는가? read_line의 deadline/remaining/settimeout 위치를 찾는다. 서버 수신 2초와 클라이언트/HTTP의 timeout이 모두 실행 전체의 정확한 상한인지 설명한다.

## Q5. 직접 변경과 원복

실험 A에서 바꾼 입력 한 가지·유지한 조건·정상/변경/원복의 클라이언트 출력과 서버 관찰을 설명한다. 직접 실행하지 않았다면 미수행과 필요한 보충을 말한다.

## Q6. 404와 통신 오류

실험 B에서 curl이 404를 받고 종료 0, 자동 점검은 status 404·http_error와 종료 1을 기록했다. 모순인가? 서버 중지 때의 기록과 무엇이 다른가? 상태 수신 뒤 본문이 끊기면 성공으로 셀 수 있는가?

## Q7. 수동·자동과 복구

정상/중지/복구에 쓴 같은 경로·자동 횟수·대조한 필드와 서버 로그를 설명한다. 자동 세 줄에서 무엇까지 판단할 수 있고 어떤 원인/성능 주장은 아직 할 수 없는가?

## Q8. timeout 뒤 재시도

‘수량을 1 증가’ 요청의 응답을 못 받았다. 서버가 처리하지 않았다고 단정할 수 있는가? ‘7로 설정’과 비교해 멱등성을 설명하고, 최초 1회+추가 최대 2회의 총 시도 상한과 별도 중단 조건을 말한다.

조건 변경: [가공 예](CONCEPTS.md#retry-budget)처럼 앞 세 호출 계층이 각각 최초 포함 최대3회씩 시도하면 최하위 호출 수 상한은 얼마인가? 한 계층만 재시도하면 어떻게 달라지는가? 시도별0.4초·사이 대기0.2초·최대3회가 전체1초 마감을 보장하는지도 계산하라. 이 조건은 제공 점검 코드의 동작과 구별한다.
