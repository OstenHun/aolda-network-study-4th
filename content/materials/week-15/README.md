# 15주차 · 사람이 확인한 절차를 코드로 반복하기

요약: 작은 TCP 예제로 메시지 경계·부분 수신·EOF·시간제한을 읽고 종료 조건 하나를 바꾼다. 기존 HTTP 서비스의 정상·404·중지·복구를 수동 요청과 제한된 자동 기록으로 대조하고 재시도의 조건을 설명한다.

<span id="weekly-study"></span>

## 개인 공부와 오프라인 확인

오프라인 모임 전까지 아래 범위를 공부하고 실습을 시도한다. 모임은 그 주의 학습을 마무리하는 자리로, 막힌 이유와 조건을 바꾼 결과를 설명하고 남은 보충을 정한다. [공동 질문](WORKSHEET.md)은 개인 공부의 출발점으로 쓰고, 모임에서는 근거를 비교한다. 별도 사전 모임이나 발표 자료는 필요하지 않다.

- **개념·문제:** 소켓 부분 수신·LF·UTF-8 누적, EOF/timeout·수신 deadline, 수동/자동 판정, 멱등성·재시도 횟수/전체 예산. [교재](CONCEPTS.md) → [공식 지정 절](SOURCES.md) → [복습](REVIEW.md) 순서로 읽고, 먼저 답한 뒤 [해설](ANSWERS.md)과 비교한다.
- **실습·분석:** A ending 하나 변경→분기/서버 로그 비교→원복, B 같은 HTTP 경로의 수동/자동 정상·중지·복구. 재시도 예산은 제공 계산으로 분석하며 실제 부하를 만들지 않음. [실행 안내](LINUX.md)의 필수/선택과 제공 분석/직접 수행 구분을 따른다.
- **모임에 가져올 것:** 본인의 근거에서 고른 출력·풀이와 아직 설명이 막힌 질문. 개인 학습 노트에 한 번 정리하고 원시 로그·pcap은 파일 링크로 연결해도 된다. 새 제출 양식은 만들지 않는다.

<span id="personal-notes"></span>

### 개인 공부를 정리할 때

기존 개인 학습 노트에 아래 세 가지를 중심으로 정리한다. 모임 전에는 현재 답과 막힌 지점을 남기고, 모임 뒤에는 확인한 차이와 보충할 부분을 고친다. 정해진 개수·분량이나 새 제출물은 없다.

- **주요 질문과 내 답:** [공동 질문](WORKSHEET.md)과 아래 확인 질문에 먼저 내 말로 답한다. 이유·성립 조건과 공식 자료·실습 근거를 연결하고, [분리 해설](ANSWERS.md)은 시도 뒤에 비교한다.
- **헷갈리는 개념 비교:** [핵심 설명](CONCEPTS.md)에서 수신 조각과 메시지, timeout과 처리 실패의 역할·관찰 위치·성공 범위를 비교한다. 두 개념이 다른 결론을 내는 예를 들어 본다.
- **이번 주 꼭 기억하고 이해할 핵심 개념:** [핵심 정리](CONCEPTS.md)의 W15-K1~K3를 길잡이로 용어·역할·동작 순서를 추린다. 필요한 공식은 식·단위·성립 조건과 적용 이유를 함께 설명한다. 예제 주소·일회성 출력값을 외우는 목록으로 만들지 않는다.

실습 근거는 해당 질문·개념 아래에 예상·실제 관찰·수정한 이해와 함께 연결한다. 제공 분석과 직접 실행을 구별하고 관찰하지 않은 결과는 채우지 않는다. 입력 화면을 썼다면 이동 전에 답안을 내려받는다. [전체 개념 색인의 정리 방법](../CONCEPT_INDEX.md#personal-study)은 다른 주차에도 같은 방식으로 쓸 수 있다.

### 오프라인에서 확인할 질문

1. **중심 질문:** 자동 실패 기록에서 404와 서버 중지, timeout과 서버 미처리를 어떻게 구별할까?
2. **조건을 바꾸면:** 각 3회씩 재시도하는 세 계층의 최하위 호출 상한과 요청 전체 마감은 어떻게 함께 제한할까?
3. **앞 개념을 다시 쓰면:** 4주 ACK와 앱 처리, 14주 느림·오류를 근거로 재전송이 안전한지 판단할 수 있는가?

중심 질문을 먼저 설명하고 나머지는 짧은 후속 질문으로 사용한다. [분리 해설](ANSWERS.md)과 실제 근거를 대조하되 답을 본 시도와 독립 설명을 구별한다. 개인 공부에서 마친 정상 실습을 전부 반복하지 않고, 막힌 항목과 한 조건 변경·복구를 각자 확인한다.

### 같은 개념을 더 깊게 연결하기

전송의 경계를 코드와 시간 예산으로 명시한다. 16주에는 같은 정상 기준을 가지고 관찰·최소 변경·복구를 스스로 고른다. [핵심 개념의 단계별 연결](../CONCEPT_INDEX.md#operations-progression)에서 앞뒤 학습을 찾는다.

## 이번 주의 질문

**사람이 하던 확인을 코드로 반복해도 같은 결론을 낼 수 있을까?** 먼저 [1주차 요청·로그](../week-01/README.md), [4주차 바이트 스트림](../week-04/CONCEPTS.md), [6주차 HTTP 경계](../week-06/CONCEPTS.md)를 떠올린다. `recv`가 돌아왔다는 사실과 메시지 완료, HTTP 응답 수신과 서비스 성공을 각각 구별한다.

## 함께 공부하는 순서

1. [공동 질문 W15-D1](WORKSHEET.md)에서 수동 확인에 필요한 관찰을 고른다.
2. [교재 K1\~K3](CONCEPTS.md)와 [공식 지정 절](SOURCES.md)을 함께 읽는다. 경계·EOF·시간제한을 코드에서 찾는다.
3. 한 명이 근거를 설명하고 다른 사람이 종료 조건 하나를 바꿔 묻는다. 다음 설명자는 교대한다.
4. [실험 A](LINUX.md#socket-lab)에서 `line → eof → line`을 직접 실행한다. [실험 B](LINUX.md#http-lab)에서 같은 HTTP 입력의 수동·자동 결과를 정상→서버 중지→복구로 대조한다.
5. [복습](REVIEW.md)을 먼저 풀고 [분리 해설](ANSWERS.md)과 비교한다. [진행자 안내](FACILITATOR.md)에서 막힐 때 돌아갈 설명을 찾는다.

## 필수와 선택

| 구분 | 이번에 할 일 |
| --- | --- |
| 필수 설명 | 메시지 경계·부분 수신·EOF·시간제한 처리 위치, timeout 뒤 처리 불확실성·재시도 상한·멱등성 |
| 필수 직접 수행 A | 준비된 소켓 코드에서 `--ending` 입력 한 가지를 바꾸고 출력·서버 로그를 비교한 뒤 원복 |
| 필수 직접 수행 B | 기존 Handler의 200/404 수동·자동 대조, 같은 정상 경로에서 중지·복구 전후 각 3회 기록 |
| 선택 | A의 `hold`, 짧은 클라이언트 시간제한과 서버 응답 대기 비교, UTF-8 메시지와 수신 크기 해석 |
| 후속 | 큰 자동화 플랫폼, Ansible/Terraform 계획 읽기, NETCONF/YANG, 부하·복합 장애 |

본인에게 허가된 기존 Linux 한 대의 루프백에서 실행한다. 새 언어·큰 앱·TCP 스택 구현·외부 공개·유료 자원은 필요하지 않다. [제공 사례](../../labs/week-15/observations.txt)는 출력 읽기를 돕지만 본인 직접 변경·실행을 대신하지 않는다. 상세 근거는 개인 파일에 한 번 보관하며 팀 기록·개인 마무리 양식을 추가하지 않는다.
