# 진행자 안내 · 링크 상태와 전달 증거

요약: 개인 공부에서 개념·문제·실습을 준비하고 오프라인 한 번에서 설명·조건 변경·직접 수행을 확인한다. 준비·복구와 제공 분석의 경계를 지키며 막힌 필수 항목을 보충한다.

## 사용 전 준비

개인 공부에서 지정 읽기·작은 분석과 두 준비 실습을 시도한다. 오프라인에서는 원리와 조건 변경·복구를 확인하며 독립 초기 구축이나 발표 자료를 요구하지 않는다.

진행자는 본인 PC에서 [실습](LINUX.md)의 세 파일과 Python 버전을 확인하고 A1~A3/B를 정상→변경→복구 순으로 리허설한다. 고정 출력만 시연하지 말고 참가자 각자가 명령을 실행할 수 있는지 확인한다. OS 네트워크나 공용 스위치를 바꿀 이유는 없다. 화면 글씨가 작으면 터미널 확대를 먼저 한다.

## 한 주의 개인 공부와 오프라인 확인

개인 준비는 [학습 홈의 정리 안내](README.md#personal-notes)에 따라 주요 질문과 내 답·헷갈리는 개념 비교·꼭 기억하고 이해할 핵심을 살핀다. 노트 분량을 평가하지 않고 이유·조건 변경·관련 실습 근거로 확인한다. 모임 뒤에는 틀린 설명과 남은 보충만 기존 개인 노트에서 고치며 중복 제출을 요구하지 않는다.

[학습 홈의 개인 공부 범위와 세 확인 질문](README.md#weekly-study)을 오프라인 모임 전까지 준비한다. 모임은 그 주 학습을 마무리하고 남은 보충을 정하는 자리다. 개념·공식 지정 절·복습과 준비된 실습의 정상→변경→복구는 개인 공부에서 시도한다. 모임 전 완성 답안·발표 자료를 요구하지 않으며 막힌 질문과 본인 근거를 가져오게 한다. 진단 원인을 가리는 과제는 정상 기준과 도구까지만 준비한다.

오프라인은 한 번의 모임에서 **설명 → 새 조건 → 본인 실습/분석 확인 → 보충 결정**으로 진행한다. 아래 60분은 시간 배분 예시이며 모임 길이나 추가 회차를 확정하는 표가 아니다.

| 시간 예시 | 진행자가 확인할 것 |
| --- | --- |
| 0~10분 | 개인 공부에서 막힌 질문과 2~4학습 단위 전 개념 하나를 골라 근거로 설명 |
| 10~25분 | 학습 홈의 중심 질문 → 조건 변경. 소그룹에서 설명자/확인자 교대 |
| 25~50분 | A MAC/VLAN 변경·복구와 STP 링크 전환, B LACP 멤버 단절/복구를 개인 환경에서 수행하고 출력 준비. 이미 수행했다면 근거를 보고 다른 한 조건의 판단·변경·복구 확인 |
| 50~60분 | 정상 복구·받은 도움·미완료 구분, 개인 학습 노트에 필요한 보충과 다음 질문 연결 |

개인 학습 시간을 고정된 2~3시간으로 제한하지 않는다. 필수 범위를 먼저 공부하고 실제 막힘에 따라 시간을 배분한다. 주차를 미리 분할하거나 필수 기준을 낮추지 않으며, 개인 공부 후에도 해결되지 않는 항목만 보충한다. C04/C08/C12/C16은 해당 주 기존 설명·실습을 대체하고 점검을 별도로 더하지 않는다. 한 사람의 답·팀 합의·파일 제출은 개인 이해/직접 수행의 증거가 아니다.

시간이 넘으면 선택 passive/passive·전체 단절·trunk 허용 목록 조작·독립 구축을 먼저 줄인다. 필수 A/B를 제공 trace 읽기로 완료 처리하지 말고 별도 보충에 남긴다. 원리 설명이 막히면 용어를 더 늘리지 않고 현재 출력의 필드 하나부터 읽는다.

## 관찰을 해석하는 기준

[실제 STP·LACP 보완 실습](REAL_L2.md)은 모임 전에 Docker Linux 엔진·netns·bridge·OVS와 정상 상태까지 준비한다. STP의 root/포트 변화·BPDU와 데이터 응답, LACP의 actor/partner·선택 멤버·LACPDU와 응답을 같은 단계에서 비교한다. 모델→실제 구현의 대응에 기존 실습 시간을 쓰며 설치부터 학습자에게 맡기거나 새 제출물을 요구하지 않는다. 고전 STP의 대기와 데이터 복귀 지연을 보존한다. 지원되지 않는 환경에서는 기존 모형과 실제 도구 미수행을 구분한다. 초기 구축·고급 튜닝은 선택 범위다.

루트가 같아도 포트가 바뀔 수 있고, physical up이어도 데이터 차단·LACP 미참여일 수 있다. `PROBE PASS`는 모의 L2 왕복이며 실제 ping·HTTP·처리량의 증거가 아니다. 실제 패킷·프로토콜 타이머가 필요하면 별도의 허가된 격리 장비에서 확인한다. 그 환경을 이번 모델 실행으로 갈음하지 않는다.

기본 설명과 본인 정상→변경→복구를 [분리 해설](ANSWERS.md)·본인 출력으로 확인한다. 한 사람의 설명이나 해설 열람이 전원의 직접 수행 완료를 뜻하지 않는다. 이후 C12에서는 이 근거를 재사용한다. 복잡한 선출·RSTP/MSTP·보호·다중 섀시·해시 정책·CRC 다항식 계산은 후속 선택이다.
