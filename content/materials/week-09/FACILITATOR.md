# 진행자 안내 · 링크 상태와 전달 증거

요약: 중심 질문과 두 공식 지정 절에서 출발해 MAC/VLAN·STP·LACP를 설명한다. 두 직접 실습의 변경·복구를 확보하고, 시간이 부족하면 선택부터 줄인다.

## 사용 전 준비

개념 모임과 직접 실습을 각각60분으로 잡은 아래 배치는 추정이다. 실측 완료 시간이나 확정 모임 횟수가 아니다. 개인 준비는 지정 읽기·작은 분석과 Python 확인에 쓰고, 독립 초기 구축이나 발표 자료를 요구하지 않는다.

진행자는 본인 PC에서 [실습](LINUX.md)의 세 파일과 Python 버전을 확인하고 A1~A3/B를 정상→변경→복구 순으로 리허설한다. 고정 출력만 시연하지 말고 참가자 각자가 명령을 실행할 수 있는지 확인한다. OS 네트워크나 공용 스위치를 바꿀 이유는 없다. 화면 글씨가 작으면 터미널 확대를 먼저 한다.

## 공동학습 60분 배치안

| 시간 | 함께 할 일 | 막히면 돌아갈 설명 |
| --- | --- | --- |
| 0~5분 | 2/3주 접두사·ARP 복습, W09-D1 질문 | 같은 /24 계산과 broadcast 도달 범위 분리 |
| 5~15분 | access/trunk·STP 지정 두 절 공동 탐색 | [출처의 필수 범위](SOURCES.md), 영문 두 문장씩 역할을 풀어 설명 |
| 15~30분 | K1·K2, 삼각형에서 루트/포트 읽기 | 출발지 학습과 목적지 조회, 역할과 상태의 차이 |
| 30~40분 | K3, 한 사람이 설명하고 멤버 조건 변경 질문 | 논리 포트 po1과 m1/m2, flow 분산과 단일 연결 |
| 40~55분 | 오류 검출 표 분석·Q7/Q8, 핵심3/혼동2 확인 | parity의 두 비트 반례·CRC 나머지0의 한계 |
| 55~60분 | 각자 실습 파일·정상 기준 점검 | Python 실행 위치와 sim>의 차이 |

## 직접 실습 60분 배치안

| 시간 | 필수 수행 | 확인할 근거 |
| --- | --- | --- |
| 0~5분 | 파일·버전·구성 확인 | SIM v1·show·원래 VLAN/링크 |
| 5~20분 | A1/A2 MAC·broadcast·VLAN 변경/복구 | LEARN/FLOOD/UNICAST·ACCESS·FRAME·PASS/FAIL |
| 20~35분 | A3 STP 링크 단절/복구 | root·cost·포트·TX·모의 왕복의 전후 |
| 35~50분 | B LACP 멤버 하나 단절/복구 | selected·carrier/참여·po1·flow별 선택·모의 왕복 |
| 50~60분 | 짧은 조건 변경 설명·복구/종료·개인 근거 보관 | 본인 수행/도움/미완료 구별. Q3~Q6 근거 재사용 |

시간이 넘으면 선택 passive/passive·전체 단절·trunk 허용 목록 조작·독립 구축을 먼저 줄인다. 필수 A/B를 제공 trace 읽기로 완료 처리하지 말고 별도 보충에 남긴다. 원리 설명이 막히면 용어를 더 늘리지 않고 현재 출력의 필드 하나부터 읽는다.

## 관찰을 해석하는 기준

루트가 같아도 포트가 바뀔 수 있고, physical up이어도 데이터 차단·LACP 미참여일 수 있다. `PROBE PASS`는 모의 L2 왕복이며 실제 ping·HTTP·처리량의 증거가 아니다. 실제 패킷·프로토콜 타이머가 필요하면 별도의 허가된 격리 장비에서 확인한다. 그 환경을 이번 모델 실행으로 갈음하지 않는다.

기본 설명과 본인 정상→변경→복구를 [분리 해설](ANSWERS.md)·본인 출력으로 확인한다. 한 사람의 설명이나 해설 열람이 전원의 직접 수행 완료를 뜻하지 않는다. 이후 C12에서는 이 근거를 재사용한다. 복잡한 선출·RSTP/MSTP·보호·다중 섀시·해시 정책·CRC 다항식 계산은 후속 선택이다.
