# 9주차 · 같은 스위치인데 왜 닿지 않을까?

요약: MAC 학습과 VLAN의 전달 범위를 구별하고, 격리 모형에서 STP 경로와 LACP 멤버를 끊고 복구한다. 준비된 실제 도구에서는 BPDU·LACPDU·데이터 전달을 비교하며 오류 검출은 작은 예제로 확인한다.

<span id="weekly-study"></span>

## 개인 공부와 오프라인 확인

오프라인 모임 전까지 아래 범위를 공부하고 실습을 시도한다. 모임은 그 주의 학습을 마무리하는 자리로, 막힌 이유와 조건을 바꾼 결과를 설명하고 남은 보충을 정한다. [공동 질문](WORKSHEET.md)은 개인 공부의 출발점으로 쓰고, 모임에서는 근거를 비교한다. 별도 사전 모임이나 발표 자료는 필요하지 않다.

- **개념·문제:** MAC 학습/전달·VLAN/access/trunk, STP 역할/상태, LACP 논리 링크/멤버/흐름, parity/checksum/CRC의 검출 한계. [교재](CONCEPTS.md) → [공식 지정 절](SOURCES.md) → [복습](REVIEW.md) 순서로 읽고, 먼저 답한 뒤 [해설](ANSWERS.md)과 비교한다.
- **실습·분석:** A MAC/VLAN 변경·복구와 STP 링크 전환, B LACP 멤버 단절/복구를 개인 환경에서 수행하고 출력 준비. 독립 초기 구성·복잡한 선출은 선택. [실행 안내](LINUX.md)의 필수/선택과 제공 분석/직접 수행 구분을 따른다.
- **실제 구현과 비교:** [Linux bridge·Open vSwitch 실습](REAL_L2.md)은 준비된 격리 환경에서 BPDU·LACPDU와 상태·ICMP를 관찰한다. 기존 모형은 예상·복습에 유지하며, 실제 도구 준비와 수행은 별도로 확인한다.
- **모임에 가져올 것:** 본인의 근거에서 고른 출력·풀이와 아직 설명이 막힌 질문. 개인 학습 노트에 한 번 정리하고 원시 로그·pcap은 파일 링크로 연결해도 된다. 새 제출 양식은 만들지 않는다.

<span id="personal-notes"></span>

### 개인 공부를 정리할 때

기존 개인 학습 노트에 아래 세 가지를 중심으로 정리한다. 모임 전에는 현재 답과 막힌 지점을 남기고, 모임 뒤에는 확인한 차이와 보충할 부분을 고친다. 정해진 개수·분량이나 새 제출물은 없다.

- **주요 질문과 내 답:** [공동 질문](WORKSHEET.md)과 아래 확인 질문에 먼저 내 말로 답한다. 이유·성립 조건과 공식 자료·실습 근거를 연결하고, [분리 해설](ANSWERS.md)은 시도 뒤에 비교한다.
- **헷갈리는 개념 비교:** [핵심 설명](CONCEPTS.md)에서 VLAN과 서브넷, STP와 LACP의 역할·관찰 위치·성공 범위를 비교한다. 두 개념이 다른 결론을 내는 예를 들어 본다.
- **이번 주 꼭 기억하고 이해할 핵심 개념:** [핵심 정리](CONCEPTS.md)의 W09-K1~K3를 길잡이로 용어·역할·동작 순서를 추린다. 필요한 공식은 식·단위·성립 조건과 적용 이유를 함께 설명한다. 예제 주소·일회성 출력값을 외우는 목록으로 만들지 않는다.

실습 근거는 해당 질문·개념 아래에 예상·실제 관찰·수정한 이해와 함께 연결한다. 제공 분석과 직접 실행을 구별하고 관찰하지 않은 결과는 채우지 않는다. 입력 화면을 썼다면 이동 전에 답안을 내려받는다. [전체 개념 색인의 정리 방법](../CONCEPT_INDEX.md#personal-study)은 다른 주차에도 같은 방식으로 쓸 수 있다.

### 오프라인에서 확인할 질문

1. **중심 질문:** 같은 /24 두 장치가 다른 VLAN이면 왜 ARP와 요청이 닿지 않을까?
2. **조건을 바꾸면:** STP 차단 포트와 LACP의 선택 멤버는 어떤 역할 차이가 있으며 단절 뒤 무엇을 확인할까?
3. **앞 개념을 다시 쓰면:** 3주 이웃 캐시와 이번 FDB는 무엇을 기억하며, PASS 하나로 성능까지 확인했는가?

중심 질문을 먼저 설명하고 나머지는 짧은 후속 질문으로 사용한다. [분리 해설](ANSWERS.md)과 실제 근거를 대조하되 답을 본 시도와 독립 설명을 구별한다. 개인 공부에서 마친 정상 실습을 전부 반복하지 않고, 막힌 항목과 한 조건 변경·복구를 각자 확인한다.

## 먼저 떠올릴 것

[3주차 ARP](../week-03/arp.html)에서 목적지 IP와 다음 홉 MAC을 구별했다. [2주차](../week-02/concepts.html)의 접두사 계산이 같더라도 링크가 분리되어 있으면 ARP가 상대에게 닿지 않을 수 있다. [7주차](../week-07/CONCEPTS.md)는 IP의 왕복 경로를, [8주차](../week-08/CONCEPTS.md)는 관찰 위치와 IPv6 이웃 탐색을 다뤘다. 이번에는 그 아래의 L2 전달 범위를 살핀다.

## 함께 사용할 순서

1. [중심 질문](WORKSHEET.md)을 고르고, access/trunk와 STP의 지정 공식 절에서 근거를 찾는다.
2. [개념 교재](CONCEPTS.md)의 W09-K1~K3와 혼동 두 가지를 읽고 한 사람이 설명한다.
3. [필수 실습 A/B](LINUX.md)에서 각자 상태를 바꾸고 전달 결과·복구를 확인한다.
4. [복습 문제](REVIEW.md)에 답한 뒤 [분리 해설](ANSWERS.md)과 비교한다. [진행자 안내](FACILITATOR.md)와 [출처](SOURCES.md)는 필요한 때 찾는다.

시뮬레이터는 메모리 안에서 프레임·수렴 후 상태를 계산한다. 고정 출력 읽기와 구별해 본인이 명령을 실행하고 바꾼 조건을 근거로 설명한다. 실제 Ethernet 패킷·수렴 시간·처리량·Linux 네트워크 설정을 측정하는 도구는 아니다. 직접 실행하지 못했다면 분석과 남은 직접 수행을 나눈다.

복잡한 선출, RSTP/MSTP·보호 기능, 다중 섀시 집성, 해시 정책의 독립 구성과 CRC 다항식 계산은 선택이다. 다음에는 L2의 루프 방지와 IP 라우팅 정보의 갱신을 구별한다.
