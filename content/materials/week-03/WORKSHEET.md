# 3주차 함께 찾을 질문 — 패킷의 다음 전달 상대

요약: 목적지 IP와 링크의 다음 상대가 어떻게 연결되는지 함께 찾는다. 주제별 교재와 공식 자료를 읽고 한 명이 설명한 뒤 목적지·캐시 조건을 비교한다. 실제 조회·제공 예제·직접 관찰을 구분한다.

## 중심 질문

**목적지 IP를 아는데 왜 MAC 주소와 ARP가 필요할까?**

먼저 2주차의 같은/다른 서브넷·게이트웨이를 짧게 설명한다. 막히면 [복습 진단](topics/01-recall.md)에서 필요한 앞 개념으로 돌아간다. 답을 미리 알아야 참여할 수 있는 활동이 아니다.

## 함께 찾아 공부하는 순서

| 단계 | 함께 할 일 | 볼 자료 |
| --- | --- | --- |
| 질문 고르기 | 최종 서버와 첫 링크의 전달 상대를 어떻게 구별할지 예상한다 | 중심 질문 |
| 공동 탐색 | 프레임·다음 홉·주소 대응을 필요한 순서로 함께 읽는다 | [LAN·MAC](topics/02-lan-mac.md) → [다음 홉](topics/03-next-hop.md) → [ARP·캐시](topics/04-arp.md) |
| 한 명 설명 | IP 목적지와 다음 상대를 작은 그림으로 표시하고 근거 절을 가리킨다 | 교재·실제 경로/이웃 출력 또는 [가상 패킷 예제](../../labs/week-03/sample-trace.txt) |
| 조건 변경 | 목적지가 같은 링크에 있을 때와 게이트웨이를 거칠 때를 비교해 묻는다 | 아래 보조 질문·[ICMP·ping](topics/05-icmp.md) |
| 직접 확인 | 주소·경로·이웃을 조회하고 허용 대상에 짧은 ping을 보낸다 | [Linux 실험](LINUX.md), 직접 캡처 또는 제공 trace 분석 |

설명자는 질문이나 회차마다 교대한다. 다른 사람도 조건 변경에 답하거나 출력을 읽는다. AI 설명은 가설로 두고 공식 자료·조회·패킷과 대조한다. 실제 관찰 전의 예상, 제공 자료의 결과, 본인 실행 결과를 구별한다.

## 검색을 시작할 공식 절

- [RFC 826](https://www.rfc-editor.org/rfc/rfc826)의 “Packet Generation”·“An Example”: 경로 판단과 주소 대응 조회가 어떻게 이어지는지 찾는다.
- [RFC 792](https://www.rfc-editor.org/rfc/rfc792)의 “Echo or Echo Reply Message”: ICMP Echo의 요청·응답과 확인 가능한 범위를 읽는다.

명령의 의미와 추가 읽기 범위는 [출처 안내](SOURCES.md)에서 확인한다. 원문이 어렵거나 열리지 않으면 해당 주제의 한국어 교재로 함께 공부하고 원문 미열람과 구분한다.

## 선택 보조 질문

### 다른 망의 서버로 보낼 때 누구의 MAC을 찾을까?

`ip -4 route get TARGET`의 `via` 유무를 비교한다. 게이트웨이의 MAC을 최종 서버의 MAC이라고 부르면 무엇이 틀릴까? 이웃 행이 없거나 `FAILED`라면 무엇을 모를까? [다음 홉](topics/03-next-hop.md)·[ARP](topics/04-arp.md)와 실제 출력 또는 가상 패킷 예제 A01~A03·B01~B03을 대조한다. 문서 예시 주소로 요청을 보내지 않는다.

### ARP가 안 보이거나 ping 응답이 없으면 무엇을 말할 수 있을까?

캐시·캡처 시각을 바꾸어 생각하고, Echo reply가 없다는 사실과 HTTP 서비스 상태를 구별한다. [ICMP](topics/05-icmp.md), 제한된 캡처·전후 이웃 상태 또는 가상 패킷 예제 A04~A06·B04를 근거로 설명한다. 1주차 lo의 HTTP 캡처를 Ethernet ARP 관찰로 쓰지 않는다.

[핵심 정리의 개발 사례](ESSENTIALS.md)는 관련 질문에 이어 선택한다. 보조 질문을 모두 같은 시간에 끝내거나 추가 발표 자료를 만들 필요는 없다.

## 실습 뒤 설명과 복습

실험 A에서 주소·경로·이웃을 읽고 실험 B에서 허용 대상에 제한된 ping을 보낸다. 프레임·ARP·ICMP는 직접 캡처 또는 제공 trace로 분석한다. 같은 링크/게이트웨이 사례를 그림으로 비교하고 자신의 경로·이웃을 도움 없이 다시 읽는다. 실제 대상 변경은 허용 범위 안에서만 하며 관리 NIC·경로·정책·이웃 캐시를 변경하지 않는다.

[복습 문제](REVIEW.md)에 먼저 답한 뒤 [분리 해설](ANSWERS.md)과 비교한다. 상세 명령·출력·패킷은 개인 파일이나 노트에 한 번 보관한다. 필요하면 [개인 실습 메모](../../labs/week-03/PERSONAL_RECORD.md)를 참고하되 정해진 양식을 모두 채울 필요는 없다.

허용 대상·도구·권한이 없으면 제공 예제를 분석하고 실행하지 못한 항목과 보충할 행동을 구분해 둔다. 한 사람의 VM 결과를 모두의 직접 수행으로 세지 않는다. 모르는 MAC은 추정해서 채우지 않는다.
