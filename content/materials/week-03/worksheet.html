개발 질문을 함께 다룰 때

핵심 정리의 개발 사례를 관련 질문 하나의 추가 질문으로 사용한다. 기존 세 질문과 팀 기록 세 항목·개인 마무리 두 줄 안에서 다루며 새 기록 칸을 추가하지 않는다. 시간이 부족하면 사례의 첫 질문만 설명하고 조건 변경·진단은 선택으로 둔다.

모임에서 사용하는 방법

개념 교재 색인과 Linux 안내를 옆에 둔다. 사전 모임에서는 아래 세 질문을 제공 교재·가상 패킷 예제로 이야기하고, 실습 모임에서는 각자의 실제 조회·패킷이 있으면 설명을 다시 확인한다. 사전 모임에서는 질문 하나에 약 8분, 세 질문에 약 25분을 쓴다. 오프라인에서는 같은 세 질문을 5분씩 다시 확인하고, 45~55분에 짝·3인 소그룹의 병렬 2분 설명을 진행한다. 환경 준비와 직접 실험 시간은 별도다.

모두 같은 질문을 먼저 생각한다. 질문마다 설명자를 바꾼다. 한 번도 설명하지 못한 사람은 다음 회차에 먼저 기회를 준다. 길게 쓰기보다 서로의 설명에서 막히는 지점을 찾는다. 생각 메모는 선택이고 팀 기록은 대화가 끝난 뒤 세 가지만 정리한다.

질문 하나를 다루는 순서

순서 시간 함께 할 일
각자 생각 1분 답과 이유를 먼저 생각한다. 바로 해설이나 AI 답을 읽지 않는다.
한 사람 설명 2분 자기 말과 작은 그림으로 설명한다. 실제 출력이나 제공된 패킷 예제를 가리켜도 좋다.
질문과 보완 3분 다른 사람은 반례·조건·모르는 점을 묻고 설명을 보완한다.
근거로 확인 2분 교재·실제 출력·패킷 또는 제공된 패킷 예제의 행 번호와 대조해 함께 설명을 고친다.

실제 조회·캡처가 아직 없으면 예상 또는 제공 자료라고 밝힌다. 의견이 같아도 근거가 없으면 남은 질문으로 둔다. 한 사람의 VM 결과를 모두의 직접 실행으로 세지 않는다.

이번 주 함께 다룰 세 질문

1. 목적지 IP를 아는데 왜 MAC을 또 찾아야 할까?

  • 먼저 설명할 것: IP의 최종 목적지와 Ethernet 프레임이 지금 링크에서 전달될 상대를 구분한다.
  • 서로 물을 것: 내 PC의 NIC와 VM의 가상 NIC는 같은가? lo의 HTTP 캡처에서 ARP를 찾을 수 있는가?
  • 확인할 근거: LAN·MAC, 본인 ip -o link show의 link/ether 또는 가상 패킷 예제 A01·A03의 주소. 실제 물리망 전체를 보았다고 말하지 않는다.

2. 다른 망의 서버로 보낼 때 누구의 MAC을 찾을까?

  • 먼저 설명할 것: ip -4 route get TARGET에 via가 있는 경우와 없는 경우의 다음 상대를 비교한다.
  • 서로 물을 것: 게이트웨이의 MAC을 최종 서버의 MAC이라고 부르면 무엇이 틀리는가? 이웃 행이 없거나 FAILED라면 무엇을 모르는가?
  • 확인할 근거: 다음 홉·ARP, 실제 경로·이웃 출력 또는 가상 패킷 예제 A01~A03과 B01~B03. 문서 주소는 실행 대상이 아니다.

3. ARP가 안 보이거나 ping 응답이 없으면 무엇을 말할 수 있을까?

  • 먼저 설명할 것: ARP 캐시·캡처 시각, ICMP Echo의 요청·응답과 HTTP 서비스 상태를 나눈다.
  • 서로 물을 것: 캐시가 이미 있으면 새 ARP 요청이 꼭 나오는가? Echo reply 없음만으로 서버 중지를 단정할 수 있는가?
  • 확인할 근거: ICMP, 실제 제한된 캡처·ping·전후 이웃 상태 또는 가상 패킷 예제 A04~A06·B04. 제공 예시의 응답을 내 VM 결과로 바꾸어 쓰지 않는다.

팀 기록 — 대화 뒤 세 가지만

기록 담당은 회차마다 교대한다. 날짜·팀·참여자·설명자는 필요한 범위에서 첫 항목에 적고, 공개본에는 이름·접속 정보·민감한 주소를 빼거나 가린다. 각 질문을 짧게 묶어 보관한다. 이 페이지는 자동 저장되지 않으므로 사용한 파일을 직접 보관한다.

  1. 다룬 질문과 근거 위치: 확인한 교재 절, 개인 기록 또는 원본 출력 파일 위치, 패킷/가상 패킷 예제 행 번호. 상세 출력은 팀 기록에 복사하지 않는다.
  2. 바뀐 설명: 처음 생각 → 근거 확인 뒤 설명. 바뀌지 않았다면 무엇으로 확인했는지 쓴다.
  3. 남은 질문: 아직 모르는 것과 다음 확인 방법. 없으면 없음으로 쓴다.

개인 마무리 — 한 줄씩

  • 오늘 이해한 것 하나: 자기 말로 적는다.
  • 아직 헷갈리는 것 하나: 없으면 없음, 있으면 다음에 확인할 질문으로 적는다.

팀 기록은 한 사람이 작성할 수 있지만 개인 마무리는 각자 남긴다. 공유 여부는 본인이 정한다.

직접 실험과 상세 증거

실험 A의 주소·경로·이웃 조회, 실험 B의 허가된 ping·제한 캡처, 예측과 패킷 분석·조건을 바꿔 스스로 다시 확인한 결과는 개인 기록지와 원본 출력 파일에 남긴다. 긴 명령·출력·패킷 표를 이 활동지에 중복해서 적지 않는다. 제공된 패킷 예제를 분석했으면 개인 기록에도 제공 분석으로 표시하고 직접 실행은 미완료로 둔다. 짝의 근거 질문으로 설명을 고쳤더라도 각자의 실제 수행 상태는 따로 확인한다.
