# 3주차 — IP를 아는데 왜 MAC이 필요할까?

요약: 앞선 주소·경로 학습을 복습하고 LAN·MAC·ARP·ICMP를 작은 주제로 익힌다. 주소·경로 조회와 제한된 ping·캡처로 다음 홉을 확인한다.

## 핵심 개념·혼동·개발 질문

[이번 주 핵심 정리](ESSENTIALS.md)에서 기억할 개념 3개·혼동 2개·개발 사례 1개를 찾는다. 기존 개념 읽기 마지막 5분과 공통 질문의 후속 발문에 포함하며 추가 기록 과제로 만들지 않는다. [전체 개념 색인](../CONCEPT_INDEX.md) · [외부 참고자료](../INTERVIEW_REFERENCES.md). 핵심 정리와 개발 질문을 읽은 뒤 직접 설명해 본다. 교재 읽기와 실제 실습 완료는 구별한다.

## 시작과 준비 상태

[3주차 학습 홈](index.html)에서 시작한다. 복습 진단 → 개념 → 함께 설명 → Linux 실험 → 개인 기록 → 복습으로 이어 간다.

**목적지 IP를 아는데 왜 MAC 주소와 ARP가 필요할까?** 이 질문에 답하려면 2주차의 경로 선택과 3주차의 링크 전달을 연결해야 한다. 교재를 읽었다는 사실을 숙달로 취급하지 않고 짧은 진단부터 시작한다.

## 주제 하나만 찾아 읽기

- IP와 port, HTTP 404와 연결 실패를 혼동하면 [복습 진단](topics/01-recall.md)과 [1주차](../week-01/index.html)를 읽는다.
- 같은/다른 서브넷 계산이 막히면 [2주차](../week-02/index.html)로 돌아간 뒤 [다음 홉](topics/03-next-hop.md)을 읽는다.
- 프레임의 상대와 최종 서버를 혼동하면 [LAN·MAC](topics/02-lan-mac.md) → [다음 홉](topics/03-next-hop.md)을 읽는다.
- ARP가 안 보이거나 이웃 행이 없으면 [ARP·캐시](topics/04-arp.md)와 [Linux 대안](LINUX.md)을 읽는다.
- ping과 HTTP 결과가 다르면 [ICMP](topics/05-icmp.md)와 [Q7 해설](ANSWERS.md#q7--ping과-http)을 대조한다.

## 이번 주 완료 증거

각자 목적지 IP·선택 인터페이스·다음 홉 IP·알 수 있는 MAC을 표시한 그림을 남긴다. 실제 `ip route get`과 `ip neigh`를 판단 근거로 쓰고 ARP/ICMP 직접 관찰 또는 [설명용 trace](../../labs/week-03/sample-trace.txt) 분석을 연결한다. 모르는 MAC은 추정해서 채우지 않는다.

캐시 때문에 새 ARP 요청이 없을 수 있음, ping 실패만으로 HTTP 서버 중지를 단정할 수 없음, loopback은 Ethernet ARP 관찰 대상이 아님을 짝에게 설명한다. 직접 실행·진행자 시연·제공 자료 분석을 별도로 표시한다. trace만 분석했다면 본인 VM 실행은 보충으로 남긴다.

## 기존 인스턴스를 사용하는 조건

이미 준비된 Linux 인스턴스를 사용한다. 새 VM 생성부터 반복하지 않는다. 본인의 도구·권한·허용 대상과 VM 간 통신 조건을 먼저 확인한다.

기본 실험은 NIC·주소·경로·정책을 변경하지 않는다. 승인된 대상이 없거나 캡처 권한·도구가 없으면 설명용 자료로 전환한다. [두 VM 비교와 후속 탐구](EXPLORATIONS.md)는 조건을 확인한 뒤 고른다.
