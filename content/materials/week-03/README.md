# 3주차 — IP를 아는데 왜 MAC이 필요할까?

요약: 주소·경로를 복습하고 목적지 IP와 링크의 다음 상대를 함께 탐구한다. 주제별 교재를 찾아 읽고 한 명이 설명한 뒤 조회·제한된 ping·패킷 분석으로 확인한다. 실제 수행과 제공 예제 분석을 구분한다.

<span id="weekly-study"></span>

## 개인 공부와 오프라인 확인

오프라인 모임 전까지 아래 범위를 공부하고 실습을 시도한다. 모임은 그 주의 학습을 마무리하는 자리로, 막힌 이유와 조건을 바꾼 결과를 설명하고 남은 보충을 정한다. [공동 질문](WORKSHEET.md)은 개인 공부의 출발점으로 쓰고, 모임에서는 근거를 비교한다. 별도 사전 모임이나 발표 자료는 필요하지 않다.

- **개념·문제:** LAN·프레임·MAC, 최종 IP와 다음 홉, ARP 캐시, ICMP Echo와 HTTP가 확인하는 범위. [핵심 정리](ESSENTIALS.md) → [공식 지정 절](SOURCES.md) → [복습](REVIEW.md) 순서로 읽고, 먼저 답한 뒤 [해설](ANSWERS.md)과 비교한다.
- **실습·분석:** A 자기 주소/경로/이웃 조회와 B 승인 대상의 제한된 ping. ARP/프레임/ICMP는 직접 캡처 또는 제공 trace 분석. 캐시 삭제·관리 경로 변경은 하지 않음. [실행 안내](LINUX.md)의 필수/선택과 제공 분석/직접 수행 구분을 따른다.
- **모임에 가져올 것:** 본인의 근거에서 고른 출력·풀이와 아직 설명이 막힌 질문. 개인 학습 노트에 한 번 정리하고 원시 로그·pcap은 파일 링크로 연결해도 된다. 새 제출 양식은 만들지 않는다.

<span id="personal-notes"></span>

### 개인 공부를 정리할 때

기존 개인 학습 노트에 아래 세 가지를 중심으로 정리한다. 모임 전에는 현재 답과 막힌 지점을 남기고, 모임 뒤에는 확인한 차이와 보충할 부분을 고친다. 정해진 개수·분량이나 새 제출물은 없다.

- **주요 질문과 내 답:** [공동 질문](WORKSHEET.md)과 아래 확인 질문에 먼저 내 말로 답한다. 이유·성립 조건과 공식 자료·실습 근거를 연결하고, [분리 해설](ANSWERS.md)은 시도 뒤에 비교한다.
- **헷갈리는 개념 비교:** [핵심 설명](ESSENTIALS.md)에서 최종 목적지 IP와 다음 홉 MAC의 역할·관찰 위치·성공 범위를 비교한다. 두 개념이 다른 결론을 내는 예를 들어 본다.
- **이번 주 꼭 기억하고 이해할 핵심 개념:** [핵심 정리](ESSENTIALS.md)의 W03-K1~K3를 길잡이로 용어·역할·동작 순서를 추린다. 필요한 공식은 식·단위·성립 조건과 적용 이유를 함께 설명한다. 예제 주소·일회성 출력값을 외우는 목록으로 만들지 않는다.

실습 근거는 해당 질문·개념 아래에 예상·실제 관찰·수정한 이해와 함께 연결한다. 제공 분석과 직접 실행을 구별하고 관찰하지 않은 결과는 채우지 않는다. 입력 화면을 썼다면 이동 전에 답안을 내려받는다. [전체 개념 색인의 정리 방법](../CONCEPT_INDEX.md#personal-study)은 다른 주차에도 같은 방식으로 쓸 수 있다.

### 오프라인에서 확인할 질문

1. **중심 질문:** 다른 망의 HTTP 서버로 보낼 때 첫 프레임의 목적 MAC은 누구의 것일까?
2. **조건을 바꾸면:** ICMP는 보이는데 새 ARP가 없다면 무엇을 조회하고 어떤 결론을 유보할까?
3. **앞 개념을 다시 쓰면:** 2주 같은 /24 계산, 직접 연결 경로, HTTP 응답은 각각 무엇을 증명할까?

중심 질문을 먼저 설명하고 나머지는 짧은 후속 질문으로 사용한다. [분리 해설](ANSWERS.md)과 실제 근거를 대조하되 답을 본 시도와 독립 설명을 구별한다. 개인 공부에서 마친 정상 실습을 전부 반복하지 않고, 막힌 항목과 한 조건 변경·복구를 각자 확인한다.

## 이번 주 완료 기준과 근거 보관

각자 목적지 IP·선택 인터페이스·다음 홉 IP·알 수 있는 MAC을 표시한 그림을 남긴다. 실제 `ip route get`과 `ip neigh`를 판단 근거로 쓰고, 허용 대상 ping과 ARP/ICMP 직접 관찰 또는 [설명용 trace](../../labs/week-03/sample-trace.txt) 분석을 연결한다. 모르는 MAC은 추정해서 채우지 않는다.

캐시 때문에 새 ARP 요청이 없을 수 있음, ping 실패만으로 HTTP 서버 중지를 단정할 수 없음, loopback은 Ethernet ARP 관찰 대상이 아님을 자기 말로 설명한다. 자신의 경로·이웃을 다시 읽거나 제공 trace를 도움 없이 재분석한다.

명령·출력·패킷은 개인 파일이나 노트에 한 번 보관하고 함께 설명할 때 필요한 근거를 보여 준다. [개인 실습 메모](../../labs/week-03/PERSONAL_RECORD.md)는 필요할 때 참고한다. 직접 실행·시연·제공 분석을 구분하고, 조회·요청을 실행하지 못했다면 직접 수행 보충을 남긴다. 입력 화면을 사용했다면 이동 전에 내려받아 파일을 확인한다.

## 기존 인스턴스를 사용하는 조건

이미 준비된 Linux 인스턴스를 사용한다. 본인의 접속·도구·권한·허용 대상과 통신 조건을 먼저 확인한다. 기본 실험은 NIC·주소·경로·정책·이웃 캐시를 변경하지 않는다. 대상이나 캡처 권한이 없으면 [실행 절차의 대안](../../labs/week-03/LINUX.md)을 따른다.
