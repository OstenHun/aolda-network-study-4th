# 3주차 진행자 안내 — LAN의 다음 상대

요약: 두 번의 60분 모임을 제안한다. 조회 한 묶음과 짧은 ARP/ICMP 관찰 두 실험에 집중하고, 환경이 막히면 가상 패킷 예제로 개념 학습을 이어간다.

## 핵심 개념과 질문 연결

[핵심 3·혼동 2·개발 사례 1](ESSENTIALS.md)을 읽기 마지막 5분에 사용한다. 공통 질문 하나에 개발 사례의 설명 → 조건을 바꾼 질문 → 원인을 좁히는 질문을 연결하고 추가 기록 과제로 만들지 않는다. 답은 [분리 해설](ANSWERS.md#개발-질문-해설)로 확인한다. 다음 주에 다시 물을 질문: “게이트웨이의 MAC이 보이는데도 IP 목적지는 원격 서버로 남을 수 있는 이유는?”

## 시작 전 준비

아래 시간표는 개념 학습과 실습을 각 60분으로 나눌 때의 예시다. 준비 상태와 학습 속도에 맞춰 조정한다.

- [ ] 허용된 Linux VM 접속과 `ip`·`ping`·`tcpdump`·`timeout`을 확인한다. 설치·권한 변경은 기본 실습이 아니다.
- [ ] 허용할 IPv4 대상과 범위를 확인한다. 다른 참가자 VM은 이미 존재하고 같은 네트워크이며 양측 권한이 확인된 경우에만 쓴다.
- [ ] `ip -4 route get TARGET`의 `dev`·`via`와 `ip -o link show dev IFACE`의 `link/ether`를 확인한다. `lo`·비 Ethernet이면 직접 ARP 절차를 요구하지 않는다.
- [ ] 제한된 필터와 `sudo -n` 캡처 권한을 사전 확인한다. 권한이 없으면 [가상 패킷 예제](../../labs/week-03/sample-trace.txt)를 쓴다.
- [ ] 공유할 기록에서 실제 주소·호스트명·계정과 비밀정보를 가렸는지 확인한다.

[실행 절차](../../labs/week-03/LINUX.md)의 중단 조건과 권한 경계를 먼저 확인한다. 예제의 결과를 본인 환경의 관찰로 기록하지 않는다.

## 사전 공동학습 60분 — 세 질문을 함께 설명

| 시간 | 진행·질문 | 개인 증거 |
| --- | --- | --- |
| 0~8분 | 2주차 같은 망·게이트웨이와 1주차 `lo`를 연결. 오늘 세 질문 소개 | 각자 첫 생각 |
| 8~20분 | LAN/WAN·장비·Ethernet 프레임을 작은 그림으로 설명 | VM NIC와 개인 PC를 분리한 그림 |
| 20~45분 | [팀 활동](WORKSHEET.md)의 세 질문을 각각 각자 생각 1분 → 설명자 교대 2분 → 동료 질문 3분 → 교재·가상 패킷 예제 근거 확인 2분으로 진행 | 팀 기록 세 항목의 초안·근거 위치 |
| 45~55분 | 같은 링크 A01~A04와 게이트웨이 B01~B04를 다시 비교. 각자 다음 상대 그림을 고친다 | 개인 예상과 수정한 그림 |
| 55~60분 | 승인 대상·VM·도구·캡처 권한을 점검 | 환경 상태와 막힌 항목 |

사전 모임은 함께 설명하고 질문한 뒤 텍스트 근거로 확인한다. 가상 패킷 예제를 실제 아올다 관찰로 쓰지 않는다. 장비 역할은 교육용 모형이며 현재 아올다의 물리/가상망 구성을 확정하지 않는다.

## 오프라인 실습 60분 — 필수 두 실험

| 시간 | 활동과 전환 기준 | 개인 증거 |
| --- | --- | --- |
| 0~6분 | 승인 대상·실습 NIC·직접 실행 가능 여부 확인. 대상이 없으면 가상 패킷 예제로 전환 | 환경·출처를 개인 기록에 표시 |
| 6~17분 | 실험 A: 각자 예상 뒤 주소·경로·이웃 조회. `dev`·`via`·`link/ether` 확인 | 상세 명령·출력은 개인 기록/원파일 |
| 17~30분 | 실험 B: 각자 예상 뒤 12초/16패킷 이내 캡처와 승인 대상 ping 2회, 전후 이웃 비교 | 상세 필터·시간·패킷/0개는 개인 기록/원파일 |
| 30~45분 | [팀 활동](WORKSHEET.md)의 세 질문을 이번 근거로 재확인. 질문당 생각 30초 → 설명 1분 30초 → 동료 질문 2분 → 근거 확인 1분 | 팀 기록은 질문·근거 위치, 바뀐 설명, 남은 질문 세 항목만 |
| 45~55분 | 짝·3인 소그룹에서 각자 2분 독립 설명. 각자 경로·이웃을 다시 조회하거나 같은 제공된 패킷 예제를 도움 없이 재분석하고 확인자를 남긴다 | 본인의 재현·2분 설명·짝의 근거 질문. 원본 출력은 개인 기록 |
| 55~60분 | 각자 이해한 점·헷갈리는 점 한 줄, 저장 파일 확인·미완료 보충 | 개인 마무리와 보충 상태 |

도구·승인·권한 문제 해결이 5분을 넘으면 제공된 패킷 예제로 이동한다. 제한된 캡처가 실패해도 `ip` 조회는 가능하면 기록한다. 원본 출력과 예상·패킷 분석, 스스로 다시 확인한 결과는 [개인 기록지](../../labs/week-03/PERSONAL_RECORD.md)에 두고 팀 활동지에는 근거 위치만 남긴다. 진행자가 설명한 결과를 참가자별 완료로 집계하지 않는다. 주소·경로·방화벽·SSH 관리·이웃 캐시 삭제는 수행하지 않는다.

## 판정과 다음 질문

필수 실습을 마쳤는지 **각자** 확인한다. A의 조회 결과, B의 허용 대상 ping·캡처 결과나 실행하지 못한 이유, 목적지 IP와 다음 홉 MAC을 표시한 그림을 살펴본다. 질문에 답한 설명과 스스로 다시 확인한 결과도 함께 본다. 가상 패킷 예제만 분석한 사람은 개념 분석 완료와 직접 실행 미완료를 따로 기록한다. `INCOMPLETE`·`FAILED`·행 없음·ARP 미관찰은 실패를 숨길 이유가 아니다. ping 응답만으로 HTTP 서비스 성공을 결론 내리지 않는지 확인한다. 다음 주 TCP/UDP에서 “IP 패킷이 도착한 뒤 어느 프로그램으로 가는가?”로 연결한다.
