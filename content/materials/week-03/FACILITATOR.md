# 3주차 진행자 안내 — LAN의 다음 상대

요약: 개인 공부에서 개념·문제·실습을 준비하고 오프라인 한 번에서 설명·조건 변경·직접 수행을 확인한다. 준비·복구와 제공 분석의 경계를 지키며 막힌 필수 항목을 보충한다.

## 핵심 개념과 질문 연결

[핵심 3·혼동 2·개발 사례 1](ESSENTIALS.md)을 읽기 마지막 5분에 사용한다. 공통 질문 하나에 개발 사례의 설명 → 조건을 바꾼 질문 → 원인을 좁히는 질문을 연결하고 추가 기록 과제로 만들지 않는다. 답은 [분리 해설](ANSWERS.md#개발-질문-해설)로 확인한다. 다음 주에 다시 물을 질문: “게이트웨이의 MAC이 보이는데도 IP 목적지는 원격 서버로 남을 수 있는 이유는?”

## 시작 전 준비

개인 공부에서 개념과 실습을 먼저 시도하고, 오프라인에서는 준비 상태와 실제로 막힌 부분을 확인한다.

- [ ] 허용된 Linux VM 접속과 `ip`·`ping`·`tcpdump`·`timeout`을 확인한다. 설치·권한 변경은 기본 실습이 아니다.
- [ ] 허용할 IPv4 대상과 범위를 확인한다. 다른 참가자 VM은 이미 존재하고 같은 네트워크이며 양측 권한이 확인된 경우에만 쓴다.
- [ ] `ip -4 route get TARGET`의 `dev`·`via`와 `ip -o link show dev IFACE`의 `link/ether`를 확인한다. `lo`·비 Ethernet이면 직접 ARP 절차를 요구하지 않는다.
- [ ] 제한된 필터와 `sudo -n` 캡처 권한을 사전 확인한다. 캡처 권한이 없으면 패킷 분석에만 [가상 패킷 예제](../../labs/week-03/sample-trace.txt)를 쓰고 가능한 조회·ping은 직접 수행한다.
- [ ] 공유할 기록에서 실제 주소·호스트명·계정과 비밀정보를 가렸는지 확인한다.

[실행 절차](../../labs/week-03/LINUX.md)의 중단 조건과 권한 경계를 먼저 확인한다. 예제의 결과를 본인 환경의 관찰로 기록하지 않는다.

## 한 주의 개인 공부와 오프라인 확인

개인 준비는 [학습 홈의 정리 안내](README.md#personal-notes)에 따라 주요 질문과 내 답·헷갈리는 개념 비교·꼭 기억하고 이해할 핵심을 살핀다. 노트 분량을 평가하지 않고 이유·조건 변경·관련 실습 근거로 확인한다. 모임 뒤에는 틀린 설명과 남은 보충만 기존 개인 노트에서 고치며 중복 제출을 요구하지 않는다.

[학습 홈의 개인 공부 범위와 세 확인 질문](README.md#weekly-study)을 오프라인 모임 전까지 준비한다. 모임은 그 주 학습을 마무리하고 남은 보충을 정하는 자리다. 개념·공식 지정 절·복습과 준비된 실습의 정상→변경→복구는 개인 공부에서 시도한다. 모임 전 완성 답안·발표 자료를 요구하지 않으며 막힌 질문과 본인 근거를 가져오게 한다. 진단 원인을 가리는 과제는 정상 기준과 도구까지만 준비한다.

오프라인은 한 번의 모임에서 **설명 → 새 조건 → 본인 실습/분석 확인 → 보충 결정**으로 진행한다. 아래 60분은 시간 배분 예시이며 모임 길이나 추가 회차를 확정하는 표가 아니다.

| 시간 예시 | 진행자가 확인할 것 |
| --- | --- |
| 0~10분 | 개인 공부에서 막힌 질문과 2~4학습 단위 전 개념 하나를 골라 근거로 설명 |
| 10~25분 | 학습 홈의 중심 질문 → 조건 변경. 소그룹에서 설명자/확인자 교대 |
| 25~50분 | A 자기 주소/경로/이웃 조회와 B 승인 대상의 제한된 ping. 이미 수행했다면 근거를 보고 다른 한 조건의 판단·변경·복구 확인 |
| 50~60분 | 정상 복구·받은 도움·미완료 구분, 개인 학습 노트에 필요한 보충과 다음 질문 연결 |

개인 학습 시간을 고정된 2~3시간으로 제한하지 않는다. 필수 범위를 먼저 공부하고 실제 막힘에 따라 시간을 배분한다. 주차를 미리 분할하거나 필수 기준을 낮추지 않으며, 개인 공부 후에도 해결되지 않는 항목만 보충한다. C04/C08/C12/C16은 해당 주 기존 설명·실습을 대체하고 점검을 별도로 더하지 않는다. 한 사람의 답·팀 합의·파일 제출은 개인 이해/직접 수행의 증거가 아니다.

캡처 도구·권한만 없으면 직접 조회·제한된 ping을 먼저 확인한다. 캡처 미실행과 실제 0패킷을 구분한다. 주소·경로·방화벽·SSH 관리·이웃 캐시 삭제는 수행하지 않는다. 제공 trace 분석과 본인 실행을 나누어 개인 학습 노트에 남긴다.

## 판정과 다음 질문

필수 실습을 마쳤는지 **각자** 확인한다. A의 조회 결과, B의 허용 대상 ping 결과와 직접 캡처 또는 제공 trace 분석, 실행하지 못한 단계의 이유, 목적지 IP와 다음 홉 MAC을 표시한 그림을 살펴본다. 질문에 답한 설명과 스스로 다시 확인한 결과도 함께 본다. 조회·ping 없이 제공 예제만 분석했다면 직접 수행은 보충으로 남긴다. 직접 조회·ping과 제공 패킷 분석을 마쳤다면 직접 캡처를 추가 필수로 요구하지 않는다. `INCOMPLETE`·`FAILED`·행 없음·ARP 미관찰은 실패를 숨길 이유가 아니다. ping 응답만으로 HTTP 서비스 성공을 결론 내리지 않는지 확인한다. 다음 주 TCP/UDP에서 “IP 패킷이 도착한 뒤 어느 프로그램으로 가는가?”로 연결한다.
