# 3주차 핵심 정리 — 다음 홉·ARP·서비스 확인

요약: 최종 IP와 링크의 다음 상대, ARP 캐시, ICMP와 HTTP의 관찰 범위를 세 문장으로 정리한다. 두 혼동과 개발 사례를 기존 교재·실습·분리 해설에 연결한다.

- 사용법: 개념 읽기의 마지막 5분에 사용하고, 공통 질문 하나를 이 사례와 연결한다. 별도 발표·활동지·필수 기록은 추가하지 않는다. 기존 실습 완료 기준은 유지한다.

## 꼭 기억할 개념 세 개

### W03-K1 · 최종 IP와 링크에서 보낼 MAC은 다를 수 있다

**기억 문장:** 단순 Ethernet·IPv4 라우팅 모형에서 IP 목적지는 최종 대상이고, 프레임 목적 MAC은 이번 링크의 다음 상대다.

원격 목적지로 가는 `via` 경로라면 첫 링크에서 보통 게이트웨이의 MAC이 필요하다. NAT 없는 모형이며 가상망·터널의 내부 동작까지 이 출력만으로 단정하지 않는다. [다음 홉 교재](topics/03-next-hop.md), [ip-route(8)](https://man7.org/linux/man-pages/man8/ip-route.8.html).

### W03-K2 · ARP는 IPv4 다음 상대의 링크 주소를 찾는다

**기억 문장:** Ethernet의 IPv4 통신에서 필요한 다음 상대의 MAC 매핑이 없으면 ARP를 사용할 수 있으며 캐시가 있으면 새 요청이 안 보일 수 있다.

ARP 브로드캐스트는 해당 링크 범위에서 전달된다. 원격 서버의 MAC을 라우터 너머로 ARP 조회하는 것으로 설명하지 않는다. `STALE`은 서버가 중지됐다는 뜻은 아니며, IPv6 이웃 탐색을 ARP와 같게 취급하지 않는다. [ARP 교재](topics/04-arp.md), [RFC 826](https://www.rfc-editor.org/rfc/rfc826.html), [ip-neighbour(8)](https://man7.org/linux/man-pages/man8/ip-neighbour.8.html).

### W03-K3 · 확인 도구마다 묻는 질문이 다르다

**기억 문장:** ping의 ICMP 반응·TCP 연결·HTTP 상태는 각각 따로 관찰해야 한다.

ping 성공은 HTTP 서비스 정상을 보장하지 않는다. Echo 무응답과 HTTP 응답이 함께 관찰돼도 모순이 아니다. ping의 RTT를 API 전체 응답 시간으로 쓰지 않는다. [ICMP 교재](topics/05-icmp.md), [ping(8)](https://man7.org/linux/man-pages/man8/ping.8.html).

## 헷갈리는 부분 두 가지

| 자주 섞는 설명 | 구별하는 방법 |
| --- | --- |
| 프레임에 게이트웨이 MAC이 있으니 IP 목적지도 게이트웨이다 | NAT 없는 원격 전달 모형에서 최종 IP와 첫 링크 목적 MAC의 역할을 나누어 그린다 |
| ping이 안 되거나 ARP가 안 보이면 서버가 죽었다 | ICMP 정책·경로·이웃 캐시·관찰 인터페이스를 확인한다. HTTP 서버 상태와는 별도 증거다 |

## 개발 상황으로 설명하기

**출처 구분: 스터디 자체 문항.** 아래는 개념 확인용 사례이며 특정 기업의 실제 출제 문제·빈출 문항을 뜻하지 않는다.

같은 시각에 허가된 목적지의 ping은 무응답, 같은 호스트의 평문 HTTP 요청은 404 응답이다. 경로는 `via`이고 첫 이웃은 `REACHABLE`, 해당 캡처 구간에 새 ARP는 없다. 모두 설명을 위해 정한 조건이며 실제 측정 결과가 아니다.

1. **W03-D1 · 설명:** HTTP·ICMP·ARP 각각에서 관찰한 사실과 아직 모르는 것은?
2. **W03-D2 · 조건 변경:** 이웃 상태가 `STALE`로 바뀌면 HTTP 서버 장애로 판정할 수 있을까?
3. **W03-D3 · 진단:** 404가 의도한 원 서버에서 나온 것인지, ARP가 안 보인 이유가 캐시인지 무엇으로 확인할까?

[함께 찾을 질문](WORKSHEET.md)의 중심 질문이나 필요한 보조 질문에 이어서 묻는다. 먼저 말하거나 짧게 적은 뒤 [개발 질문 해설](ANSWERS.md#개발-질문-해설)을 연다. 해설을 읽는 것과 직접 실행하거나 스스로 설명하는 것은 구분한다.
