핵심 개념과 질문 연결

핵심 3·혼동 2·개발 사례 1을 읽기 마지막 5분에 사용한다. 공통 질문 하나에 개발 사례의 설명 → 조건을 바꾼 질문 → 원인을 좁히는 질문을 연결하고 추가 기록 과제로 만들지 않는다. 답은 분리 해설로 확인한다. 다음 주에 다시 물을 질문: “게이트웨이의 MAC이 보이는데도 IP 목적지는 원격 서버로 남을 수 있는 이유는?”

시작 전 준비

아래 시간표는 개념 학습과 실습을 각 60분으로 나눌 때의 예시다. 준비 상태와 학습 속도에 맞춰 조정한다.

  • 허용된 Linux VM 접속과 ip·ping·tcpdump·timeout을 확인한다. 설치·권한 변경은 기본 실습이 아니다.
  • 허용할 IPv4 대상과 범위를 확인한다. 다른 참가자 VM은 이미 존재하고 같은 네트워크이며 양측 권한이 확인된 경우에만 쓴다.
  • ip -4 route get TARGET의 dev·via와 ip -o link show dev IFACE의 link/ether를 확인한다. lo·비 Ethernet이면 직접 ARP 절차를 요구하지 않는다.
  • 제한된 필터와 sudo -n 캡처 권한을 사전 확인한다. 권한이 없으면 가상 패킷 예제를 쓴다.
  • 공유할 기록에서 실제 주소·호스트명·계정과 비밀정보를 가렸는지 확인한다.

실행 절차의 중단 조건과 권한 경계를 먼저 확인한다. 예제의 결과를 본인 환경의 관찰로 기록하지 않는다.

사전 공동학습 60분 — 중심 질문을 함께 탐구

시간 진행·질문 확인할 것
0~10분 2주차 경로와 1주차 lo를 짧게 복습하고 중심 질문을 확인 막히는 앞 개념과 필요한 교재
10~30분 LAN·MAC → 다음 홉 → ARP에서 필요한 절과 RFC 826의 Packet Generation·An Example을 함께 탐색 자료의 절·주장·해당 조건
30~45분 한 명이 목적지 IP와 링크의 다음 상대를 그림으로 설명하고 다른 사람은 근거를 질문 프레임·패킷, PC·VM의 구분
45~55분 같은 링크/게이트웨이 사례를 비교. 필요하면 캐시·ping의 보조 질문과 RFC 792를 선택 바꾼 조건과 예상, 실제 확인 방법
55~60분 허용 대상·VM·도구·캡처 권한 점검 실습에 필요한 환경과 막힌 항목

시간은 제안이며 공동 탐색이 더 필요하면 보조 질문을 줄인다. 공식 절은 출처, 탐색이 막힐 때는 주제별 한국어 교재를 사용한다. 한 명의 설명 뒤 다른 사람이 조건을 바꾸어 묻고 설명자는 질문·회차마다 교대한다. 가상 패킷 예제를 실제 아올다 관찰로 쓰지 않는다. 장비 역할은 교육용 모형이며 현재 아올다의 물리/가상망 구성을 확정하지 않는다.

오프라인 실습 60분 — 필수 두 실험

시간 활동과 전환 기준 개인 증거
0~6분 승인 대상·실습 NIC·직접 실행 가능 여부 확인. 대상이 없으면 가상 패킷 예제로 전환 환경·출처를 개인 기록에 표시
6~17분 실험 A: 각자 예상 뒤 주소·경로·이웃 조회. dev·via·link/ether 확인 상세 명령·출력은 개인 기록/원파일
17~30분 실험 B: 각자 예상 뒤 12초/16패킷 이내 캡처와 승인 대상 ping 2회, 전후 이웃 비교 상세 필터·시간·패킷/0개는 개인 기록/원파일
30~45분 중심 질문을 이번 출력·패킷 또는 제공 trace와 대조하고 예상과 비교 IP 목적지와 다음 홉 MAC의 구분·수정한 설명
45~55분 짝·3인 소그룹에서 각자 2분 독립 설명. 각자 경로·이웃을 다시 조회하거나 같은 제공된 패킷 예제를 도움 없이 재분석하고 확인자를 남긴다 본인의 재현·2분 설명·짝의 근거 질문. 원본 출력은 개인 기록
55~60분 실험 정리·파일 보관·다음 확인 질문과 미완료 보충 점검 직접 수행·제공 분석·보충 상태

도구·승인·권한 문제 해결이 5분을 넘으면 제공된 패킷 예제로 이동한다. 제한된 캡처가 실패해도 ip 조회는 가능하면 기록한다. 원본 출력과 예상·패킷 분석, 스스로 다시 확인한 결과는 개인 실습 메모 또는 별도 파일에 한 번 보관한다. 실습 메모 양식은 참고용이며 자유로운 노트를 사용해도 된다. 진행자가 설명한 결과를 참가자별 완료로 집계하지 않는다. 주소·경로·방화벽·SSH 관리·이웃 캐시 삭제는 수행하지 않는다.

판정과 다음 질문

필수 실습을 마쳤는지 각자 확인한다. A의 조회 결과, B의 허용 대상 ping·캡처 결과나 실행하지 못한 이유, 목적지 IP와 다음 홉 MAC을 표시한 그림을 살펴본다. 질문에 답한 설명과 스스로 다시 확인한 결과도 함께 본다. 가상 패킷 예제만 분석한 사람은 개념 분석 완료와 직접 실행 미완료를 따로 기록한다. INCOMPLETE·FAILED·행 없음·ARP 미관찰은 실패를 숨길 이유가 아니다. ping 응답만으로 HTTP 서비스 성공을 결론 내리지 않는지 확인한다. 다음 주 TCP/UDP에서 “IP 패킷이 도착한 뒤 어느 프로그램으로 가는가?”로 연결한다.
