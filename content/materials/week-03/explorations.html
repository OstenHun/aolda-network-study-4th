LAN · MAC · ARP · ICMP

3주차 선택 탐구 — 다음 상대를 더 정확히 설명하기

필수 조회·제한된 관찰을 마친 뒤 이미 얻은 근거에서 캐시·경로·ICMP의 한계를 비교한다. 선택 과제는 공통 완료 조건을 늘리지 않는다.

1. 복습 진단2. LAN·MAC3. 다음 홉4. ARP·캐시5. ICMP·ping

선택 기준

팀 활동의 필수 A/B와 독립 설명 뒤 한 과제만 고른다. 실제 조회와 합성 trace는 출처를 구분한다. 새 주소·경로·방화벽·SSH 설정 변경, 이웃 캐시 일괄 삭제, 허가되지 않은 ping은 하지 않는다.

A. 이웃 상태의 시간 차이 — 10분

이미 허용된 대상에 대한 전후 ip -4 neigh show dev IFACE 행을 비교한다. REACHABLE·STALE·INCOMPLETE·FAILED 또는 행 없음 중 실제로 본 것만 적는다. ARP를 못 봤다면 “캐시 때문”을 확정하지 말고 캡처 시작 시각과 필터, 다른 트래픽 가능성을 따진다. 추가 ping이나 캐시 flush 없이 기존 증거만으로 설명을 고친다.

B. 같은 링크와 게이트웨이 — 10분

합성 trace A03과 B03의 IP 목적지·Ethernet 목적 MAC을 한 표로 비교한다. B03의 게이트웨이 MAC을 198.51.100.8의 MAC으로 오해하면 어떤 설명이 틀리는가? 실제 VM의 route get에서 via가 없거나 있다면 확인된 범위와 미확인 경로를 따로 쓴다. 예제 주소는 ping 대상이 아니다.

C. ping과 HTTP의 다른 질문 — 10분

3주차의 실제 또는 합성 ICMP 결과와 1주차 HTTP 상태를 비교한다. Echo reply가 있어도 웹 서버의 200은 보장되지 않고, Echo reply가 없어도 서버 중지라고 단정할 수 없다. 어떤 명령·서버 로그·패킷이 있어야 각 가설을 구분할지 제안만 한다. 새로운 네트워크 테스트는 허용 범위와 사전 점검 뒤 별도 수행한다.

D. 기존 두 VM을 비교할 수 있다면 — 별도 시간

두 VM이 이미 존재하고 같은 허용 네트워크에 있으며 양측 소유자·접속·ICMP/캡처 권한이 확인된 경우에만 실행 절차를 각 VM에 적용할 수 있다. 각자의 route get·이웃 행과 승인된 상대에게 보낸 제한된 ping 결과를 개별 출처로 기록하고, 누가 누구의 MAC을 학습했는지 비교한다. 같은 네트워크 이름만으로 실제 연결·정책 허용을 단정하지 않는다. 위 조건이 하나라도 미확인이라면 두 VM 통신을 시도하지 않고 합성 trace로만 비교한다. 새 VM 생성이나 보안 규칙 변경은 이 과제에 없다.

격리된 네트워크 네임스페이스에서 캐시 초기화를 비교하는 시연은 추후 실습 후보이며 이번 필수·선택 실행 절차에 포함하지 않는다. 물리망 전체나 다른 VM의 패킷을 본 것으로 기록하지 않는다.
