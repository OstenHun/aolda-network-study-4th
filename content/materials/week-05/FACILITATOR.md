# 5주차 · 진행자 안내

요약: DNS·DHCP를 공동 질문과 두 실습 안에서 설명하도록 돕는다. 지정 공식 절·시간 배치·준비·대안을 제공하며 실제 Linux 수행과 DHCP 제공 분석을 구별한다.

## 시작 전 확인

[학습 홈](README.md) → [공동 질문](WORKSHEET.md) → [교재](CONCEPTS.md) → [실습](LINUX.md)을 실제 순서로 따라간다. 기존 VM 한 대와 셸 두 개, dig·curl·Python 3·ip·ss, 외부 질의/요청 허용 여부, 파일 전달 경로를 확인한다. 새 VM·유료 도메인·권한 서버는 필요하지 않다. 프록시 필수 환경은 직접 연결 비교가 가능한 허가된 대상을 따로 정한다.

같은 VM에서 `host_server.py`를 실행해 200→421→200·Ctrl+C 종료를 확인한다. 포트 점유·잘못된 포트 값·없는 경로의 오류와 정상 복귀도 확인한다. A1의 허가된 이름·URL은 같은 서비스여야 한다. 공개 예제 사이트의 주소·응답·TTL은 고정값으로 배포하지 않는다. 실제 주소·계정·설정 출력은 공개 자료에 넣지 않는다.

## 공식 절에서 함께 찾을 것

| 지정 절 | 찾을 내용 | 막히면 짧게 설명할 것 |
| --- | --- | --- |
| RFC 1034 §4.3.1·§5.3.3 | 재귀 요청·반복 질의·캐시 | 권한 데이터와 대신 찾는 역할을 그림으로 나누기 |
| RFC 1034 §3.2.1 | TTL의 단위·캐시 보관 | 단일 캐시 300−120 계산으로 돌아가기 |
| RFC 2131 §3.1 Figure 3 | 초기 임대의 네 메시지 | OFFER 제안과 ACK 확인, REQUEST 선택 서버 짚기 |
| RFC 2132 §3.3·§3.5·§3.8 | mask·router·DNS 옵션 | 주소 범위·다음 홉·이름 질의를 앞 주차에 대응 |
| curl --resolve | URL 이름을 유지한 주소 지정 | DNS 조회 우회와 Host/TLS 조건 보존 구별 |

원문 전체 필독을 추가하지 않는다. [출처](SOURCES.md)에 공식 URL과 채택 범위가 있다. 질문·가공 trace·해설은 자체 자료이며 기업 기출로 소개하지 않는다.

| 시간 | 기존 활동 안에서 할 일 |
| --- | --- |
| 0~5분 | TCP 전달/HTTP 처리·주소/다음 홉 짧은 복습, 중심 질문 선택 |

| 40~55분 | DHCP 제공 trace·옵션 읽기, 실습 도구/대상 확인 |
| 55~60분 | W05-K1~K3 기억 문장을 다시 설명하고 남은 질문 확인 |

## 실습 60분 제안

| 시간 | 확인할 근거 |
| --- | --- |
| 0~5분 | 정상·변경·복구 예상과 실행 위치 |
| 5~30분 | A1 질의/요청, A2 Host 비교·복구를 각자 직접 실행 |
| 30~45분 | B 설정 조회·DHCP 제공 분석, TTL 작은 계산 |
| 45~55분 | 짝의 출력 필드 설명, 복습 8문항 중 막힌 항목 선택 |
| 55~60분 | 본인 서버 종료·소켓 확인, 개인 근거 한 번 보관 |

실제 학습 속도에 따라 선택 주소 고정·404 비교·추가 캡처·보조 질문을 먼저 줄인다. 필수 직접 수행은 제공 분석으로 완료 표시하지 않고 나눠 보충한다. DHCP는 제공 분석을 필수 완료 근거로 사용할 수 있다. 고정 팀 기록·개인 마무리·추가 발표를 요구하지 않는다.

## 관찰을 과장하지 않기

dig의 `SERVER`가 권한 서버라고 단정하지 않고, 질의 시간만으로 캐시 적중을 확정하지 않는다. HTTP 421·404는 응답이며 연결 자체 실패가 아니다. `--resolve`는 DNS 실험이 아니고 로컬 HTTP 서버는 TLS·지속 연결 실험이 아니다. DHCP 제공 trace는 실제 VM 캡처가 아니다.

임대 해제·네트워크 재시작·공유망 DHCP 서버는 실행하지 않는다. 설정 출처를 모르면 미확인으로 남기고 읽기 전용 도구로 보충한다. 전체 클라우드 O02는 6주차 TLS 신원과 이후 실제 서비스 연결 근거로 이어가며 이번 자료 열람만으로 판정하지 않는다.
