# 5주차 · 이름과 주소 설정은 어디서 올까?

요약: DNS가 이름에서 주소를 찾는 과정과 DHCP가 호스트에 설정을 임대하는 과정을 구별한다. Linux 이름 질의·서비스 요청과 제공 trace를 비교하며 캐시·TTL·주소·경로·DNS 옵션을 설명한다.

<span id="weekly-study"></span>

## 개인 공부와 오프라인 확인

오프라인 모임 전까지 아래 범위를 공부하고 실습을 시도한다. 모임은 그 주의 학습을 마무리하는 자리로, 막힌 이유와 조건을 바꾼 결과를 설명하고 남은 보충을 정한다. [공동 질문](WORKSHEET.md)은 개인 공부의 출발점으로 쓰고, 모임에서는 근거를 비교한다. 별도 사전 모임이나 발표 자료는 필요하지 않다.

- **개념·문제:** 재귀/권한 DNS·A/AAAA·응답 상태, 캐시/TTL, DHCPv4 DORA·임대·마스크/라우터/DNS 옵션. [교재](CONCEPTS.md) → [공식 지정 절](SOURCES.md) → [복습](REVIEW.md) 순서로 읽고, 먼저 답한 뒤 [해설](ANSWERS.md)과 비교한다.
- **실습·분석:** 실습 A 질의와 요청·Host 조건 변경/복구, B 실제 주소/경로/DNS 설정 조회와 DHCP 제공 trace 분석. 실제 임대 해제·서버 구축은 하지 않음. [실행 안내](LINUX.md)의 필수/선택과 제공 분석/직접 수행 구분을 따른다.
- **모임에 가져올 것:** 본인의 근거에서 고른 출력·풀이와 아직 설명이 막힌 질문. 개인 학습 노트에 한 번 정리하고 원시 로그·pcap은 파일 링크로 연결해도 된다. 새 제출 양식은 만들지 않는다.

<span id="personal-notes"></span>

### 개인 공부를 정리할 때

기존 개인 학습 노트에 아래 세 가지를 중심으로 정리한다. 모임 전에는 현재 답과 막힌 지점을 남기고, 모임 뒤에는 확인한 차이와 보충할 부분을 고친다. 정해진 개수·분량이나 새 제출물은 없다.

- **주요 질문과 내 답:** [공동 질문](WORKSHEET.md)과 아래 확인 질문에 먼저 내 말로 답한다. 이유·성립 조건과 공식 자료·실습 근거를 연결하고, [분리 해설](ANSWERS.md)은 시도 뒤에 비교한다.
- **헷갈리는 개념 비교:** [핵심 설명](CONCEPTS.md)에서 DNS 이름 해석과 서비스 성공의 역할·관찰 위치·성공 범위를 비교한다. 두 개념이 다른 결론을 내는 예를 들어 본다.
- **이번 주 꼭 기억하고 이해할 핵심 개념:** [핵심 정리](CONCEPTS.md)의 W05-K1~K3를 길잡이로 용어·역할·동작 순서를 추린다. 필요한 공식은 식·단위·성립 조건과 적용 이유를 함께 설명한다. 예제 주소·일회성 출력값을 외우는 목록으로 만들지 않는다.

실습 근거는 해당 질문·개념 아래에 예상·실제 관찰·수정한 이해와 함께 연결한다. 제공 분석과 직접 실행을 구별하고 관찰하지 않은 결과는 채우지 않는다. 입력 화면을 썼다면 이동 전에 답안을 내려받는다. [전체 개념 색인의 정리 방법](../CONCEPT_INDEX.md#personal-study)은 다른 주차에도 같은 방식으로 쓸 수 있다.

### 오프라인에서 확인할 질문

1. **중심 질문:** A 응답을 얻었는데 HTTP가 시간 초과라면 무엇이 확인됐고 무엇은 남았을까?
2. **조건을 바꾸면:** TTL300초 응답 뒤 120초가 지났다면 기존 캐시와 새 리졸버의 답이 달라도 되는가?
3. **앞 개념을 다시 쓰면:** 4주 TCP ACK를 받았다는 사실로 앱 처리 성공을 확정할 수 있을까?

중심 질문을 먼저 설명하고 나머지는 짧은 후속 질문으로 사용한다. [분리 해설](ANSWERS.md)과 실제 근거를 대조하되 답을 본 시도와 독립 설명을 구별한다. 개인 공부에서 마친 정상 실습을 전부 반복하지 않고, 막힌 항목과 한 조건 변경·복구를 각자 확인한다.

## 함께 풀 질문

**이름에서 IP를 찾았는데 왜 웹 요청은 실패할까?** [공동 질문](WORKSHEET.md)에서 공식 절을 함께 읽고 한 명이 근거로 설명한다. 다른 사람은 이름·포트·캐시 조건 하나를 바꾸어 묻는다. 다음 질문에는 설명자를 바꾼다.

먼저 “다른 망의 서버로 보낼 때 목적지 IP와 다음 홉은 어떻게 다른가?”, “TCP 연결 성공은 HTTP 200을 뜻하는가?”를 짧게 설명한다. 막히면 [2주차 주소와 경로](../week-02/ESSENTIALS.md), [3주차 다음 홉](../week-03/ESSENTIALS.md), [4주차 전달과 처리](../week-04/CONCEPTS.md)로 돌아간다.

필수 실습은 A 이름 질의·서비스 요청 비교와 B 주소 설정 조회·제공 DHCP trace 분석이다. A의 Linux 직접 수행이 막히면 제공 출력으로 개념을 공부하고 직접 수행은 나중에 보충한다. DHCP는 제공 분석으로 확인할 수 있다. 접속 중인 VM의 임대를 해제하거나 공유망에 DHCP 서버를 띄우지 않는다.

정해진 팀 기록·개인 마무리 양식은 없다. 실습 파일은 필요한 위치에 보관하고 개인 학습 노트의 관련 질문에서 연결한다. 제공 예제를 본인 실측으로 쓰지 않는다.

## 기억하고 다시 설명하기

[W05-K1~K3](CONCEPTS.md#dns-roles)는 DNS 역할·캐시·DHCP 설정을 찾는 표지다. [전체 개념 색인](../CONCEPT_INDEX.md)에서 다른 주차와 연결한다. 개발 질문 W05-D1~D3는 설명 → 조건 변경 → 다음 관찰 순서이며 답은 분리 해설에 있다.

다음 주에는 “같은 IP로 HTTPS를 요청했는데 왜 이름을 유지해야 할까?”를 다시 묻는다. [6주차 HTTP](../week-06/CONCEPTS.md)에서 HTTP 메시지와 TLS 신원 확인으로 이어간다. 권한 DNS·DHCP 서버 구축, 부정 응답 캐시 심화는 선택이다.
