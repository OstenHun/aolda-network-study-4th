# 7주차 · 다른 망으로 보내는 경로

요약: 목적지에 따라 경로를 고르고 다음 홉으로 전달하는 과정을 익힌다. 자기 Linux에서 두 목적지를 조회하고 격리 시뮬레이터의 반환 경로 하나를 지운 뒤 복구한다. TTL과 traceroute의 관찰 한계도 구별한다.

## 이번 주에 설명할 질문

**이름과 인증서가 맞는데 TCP 연결조차 안 된다면, 요청이 가는 길과 응답이 돌아오는 길에서 무엇을 확인할까?** [함께 찾을 질문](WORKSHEET.md)에서 공식 절을 함께 찾고 한 사람이 설명한다. 다른 사람은 경로 한 항목을 바꿔 예상과 결과를 비교한다. 질문·회차마다 설명자를 교대한다.

## 앞선 개념으로 준비하기

[2주차 주소 범위](../week-02/CONCEPTS.md)에서 `/24`에 포함되는 주소를, [3주차](../week-03/topics/03-next-hop.md)에서 최종 목적지 IP와 다음 홉·ARP의 관계를 짧게 설명한다. [4주차 TCP](../week-04/CONCEPTS.md)의 연결과 앱 처리, [5주차 DNS](../week-05/CONCEPTS.md)의 이름 해석, [6주차 TLS](../week-06/CONCEPTS.md)의 서버 신원을 경로 도달성과 구별한다. 막히는 개념만 해당 교재로 돌아간다.

## 필수와 선택

필수 A는 **자기 Linux에서 두 목적지의 경로를 조회**하고 선택된 인터페이스·다음 홉·출발 주소를 설명하는 것이다. 상태는 바꾸지 않는다. 필수 B는 **제공된 두 라우터 시뮬레이터를 각자 실행해 정상→정적 경로 한 항목 삭제→왕복 결과 비교→복구**하는 것이다. Python만 있으면 개인 PC에서도 실행할 수 있다. 실제 운영체제 경로표나 네트워크에 영향을 주지 않는 교육 모형이며 Linux 패킷 실측과는 다르다.

경로표 계산·제공 traceroute 기록 분석과 TTL 설명도 필수다. 실제 traceroute 요청, 독립 장비 구성, 메트릭·정책 라우팅·다중 경로는 선택이다. 도구가 준비되지 않았다면 제공 예제를 분석하고 직접 조회/변경은 보충한다. SSH 관리 경로·공용 라우터·실제 기본 경로는 바꾸지 않는다.

## 무엇을 근거로 설명할까

두 목적지의 경로 출력, 선택한 접두사의 주소 범위, 시뮬레이터의 변경 전후 경로표와 왕복 결과를 사용한다. 반환 경로 그림을 그려 어느 장비가 어떤 목적지로 조회하는지 짚는다. 제공 기록을 읽는 것과 본인이 바꿔 실행하는 것을 나눈다. 상세 출력은 개인 파일에 한 번 보관하며 고정 팀 기록·개인 마무리는 없다. [개념 색인](../CONCEPT_INDEX.md)에서 W07-K1~K3을 다시 찾는다.
