# 7주차 · 다른 망으로 보내는 경로

요약: 목적지별 경로·다음 홉·왕복 전달을 익힌다. 기존 조회·모형 실습을 유지하며 준비된 실제 Linux에서 반환 경로 삭제와 링크 단절·복구를 비교한다. 혼자서도 수행하고 함께할 때는 각자의 근거를 대조한다.

<span id="weekly-study"></span>

## 개인 공부와 오프라인 확인

오프라인 모임 전까지 아래 범위를 공부하고 실습을 시도한다. 모임은 그 주의 학습을 마무리하는 자리로, 막힌 이유와 조건을 바꾼 결과를 설명하고 남은 보충을 정한다. [공동 질문](WORKSHEET.md)은 개인 공부의 출발점으로 쓰고, 모임에서는 근거를 비교한다. 별도 사전 모임이나 발표 자료는 필요하지 않다.

- **개념·문제:** 최장 접두사·다음 홉, 전달과 경로 학습, 왕복/비대칭 경로, TTL·traceroute 한계. [교재](CONCEPTS.md) → [공식 지정 절](SOURCES.md) → [복습](REVIEW.md) 순서로 읽고, 먼저 답한 뒤 [해설](ANSWERS.md)과 비교한다.
- **실습·분석:** A 자기 Linux 두 목적지 경로 조회, B 준비 시뮬레이터의 반환 경로 하나 변경→왕복 비교→복구. 관리 기본 경로는 바꾸지 않음. [실행 안내](LINUX.md)의 필수/선택과 제공 분석/직접 수행 구분을 따른다.
- **실제 구현과 비교:** [Linux 반환 경로·링크 장애](REAL_ROUTE.md)에서 준비된 A–R1–R2–B의 경로표와 실제 ICMP·양끝 pcap을 비교한다. 모형은 예상·복습에 유지하며 실제 도구 수행과 구별한다.
- **모임에 가져올 것:** 본인의 근거에서 고른 출력·풀이와 아직 설명이 막힌 질문. 개인 학습 노트에 한 번 정리하고 원시 로그·pcap은 파일 링크로 연결해도 된다. 새 제출 양식은 만들지 않는다.

### 개인 공부를 정리할 때

기존 개인 학습 노트에 아래 세 가지를 중심으로 정리한다. 모임 전에는 현재 답과 막힌 지점을 남기고, 모임 뒤에는 확인한 차이와 보충할 부분을 고친다. 정해진 개수·분량이나 새 제출물은 없다.

- **주요 질문과 내 답:** [공동 질문](WORKSHEET.md)과 아래 확인 질문에 먼저 내 말로 답한다. 이유·성립 조건과 공식 자료·실습 근거를 연결하고, [분리 해설](ANSWERS.md)은 시도 뒤에 비교한다.
- **헷갈리는 개념 비교:** [핵심 설명](CONCEPTS.md)에서 로컬 경로 조회와 왕복 성공의 역할·관찰 위치·성공 범위를 비교한다. 두 개념이 다른 결론을 내는 예를 들어 본다.
- **이번 주 꼭 기억하고 이해할 핵심 개념:** [핵심 정리](CONCEPTS.md)의 W07-K1~K3를 길잡이로 용어·역할·동작 순서를 추린다. 필요한 공식은 식·단위·성립 조건과 적용 이유를 함께 설명한다. 예제 주소·일회성 출력값을 외우는 목록으로 만들지 않는다.

실습 근거는 해당 질문·개념 아래에 예상·실제 관찰·수정한 이해와 함께 연결한다. 제공 분석과 직접 실행을 구별하고 관찰하지 않은 결과는 채우지 않는다. 입력 화면을 썼다면 이동 전에 답안을 내려받는다. [전체 개념 색인의 정리 방법](../CONCEPT_INDEX.md#personal-study)은 다른 주차에도 같은 방식으로 쓸 수 있다.

### 오프라인에서 확인할 질문

1. **중심 질문:** A에서 B로 가는 경로가 있는데 응답이 없다면 어느 방향의 어떤 근거를 더 볼까?
2. **조건을 바꾸면:** 더 구체적인 경로의 다음 홉이 실패하면 덜 구체적인 경로로 항상 재시도할까?
3. **앞 개념을 다시 쓰면:** 3주 최종 IP와 다음 홉 MAC은 라우터를 지날 때 각각 어떻게 되는가?

중심 질문을 먼저 설명하고 나머지는 짧은 후속 질문으로 사용한다. [분리 해설](ANSWERS.md)과 실제 근거를 대조하되 답을 본 시도와 독립 설명을 구별한다. 개인 공부에서 마친 정상 실습을 전부 반복하지 않고, 막힌 항목과 한 조건 변경·복구를 각자 확인한다.

## 이번 주에 설명할 질문

**이름과 인증서가 맞는데 TCP 연결조차 안 된다면, 요청이 가는 길과 응답이 돌아오는 길에서 무엇을 확인할까?** [질문 자료](WORKSHEET.md)에서 공식 절을 찾고 자기 말로 설명한 뒤 경로 한 항목을 바꿔 비교한다. 혼자서도 이 순서를 마칠 수 있다. 함께할 때는 각자 먼저 시도한 근거를 비교하고 필요하면 설명자·질문자를 교대한다. 고정 파트너나 2인 역할 분담은 필수 조건이 아니다.

## 필수와 선택

필수 A는 **자기 Linux에서 두 목적지의 경로를 조회**하고 선택된 인터페이스·다음 홉·출발 주소를 설명하는 것이다. 상태는 바꾸지 않는다. 필수 B는 **제공된 두 라우터 시뮬레이터를 각자 실행해 정상→정적 경로 한 항목 삭제→왕복 결과 비교→복구**하는 것이다. Python만 있으면 개인 PC에서도 실행할 수 있다. 실제 운영체제 경로표나 네트워크에 영향을 주지 않는 교육 모형이며 Linux 패킷 실측과는 다르다.

경로표 계산·제공 traceroute 기록 분석과 TTL 설명도 필수다. 실제 traceroute 요청, 독립 장비 구성, 메트릭·정책 라우팅·다중 경로는 선택이다. 도구가 준비되지 않았다면 제공 예제를 분석하고 직접 조회/변경은 보충한다. SSH 관리 경로·공용 라우터·실제 기본 경로는 바꾸지 않는다.

## 무엇을 근거로 설명할까

두 목적지의 경로 출력, 선택한 접두사의 주소 범위, 시뮬레이터의 변경 전후 경로표와 왕복 결과를 사용한다. 반환 경로 그림을 그려 어느 장비가 어떤 목적지로 조회하는지 짚는다. 제공 기록을 읽는 것과 본인이 바꿔 실행하는 것을 나눈다. 상세 출력은 개인 파일에 한 번 보관하며 고정 팀 기록·개인 마무리는 없다. [개념 색인](../CONCEPT_INDEX.md)에서 W07-K1~K3을 다시 찾는다.
