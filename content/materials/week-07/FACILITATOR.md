# 진행자 안내 · 경로를 함께 찾고 바꾸기

요약: 개인 공부에서 개념·문제·실습을 준비하고 오프라인 한 번에서 설명·조건 변경·직접 수행을 확인한다. 준비·복구와 제공 분석의 경계를 지키며 막힌 필수 항목을 보충한다.

## 사용 전에 준비할 것

자기 Linux의 iproute2와 IPv4 주소/경로 조회가 가능한지 확인한다. 개인 PC 또는 Linux에 Python 3.12 이상이 있는지 보고 [실습의 코드·JSON](LINUX.md)을 같은 폴더로 전달한다. 각자 열어 정상 probe→R2 반환 경로 삭제→실패→restore→정상까지 실행할 수 있어야 한다. 설치·전달만으로 완료 처리하지 않는다. 관리자 권한이나 실제 경로 변경은 필요 없다. 파일 누락·확장자 변경·Python 버전 오류는 실습 전에 해결한다.

구성은 호스트 A/B와 라우터 R1/R2다. [교재 그림](CONCEPTS.md#round-trip)·`show`·JSON의 주소와 접두사가 같은지 짚는다. 원본 JSON을 임의 구성으로 바꾸는 활동은 필수가 아니다. Linux 관리 SSH 경로·공용망·실제 기본 경로는 변경하지 않는다. 접속이 막히면 제공 분석으로 설명을 이어 가고 자기 Linux 조회는 보충한다.

## 공동 탐구와 설명 교대

중심 질문은 [W07-D1](WORKSHEET.md)이다. [RFC 1812 §5.2.4.3](https://www.rfc-editor.org/rfc/rfc1812.html#section-5.2.4.3)의 **(1) Basic Match와 (2) Longest Match 두 항목**, [ip-route DESCRIPTION](https://man7.org/linux/man-pages/man8/ip-route.8.html#DESCRIPTION)의 **ip route get 소제목부터 no packets are actually sent를 포함한 설명까지**를 함께 찾는다. 영문 전체 문서를 과제로 늘리지 않는다. 지정 절이 안 보이면 문서 내 검색으로 정확한 소제목을 찾는다.

탐색이 막히면 “목적지와 앞 비트가 같은 후보를 남기고 그중 더 긴 길이를 고른다”를 작은 표에 적용한다. 응답 방향은 목적지 칸을 A 주소로 바꾸어 다시 따라가게 한다. 각자가 설명→R2 경로 삭제→비교→복구를 시도한다. 혼자 공부할 때도 같은 흐름을 쓰며 고정 파트너를 요구하지 않는다. 모임에서는 각자의 근거를 먼저 보고 필요할 때 설명자·질문자를 교대한다. 발표자 설명을 참가자 전체의 확인으로 대신하지 않는다.

[실제 Linux 보완](REAL_ROUTE.md)은 진행자가 이미지·권한·정상 상태를 모임 전에 준비한다. 기존 실습 시간에 반환 경로 삭제와 링크 단절을 각각 한 조건으로 비교하며 추가 발표·제출물을 만들지 않는다. R1/R2는 장치 역할이지 사람의 역할이 아니다. 완전 초보자가 막히면 한 단계 시범→본인 재현→다른 조건의 독립 설명으로 돕고, 이미 혼자 수행한 사람에게 전 과정을 교대로 반복시키지 않는다.

## 한 주의 개인 공부와 오프라인 확인

개인 준비는 [학습 홈의 정리 안내](README.md#personal-notes)에 따라 주요 질문과 내 답·헷갈리는 개념 비교·꼭 기억하고 이해할 핵심을 살핀다. 노트 분량을 평가하지 않고 이유·조건 변경·관련 실습 근거로 확인한다. 모임 뒤에는 틀린 설명과 남은 보충만 기존 개인 노트에서 고치며 중복 제출을 요구하지 않는다.

[학습 홈의 개인 공부 범위와 세 확인 질문](README.md#weekly-study)을 오프라인 모임 전까지 준비한다. 모임은 그 주 학습을 마무리하고 남은 보충을 정하는 자리다. 개념·공식 지정 절·복습과 준비된 실습의 정상→변경→복구는 개인 공부에서 시도한다. 모임 전 완성 답안·발표 자료를 요구하지 않으며 막힌 질문과 본인 근거를 가져오게 한다. 진단 원인을 가리는 과제는 정상 기준과 도구까지만 준비한다.

오프라인은 한 번의 모임에서 **설명 → 새 조건 → 본인 실습/분석 확인 → 보충 결정**으로 진행한다. 아래 60분은 시간 배분 예시이며 모임 길이나 추가 회차를 확정하는 표가 아니다.

| 시간 예시 | 진행자가 확인할 것 |
| --- | --- |
| 0~10분 | 개인 공부에서 막힌 질문과 2~4학습 단위 전 개념 하나를 골라 근거로 설명 |
| 10~25분 | 학습 홈의 중심 질문 → 조건 변경. 소그룹에서 설명자/확인자 교대 |
| 25~50분 | A 자기 Linux 두 목적지 경로 조회, B 준비 시뮬레이터의 반환 경로 하나 변경→왕복 비교→복구. 이미 수행했다면 근거를 보고 다른 한 조건의 판단·변경·복구 확인 |
| 50~60분 | 정상 복구·받은 도움·미완료 구분, 개인 학습 노트에 필요한 보충과 다음 질문 연결 |

개인 학습 시간을 고정된 2~3시간으로 제한하지 않는다. 필수 범위를 먼저 공부하고 실제 막힘에 따라 시간을 배분한다. 주차를 미리 분할하거나 필수 기준을 낮추지 않으며, 개인 공부 후에도 해결되지 않는 항목만 보충한다. C04/C08/C12/C16은 해당 주 기존 설명·실습을 대체하고 점검을 별도로 더하지 않는다. 한 사람의 답·팀 합의·파일 제출은 개인 이해/직접 수행의 증거가 아니다.

## 수행과 분석을 나누어 확인하기

| 범위 | 확인할 행동 | 대안/보충 |
| --- | --- | --- |
| 설명·계산 | 일치 후보와 최장 접두사, 다음 홉, 종단 IP/프레임, TTL, 반환 경로 그림 | 교재 표·제공 모형으로 확인 가능 |
| 필수 A 직접 조회 | 본인 Linux의 서로 다른 두 목적지 get·필드/오류 해석 | 제공 출력은 분석만, Linux 조회 보충 |
| 필수 B 직접 변경 | 각자 시뮬레이터의 표·삭제·왕복 비교·복구 | 제공 기록 열람은 분석만, 실행 보충 |
| 필수 traceroute 분석 | 별표가 뜻하는 사실과 모르는 범위, RTT 관점 | [가공 기록](LINUX.md#trace) 사용 가능. 실제 요청은 선택 |

Q1/2/4/8로 근거를 확인하고 TTL/프레임/traceroute 오개념은 Q3/5/6으로 돌아간다. 독립 확인·도움 후 보충·미확인을 나눈다. 7주 결과는 C08의 전체 흐름·O01의 구조 설명을 준비하는 일부이며 해당 평가 전체를 미리 통과시키지 않는다.

## 복구와 다음 주 연결

실습 B는 `restore` 뒤 경로표와 왕복 결과 둘 다 확인한다. 종료하면 메모리만 버리므로 OS 설정 복구가 필요 없다. 실제 traceroute를 했다면 Ctrl+C 또는 자연 종료 후 탐색 중단을 확인한다. SSH 접속이 흔들린다고 실제 기본 경로를 지우지 않는다.

다음 주 시작에는 “이름 해석이 성공하고 캐시가 비었는데 TCP가 실패한다면 왕복 경로와 어느 단계부터 볼까?”를 재질문한다. 8주 전체 흐름·IPv6·신뢰 전송 모형은 다음 자료에서, 동적 경로/OSPF 깊이는 10주에서 다룬다. [출처](SOURCES.md)·[분리 해설](ANSWERS.md#development)·[개념 색인](../CONCEPT_INDEX.md)을 연결한다.
