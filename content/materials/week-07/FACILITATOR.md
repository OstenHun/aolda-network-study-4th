# 진행자 안내 · 경로를 함께 찾고 바꾸기

요약: 중심 질문의 공식 두 절을 함께 찾고 각자의 두 목적지 조회·반환 경로 변경/복구를 확인한다. 선택 분량을 줄여 필수 수행을 확보하며 시뮬레이터와 실제 Linux 관찰을 구별한다.

## 사용 전에 준비할 것

자기 Linux의 iproute2와 IPv4 주소/경로 조회가 가능한지 확인한다. 개인 PC 또는 Linux에 Python 3.12 이상이 있는지 보고 [실습의 코드·JSON](LINUX.md)을 같은 폴더로 전달한다. 각자 열어 정상 probe→R2 반환 경로 삭제→실패→restore→정상까지 실행할 수 있어야 한다. 설치·전달만으로 완료 처리하지 않는다. 관리자 권한이나 실제 경로 변경은 필요 없다. 파일 누락·확장자 변경·Python 버전 오류는 실습 전에 해결한다.

구성은 호스트 A/B와 라우터 R1/R2다. [교재 그림](CONCEPTS.md#round-trip)·`show`·JSON의 주소와 접두사가 같은지 짚는다. 원본 JSON을 임의 구성으로 바꾸는 활동은 필수가 아니다. Linux 관리 SSH 경로·공용망·실제 기본 경로는 변경하지 않는다. 접속이 막히면 제공 분석으로 설명을 이어 가고 자기 Linux 조회는 보충한다.

## 공동 탐구와 설명 교대

중심 질문은 [W07-D1](WORKSHEET.md)이다. [RFC 1812 §5.2.4.3](https://www.rfc-editor.org/rfc/rfc1812.html#section-5.2.4.3)의 **(1) Basic Match와 (2) Longest Match 두 항목**, [ip-route DESCRIPTION](https://man7.org/linux/man-pages/man8/ip-route.8.html#DESCRIPTION)의 **ip route get 소제목부터 no packets are actually sent를 포함한 설명까지**를 함께 찾는다. 영문 전체 문서를 과제로 늘리지 않는다. 지정 절이 안 보이면 문서 내 검색으로 정확한 소제목을 찾는다.

탐색이 막히면 “목적지와 앞 비트가 같은 후보를 남기고 그중 더 긴 길이를 고른다”를 작은 표에 적용한다. 응답 방향은 목적지 칸을 A 주소로 바꾸어 다시 따라가게 한다. 한 명의 설명 뒤 다른 사람이 R2 경로를 지워 비교한다. 다음 질문/회차에는 설명자를 교대하고 각자 필수 명령을 실행한다. 발표자 설명을 참가자 전체의 확인으로 대신하지 않는다.

## 모임에 배치하는 제안

다음은 각 60분 운영안을 위한 **배치 추정**이다. 초보자의 실제 소요 시간을 측정한 결과가 아니며 접속·설치·실제 질문에 따라 나눈다. 세 학습 주제를 모임 세 번으로 강제하지 않는다.

| 모임 | 활동·배치 추정 | 초과하면 |
| --- | --- | --- |
| 공동학습 | 이전 CIDR/ARP·실패 단계 10분, 중심 공식 절 탐색 15분, 교재 표/그림과 설명·조건 변경 25분, 핵심 정리 10분 | 보조 질문·실제 traceroute를 줄이고 지정 절과 반환 경로 설명 유지 |
| 직접 실습 | 실행 위치/파일 확인 10분, Linux 두 목적지 조회 10분, 시뮬레이터 정상/삭제/복구 25분, 복습·근거 확인 15분 | TTL 추가 실행·정책 조회 심화를 줄이고 필수 수행은 다음 회차 보충 |

핵심 3개·혼동 2개는 기존 읽기 마지막 약 5분을 대체한다. 복습 8개는 읽기 후 필요한 문제부터 확인하며 별도 긴 발표·고정 팀 기록·개인 마무리를 만들지 않는다. 원본 출력은 개인 파일에 한 번 보관한다.

## 수행과 분석을 나누어 확인하기

| 범위 | 확인할 행동 | 대안/보충 |
| --- | --- | --- |
| 설명·계산 | 일치 후보와 최장 접두사, 다음 홉, 종단 IP/프레임, TTL, 반환 경로 그림 | 교재 표·제공 모형으로 확인 가능 |
| 필수 A 직접 조회 | 본인 Linux의 서로 다른 두 목적지 get·필드/오류 해석 | 제공 출력은 분석만, Linux 조회 보충 |
| 필수 B 직접 변경 | 각자 시뮬레이터의 표·삭제·왕복 비교·복구 | 제공 기록 열람은 분석만, 실행 보충 |
| 필수 traceroute 분석 | 별표가 뜻하는 사실과 모르는 범위, RTT 관점 | [가공 기록](LINUX.md#trace) 사용 가능. 실제 요청은 선택 |

Q1/2/4/8로 근거를 확인하고 TTL/프레임/traceroute 오개념은 Q3/5/6으로 돌아간다. 독립 확인·도움 후 보충·미확인을 나눈다. 7주 결과는 C08의 전체 흐름·O01의 구조 설명을 준비하는 일부이며 해당 평가 전체를 미리 통과시키지 않는다.

## 복구와 다음 주 연결

실습 B는 `restore` 뒤 경로표와 왕복 결과 둘 다 확인한다. 종료하면 메모리만 버리므로 OS 설정 복구가 필요 없다. 실제 traceroute를 했다면 Ctrl+C 또는 자연 종료 후 탐색 중단을 확인한다. SSH 접속이 흔들린다고 실제 기본 경로를 지우지 않는다.

다음 주 시작에는 “이름 해석이 성공하고 캐시가 비었는데 TCP가 실패한다면 왕복 경로와 어느 단계부터 볼까?”를 재질문한다. 8주 전체 흐름·IPv6·신뢰 전송 모형은 다음 자료에서, 동적 경로/OSPF 깊이는 10주에서 다룬다. [출처](SOURCES.md)·[분리 해설](ANSWERS.md#development)·[개념 색인](../CONCEPT_INDEX.md)을 연결한다.
