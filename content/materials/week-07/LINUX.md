# 두 목적지 조회와 격리 경로 변경

요약: Linux에서 목적지만 바꿔 경로를 조회하고, 제공 시뮬레이터에서 반환 경로 한 항목을 지운 뒤 복구한다. 실행 위치·정상 기준·오류 처리와 코드 흐름을 읽으며 제공 분석과 본인 수행을 나눈다.

## 실행 위치와 준비

| 구분 | 필요한 환경·파일 | 권한·범위 |
| --- | --- | --- |
| 필수 A | 자기 Linux 셸, iproute2의 `ip` (`ip -V`로 버전 기록) | 조회만, 보통 일반 사용자. 운영체제 경로 변경 없음 |
| 필수 B | Linux 또는 개인 PC의 Python 3.12 이상, 아래 두 파일을 같은 폴더에 저장 | 일반 사용자, 패키지 설치·관리자 권한·외부 연결 불필요 |
| 선택 C | Linux용 traceroute 2.x (`traceroute --version`)와 허가된 목적지 | 소량의 실제 탐색 패킷. 도구/권한이 없으면 제공 분석 |

다운로드: <a download href="../../labs/week-07/route_sim.py">route_sim.py</a> · <a download href="../../labs/week-07/topology.txt">topology.txt</a>. topology.txt는 JSON 형식의 텍스트 구성 파일이다. 브라우저가 파일명을 바꾸면 위 이름으로 되돌린다. HTML 안내만 저장하지 않고 실제 코드·JSON 파일을 연다. 구성은 [교재의 A–R1–R2–B](CONCEPTS.md#round-trip)와 같다. 다른 파일이나 Python 패키지는 필요 없다. 시뮬레이터는 Python 표준 라이브러리만 사용한다.

## 필수 A · 자기 Linux의 두 목적지 조회

**자기 Linux VM에 접속한 셸**에서 실행한다. 본인에게 배정된 환경인지 먼저 확인한다. 아래 문서용 두 주소는 조회 조건이며 실제 요청을 보내지 않는다.

```sh
ip -V
ip -4 address show
ip -4 route show
ip -4 route get 192.0.2.10
ip -4 route get 203.0.113.20
```

`-4`는 IPv4로 한정한다. `show`는 기본적으로 main 표의 항목을 보여 주고 `get`은 주어진 목적지에 대한 커널의 선택을 보여 준다. 이 조회는 패킷을 보내지 않는다. 실제 표에는 정책·VPN 등 추가 조건이 있을 수 있어 교재의 단순 표와 다를 수 있다.

출력의 `via`는 다음 홉, `dev`는 출력 인터페이스, `src`는 커널이 고른 출발 주소다. 직접 연결 경로는 `via` 없이 `dev`만 나올 수 있다. 다음은 **설명용 가공 출력**이며 본인 결과의 정답이 아니다.

```text
203.0.113.20 via 192.0.2.1 dev net0 src 192.0.2.10
```

정상 기준은 두 조회를 직접 실행하고 **선택 경로가 있으면 필드를, 없으면 `Network is unreachable` 같은 오류와 해당 표의 부재를** 설명하는 것이다. 두 결과가 같아도 실패가 아니다. 둘 다 기본 경로에 맞을 수 있다. 이 경우 `show`에서 본인 직접 연결 범위 안의 주소 하나를 골라 추가 조회하면 차이를 비교할 수 있다. 주소 끝자리를 임의로 바꿔 같은 망이라 단정하지 않고 본인 접두사의 범위를 먼저 계산한다.

목적지 조건을 첫 주소→둘째 주소→첫 주소로 되돌려 조회한다. 경로표는 바꾸지 않았으므로 원복 명령이 없다. 오류가 예상과 다르면 `ip -4 rule show`, `ip -4 route show table all`을 조회만 하여 선택 조건을 확인한다. 정책 규칙의 상세 설계는 선택이다. `ip`가 없으면 진행자와 환경 준비를 확인하고 자기 Linux 조회는 보충한다. 제공 출력만 읽고 본인 조회로 처리하지 않는다.

## 필수 B · 두 라우터의 반환 경로 한 항목 바꾸기

두 파일을 저장한 **개인 실습 폴더의 셸**에서 실행한다. Linux/macOS에서는 `python3`, Windows에서는 설치된 `python` 또는 `py -3`를 쓸 수 있다. 아래 명령의 `python3`만 본인 실행 이름으로 바꾸며 3.12 이상인지 확인한다.

```sh
python3 --version
python3 route_sim.py
```

이후 `sim>` 프롬프트에서 아래 명령을 **하나씩** 입력한다. 셸의 `ip route delete`가 아니다. 단계 사이에 예상과 관찰을 말하고 각자 직접 실행한다.

```text
show
probe a b
delete r2 192.0.2.0/24
show
probe a b
restore
show
probe a b
quit
```

| 단계 | 정상·비교 기준 | 출력에서 볼 곳 |
| --- | --- | --- |
| 정상 | A→R1→R2→B, B→R2→R1→A 왕복 | 각 노드의 match/next, `ROUND_TRIP OK` |
| 변경 | R2의 정적 `192.0.2.0/24` 하나만 삭제 | `DELETED`, R2 표에서 그 항목 부재 |
| 비교 | 요청은 B 도착, 응답은 R2에서 중단 | `b DELIVERED`, `RETURN`, `r2 NO_ROUTE`, `FAIL (return)` |
| 복구 | 원래 경로표·왕복 성공 복귀 | `RESTORED`, R2 경로 존재, `ROUND_TRIP OK` |

`probe`는 교육용 왕복 전달 계산이며 ping이나 실제 서비스 요청이 아니다. `show`·변경 전후 probe·복구 결과를 개인 파일에 한 번 보관하고 반환 경로 그림과 함께 설명한다. 시뮬레이터를 직접 바꿔 실행한 것은 이 환경의 직접 수행이다. Linux 커널 경로표나 실제 ICMP 캡처를 검증한 것으로 쓰지 않는다.

복구는 `restore`가 원래 메모리 사본 전체를 되돌린다. 종료·Ctrl+C·입력 끝(EOF)도 변경을 버린다. 다시 실행하면 원본 JSON을 읽는다. JSON 자체는 이 실험에서 편집하지 않는다. 파일을 실수로 편집했다면 원본 두 파일을 다시 받아 시작한다. 누락/깨진 JSON은 기동 오류로 종료하며 경로 실습은 시작되지 않는다. 잘못된 명령·없는 경로·IPv6 입력은 `INPUT_ERROR`로 거부하고 프롬프트로 돌아간다. 연결 경로 삭제는 거부한다. 경로가 복구됐는지 표와 왕복 결과를 모두 재확인한다.

## TTL 조건 바꾸기

같은 시뮬레이터에서 경로를 복구한 뒤 `probe a b 2`, `probe a b 3`을 비교한다. 뒤 숫자는 초기 TTL이다. 2이면 R2에서 만료되고 3이면 두 라우터를 지나 B에 전달되며 응답도 별도의 TTL 3으로 돌아온다. `probe a b`의 기본값 64로 되돌려 정상 기준을 확인한다. TTL 0·256·문자열은 입력 오류다. 이 모형은 ICMP 패킷 생성/반환·시간 지연을 계산하지 않으며 `TTL_EXPIRED`는 내부 계산 결과다.

## 필수 분석 · 별표가 있는 traceroute

아래는 별표 해석을 위한 **가공 기록**이다. 실제 팀 환경의 캡처가 아니다. 숫자는 각 탐색 응답까지의 왕복 밀리초(ms)다.

```text
traceroute to 203.0.113.20, 3 hops max, 1 probe per hop
1  192.0.2.1       1.2 ms
2  *
3  203.0.113.20    4.8 ms
```

홉 2의 응답이 시간 안에 오지 않았지만 홉 3의 탐색에는 목적지가 응답했다. TTL이 다른 별도 탐색들이므로 같은 패킷 하나가 별표를 뚫었다고 표현하지 않는다. 중간 응답 제한·분산/경로 변화 등을 고려하며 중간 장비 단절을 확정하지 않는다. 이 기록만으로 TCP/HTTP 성공이나 반환 경로의 전체 홉도 알 수 없다. `4.8 - 1.2`를 홉 2 링크의 지연으로 확정하지 않는다.

선택으로 자기 Linux에서 **허가된 대상 IPv4**를 변수에 넣어 소량 실행할 수 있다. 아래 주소는 예제라 실제 실습 대상 값으로 교체한다. 허가된 대상이 없으면 실행하지 않는다.

```sh
target=203.0.113.20
traceroute -n -m 8 -q 1 -w 1 "$target"
```

`-n`은 이름 역조회 생략, `-m`은 최대 TTL, `-q`는 TTL당 탐색 수, `-w`는 응답 대기 초다. 정상 기준은 목적지 도달 여부·응답/별표·사용 방식을 구별하는 것이며 모든 홉 응답을 요구하지 않는다. 중단은 Ctrl+C, 설정 복구는 필요 없다. 미설치·권한 부족이면 제공 기록 분석으로 이 항목을 확인한다.

## 코드 읽기 · 입력에서 전달까지

참가자는 명령과 아래 흐름을 읽으면 된다. 전체 Python 문법 습득이나 독립 시뮬레이터 구현은 요구하지 않는다. [실제 코드](../../labs/week-07/route_sim.py)와 [구성](../../labs/week-07/topology.txt)을 함께 연다.

1. **구성 읽기 — `load_topology`**: `Path(__file__)`로 코드 옆 JSON을 찾고 `with`로 읽은 파일을 닫는다. 누락/잘못된 JSON은 기동을 중단한다.
2. **명령 나누기 — `main`**: `input().split()`으로 명령 단어를 나누고 `if/elif`로 종류를 결정한다. 잘못된 값은 `ValueError`를 잡아 안내한다.
3. **접두사 선택 — `choose_route`**: `IPv4Network`와 `address in network`로 일치를 판단하고 `prefixlen`이 가장 큰 경로를 고른다. 후보가 없으면 `None`을 돌려준다.
4. **한 방향 전달 — `walk`**: 현재 노드의 표로 다음 이웃을 선택하고 라우터에서 TTL을 줄인다. 결과는 `DELIVERED`, `NO_ROUTE`, `TTL_EXPIRED`, `NO_NEIGHBOR`로 나뉜다.
5. **왕복 확인 — `probe`**: 정방향 성공 뒤 출발/목적을 바꾸어 반환을 계산한다. 양쪽이 모두 성공해야 `ROUND_TRIP OK`다.
6. **변경과 복구 — `delete_route`·`restore`**: static 항목만 메모리에서 제거하고 `deepcopy`로 원본 사본을 복구한다. 파일·OS 경로표에는 쓰지 않는다.

`nodes[name]`은 이름으로 꺼내는 사전 항목이고 `routes`는 경로 목록이다. `return`은 현재 함수 계산을 끝낸다. `while True`는 전달 또는 입력을 반복하며 TTL 만료·실패·종료로 끝난다. 고정 구성은 호스트 a/b와 라우터 r1/r2, 유효 IPv4·서로 다른 접두사 후보·직접 이웃만 지원한다. 같은 길이 경로 경쟁, ARP 캐시, 링크 장애, 정책·NAT·큐잉·실제 패킷은 구현하지 않는다. 임의의 외부 JSON 구성을 지원하는 범용 장비 에뮬레이터가 아니다.

자기 말로 확인한다. `longest = -1`인 이유는 무엇일까? 기본 경로의 길이 0도 후보가 돼야 한다. 요청이 성공한 뒤 왜 `walk`를 한 번 더 호출할까? 왜 원본 사본과 현재 표를 나눌까? [복습](REVIEW.md)·[해설](ANSWERS.md)에서 조건을 바꿔 확인한다.
