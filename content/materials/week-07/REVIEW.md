# 복습 · 경로의 근거와 남은 불확실성

요약: 최장 접두사·다음 홉·왕복 경로·TTL과 traceroute의 관찰 범위를 여덟 문제로 확인한다. 먼저 자기 말로 답하고 분리 해설과 비교한다. 실제 수행은 본인 실행 근거로 구별한다.

## Q1. 세 경로 중 어디로 보낼까?

한 유효 전달표에 `0.0.0.0/0 via 192.0.2.1`, `203.0.0.0/16 via 192.0.2.2`, `203.0.113.0/24 via 192.0.2.3`이 있다. 정책·동일 접두사 경쟁은 없다. 목적지가 `203.0.113.20`, `203.0.114.20`, `198.51.100.20`일 때 각각 선택 접두사·다음 홉과 이유를 설명한다.

## Q2. 경로가 보이면 통신도 성공할까?

`ip -4 route get`이 `via ... dev ... src ...`를 출력했다. 각 필드의 뜻과 이 조회만으로 아직 알 수 없는 두 가지를 말한다. 두 목적지가 같은 기본 경로를 쓰면 조회 실습이 실패한 것일까?

## Q3. 어떤 주소가 홉마다 바뀔까?

NAT·터널 없는 A→R1→R2→B의 Ethernet 구성이다. A→R1과 R1→R2에서 최종 IP 목적지와 Ethernet 목적 MAC의 상대를 비교한다. 일반 L2 스위치 하나를 더 지나면 IPv4 TTL도 반드시 줄어들까?

## Q4. 반환 경로 하나를 지웠다면?

제공 구성에서 R2의 정적 `192.0.2.0/24`만 삭제했다. A→B와 B→A를 나누어 전달이 멈추는 곳을 설명한다. 복구 후 어떤 두 근거를 확인해야 할까?

## Q5. TTL 2와 3의 차이는?

전달할 때 라우터마다 1씩 감소하는 모형에서 A가 R1·R2를 지나 B로 보낸다. 초기 TTL 2와 3의 결과를 계산한다. B의 응답 TTL과 DNS TTL을 어떻게 구별할까?

## Q6. 중간의 별표는 무엇일까?

가공 traceroute 기록에서 홉 1은 1.2ms, 홉 2는 `*`, 홉 3의 목적지는 4.8ms다. 확실히 말할 사실 하나와 확정할 수 없는 결론 두 가지를 말한다. 3.6ms를 홉 2 링크의 지연으로 봐도 될까?

## Q7. 경로를 배우는 일과 고르는 일은?

관리자가 정적 경로를 넣는 일과 패킷마다 최장 접두사를 고르는 일을 구별한다. 더 구체적인 경로가 선택됐지만 그 다음 홉이 응답하지 않으면 반드시 기본 경로로 자동 재시도할까? 시뮬레이터가 실제 장비와 다르게 생략한 동작 두 가지도 말한다.

## Q8. 직접 수행과 분석을 구별하기

본인이 실행한 Linux 두 목적지 조회와 시뮬레이터의 정상·삭제·복구 결과에서 각각 필요한 줄을 짚는다. 실행하지 못한 항목은 제공 분석과 필요한 환경/보충 행동을 말한다. 복구했는데 왕복이 계속 실패한다면 표와 결과를 어떤 순서로 다시 볼까?
