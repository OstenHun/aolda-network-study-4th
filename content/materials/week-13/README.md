# 13주차 · 내 VM의 통신을 클라우드 자원에 연결하기

요약: 자기 VM의 주소·포트·서브넷·경로·보안 그룹을 요청과 양끝 로그에 연결한다. 테스트 서비스 전용 규칙을 변경·복구하고 DNS·TLS 근거를 재사용하며, 제공 사례로 MTU·MSS·PMTUD를 구별한다.

<span id="weekly-study"></span>

## 개인 공부와 오프라인 확인

오프라인 모임 전까지 아래 범위를 공부하고 실습을 시도한다. 모임은 그 주의 학습을 마무리하는 자리로, 막힌 이유와 조건을 바꾼 결과를 설명하고 남은 보충을 정한다. [공동 질문](WORKSHEET.md)은 개인 공부의 출발점으로 쓰고, 모임에서는 근거를 비교한다. 별도 사전 모임이나 발표 자료는 필요하지 않다.

- **개념·문제:** 가상 network/subnet/port/router·모든 적용 보안 그룹, 양끝 서비스/바인딩, DNS/TLS 신원, MTU/MSS·PMTUD. [교재](CONCEPTS.md) → [공식 지정 절](SOURCES.md) → [복습](REVIEW.md) 순서로 읽고, 먼저 답한 뒤 [해설](ANSWERS.md)과 비교한다.
- **실습·분석:** A 자기 자원 조회·양끝 요청·테스트 전용 규칙 한 조건 변경/복구와 DNS/TLS 근거 연결, B 제공 크기 분석. 권한/복구 없는 규칙 변경은 수행하지 않음. [실행 안내](LINUX.md)의 필수/선택과 제공 분석/직접 수행 구분을 따른다.
- **모임에 가져올 것:** 본인의 근거에서 고른 출력·풀이와 아직 설명이 막힌 질문. 개인 학습 노트에 한 번 정리하고 원시 로그·pcap은 파일 링크로 연결해도 된다. 새 제출 양식은 만들지 않는다.

<span id="personal-notes"></span>

### 개인 공부를 정리할 때

기존 개인 학습 노트에 아래 세 가지를 중심으로 정리한다. 모임 전에는 현재 답과 막힌 지점을 남기고, 모임 뒤에는 확인한 차이와 보충할 부분을 고친다. 정해진 개수·분량이나 새 제출물은 없다.

- **주요 질문과 내 답:** [공동 질문](WORKSHEET.md)과 아래 확인 질문에 먼저 내 말로 답한다. 이유·성립 조건과 공식 자료·실습 근거를 연결하고, [분리 해설](ANSWERS.md)은 시도 뒤에 비교한다.
- **헷갈리는 개념 비교:** [핵심 설명](CONCEPTS.md)에서 MTU와 MSS, 이름 해석과 TLS 신원의 역할·관찰 위치·성공 범위를 비교한다. 두 개념이 다른 결론을 내는 예를 들어 본다.
- **이번 주 꼭 기억하고 이해할 핵심 개념:** [핵심 정리](CONCEPTS.md)의 W13-K1~K3를 길잡이로 용어·역할·동작 순서를 추린다. 필요한 공식은 식·단위·성립 조건과 적용 이유를 함께 설명한다. 예제 주소·일회성 출력값을 외우는 목록으로 만들지 않는다.

실습 근거는 해당 질문·개념 아래에 예상·실제 관찰·수정한 이해와 함께 연결한다. 제공 분석과 직접 실행을 구별하고 관찰하지 않은 결과는 채우지 않는다. 입력 화면을 썼다면 이동 전에 답안을 내려받는다. [전체 개념 색인의 정리 방법](../CONCEPT_INDEX.md#personal-study)은 다른 주차에도 같은 방식으로 쓸 수 있다.

### 오프라인에서 확인할 질문

1. **중심 질문:** DNS는 맞고 VM은 실행 중인데 GET 로그 없이 timeout이면 어떤 두 가설과 관찰을 고를까?
2. **조건을 바꾸면:** 허용 규칙 하나를 지워도 새 연결이 200이면 중복 허용·상태·전파 중 무엇을 조회할까?
3. **앞 개념을 다시 쓰면:** 5~6주의 이름/캐시/신원과 11주의 기존/새 연결을 같은 서비스 경로에 연결할 수 있는가?

중심 질문을 먼저 설명하고 나머지는 짧은 후속 질문으로 사용한다. [분리 해설](ANSWERS.md)과 실제 근거를 대조하되 답을 본 시도와 독립 설명을 구별한다. 개인 공부에서 마친 정상 실습을 전부 반복하지 않고, 막힌 항목과 한 조건 변경·복구를 각자 확인한다.

**이름도 풀리고 VM도 실행 중인데 왜 내 요청은 닿지 않을까?** [7주차 왕복 경로](../week-07/CONCEPTS.md), [11주차 NAT·접근 정책](../week-11/CONCEPTS.md), [12주차 연결과 보호 경계](../week-12/CONCEPTS.md)를 실제 자원에 대응한다. 교재에 적힌 주소는 설명용이며 자신의 허가된 대상만 사용한다.

## 함께 공부하는 순서

1. [중심 질문](WORKSHEET.md)에서 먼저 확인할 두 관찰을 고른다.
2. [개념 교재](CONCEPTS.md)와 [공식 지정 절](SOURCES.md)을 함께 읽고 한 명이 경로·정책·서비스를 나누어 설명한다.
3. 다른 사람이 출발지나 패킷 크기 한 조건을 바꿔 묻는다. 설명자는 교대한다.
4. [실습 A](LINUX.md#cloud-lab)에서 자기 자원을 읽고 테스트 HTTP의 정상→규칙 한 조건 변경→복구를 확인한다. [5주차 DNS](../week-05/LINUX.md)·[6주차 TLS](../week-06/LINUX.md#tls-lab) 근거와 같은 VM의 이름·신원을 연결한다.
5. [실습 B](LINUX.md#mtu-analysis)에서 제공 크기 사례를 계산한 뒤 [복습](REVIEW.md)과 [분리 해설](ANSWERS.md)을 비교한다.

실제 클라우드 접근·규칙 소유권·별도 콘솔/복구가 없으면 제공 기록과 [11주차 격리 정책 실습](../week-11/LINUX.md)으로 분석을 이어간다. 이 경우 이번 주 직접 운영은 미완료다. 제공 자료를 읽거나 한 사람의 시연을 본 것으로 개인의 수행을 대신하지 않는다.

## 시간과 완료 근거

한 주의 개인 공부에서 공식 지정 절·A 정상 기준과 B 크기 분석을 준비한다. 오프라인에서는 양끝 요청과 규칙 변경·복구, 크기 조건을 바꾼 설명을 확인한다. 환경 준비·인증서 초기 생성은 진행자가 먼저 확인하며 전체 RFC 읽기나 새 발표 자료를 추가하지 않는다.

완료 근거는 **자기 자원과 왕복 경로 그림, 출발지/목적지·바인딩·포트, 요청 식별자가 든 클라이언트 결과/서버 로그, 규칙 전후/복구, 이름/TLS 확인 근거, 크기 사례 풀이**다. 개인 파일에 한 번 보관하고 필요한 부분을 보여 준다. 고정 팀 기록·개인 마무리·발표 양식은 없다. O01\~O03의 근거를 이어 모으며 분산·반복 관측 O04\~O05는 다음 주차에서 다룬다.
