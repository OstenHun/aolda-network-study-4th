# 13주차 · 내 VM의 통신을 클라우드 자원에 연결하기

요약: 자기 VM의 주소·포트·서브넷·경로·보안 그룹을 요청과 양끝 로그에 연결한다. 테스트 서비스 전용 규칙을 변경·복구하고 DNS·TLS 근거를 재사용하며, 제공 사례로 MTU·MSS·PMTUD를 구별한다.

## 이번 주의 질문

**이름도 풀리고 VM도 실행 중인데 왜 내 요청은 닿지 않을까?** [7주차 왕복 경로](../week-07/CONCEPTS.md), [11주차 NAT·접근 정책](../week-11/CONCEPTS.md), [12주차 연결과 보호 경계](../week-12/CONCEPTS.md)를 실제 자원에 대응한다. 교재에 적힌 주소는 설명용이며 자신의 허가된 대상만 사용한다.

## 함께 공부하는 순서

1. [중심 질문](WORKSHEET.md)에서 먼저 확인할 두 관찰을 고른다.
2. [개념 교재](CONCEPTS.md)와 [공식 지정 절](SOURCES.md)을 함께 읽고 한 명이 경로·정책·서비스를 나누어 설명한다.
3. 다른 사람이 출발지나 패킷 크기 한 조건을 바꿔 묻는다. 설명자는 교대한다.
4. [실습 A](LINUX.md#cloud-lab)에서 자기 자원을 읽고 테스트 HTTP의 정상→규칙 한 조건 변경→복구를 확인한다. [5주차 DNS](../week-05/LINUX.md)·[6주차 TLS](../week-06/LINUX.md#tls-lab) 근거와 같은 VM의 이름·신원을 연결한다.
5. [실습 B](LINUX.md#mtu-analysis)에서 제공 크기 사례를 계산한 뒤 [복습](REVIEW.md)과 [분리 해설](ANSWERS.md)을 비교한다.

## 필수와 선택

| 구분 | 이번에 확인할 것 |
| --- | --- |
| 필수 직접 수행 A | 실제 프로젝트/VM·network/subnet/port/router·주소/왕복 경로·모든 적용 보안 그룹 조회, 허가된 PC→VM 또는 VM→VM 요청과 양끝 로그, 테스트 서비스 전용 허용 규칙 한 조건 변경·복구 |
| 기존 근거 재사용 | DNS 이름과 실제 목적지·TLS 신원/신뢰/기간을 5\~6주 근거로 설명. 같은 서비스 경로의 근거가 빠졌다면 준비된 테스트 이름/인증서로 보충 |
| 필수 제공 분석 B | 캡슐화의 크기 예산, MTU와 MSS, IPv4 DF·IPv6 라우터/출발지, PMTUD/ICMP의 관계 |
| 선택·후속 | 추가 VM·독립 초기 구축·격리 MTU 변경·VXLAN/VRF 상세. 실제 내부 캡슐화/물리 호스트는 확인한 범위만 설명 |

실제 클라우드 접근·규칙 소유권·별도 콘솔/복구가 없으면 제공 기록과 [11주차 격리 정책 실습](../week-11/LINUX.md)으로 분석을 이어간다. 이 경우 이번 주 직접 운영은 미완료다. 제공 자료를 읽거나 한 사람의 시연을 본 것으로 개인의 수행을 대신하지 않는다.

## 시간과 완료 근거

사전 공동학습 60분은 질문→짧은 공식 읽기→교대 설명→환경 점검에 쓴다. 실습 60분은 A의 직접 수행과 B의 크기 분석 두 묶음으로 배치한다. 환경 준비·인증서 초기 생성은 진행자가 먼저 준비하며 실제 소요 시간에 따라 나눠 보충한다. 필수 읽기는 약10분 추정이며 전체 RFC 읽기를 추가하지 않는다.

완료 근거는 **자기 자원과 왕복 경로 그림, 출발지/목적지·바인딩·포트, 요청 식별자가 든 클라이언트 결과/서버 로그, 규칙 전후/복구, 이름/TLS 확인 근거, 크기 사례 풀이**다. 개인 파일에 한 번 보관하고 필요한 부분을 보여 준다. 고정 팀 기록·개인 마무리·발표 양식은 없다. O01\~O03의 근거를 이어 모으며 분산·반복 관측 O04\~O05는 다음 주차에서 다룬다.
