# 13주차 · 자원·요청·크기 복습

요약: 클라우드 자원과 왕복 요청, 정책 변경·복구, DNS/TLS, MTU·MSS·IPv4/IPv6를 확인하는 자체 문항이다. 먼저 풀고 분리 해설을 본다. 제공 분석과 본인 직접 운영을 구별한다.

## Q1. port라는 말 두 가지

서버의 Neutron port에 fixed IP·MAC·보안 그룹이 보인다. 프로그램은 TCP 8080에 대기한다. 두 port는 각각 무엇이며 어떤 값으로 연결해서 볼까?

## Q2. 같은 subnet과 외부 주소

가공 [C0](../../labs/week-13/cloud-case.txt)의 두 VM은 같은 subnet에 있고 route get에는 `dev eth0 src ...`만 있다. router가 있다는 이유로 요청이 반드시 그 router를 지날까? floating IP로 접속하는 경로와 비교해 왕복을 설명한다.

## Q3. DNS 성공 뒤 시간 제한

이름이 예상 주소를 반환하지만 요청은 시간 제한에 걸리고 서버 GET 로그가 없다. 두 원인 가설과 이를 나눌 양끝 관찰을 고른다. `ss`에 `127.0.0.1:8080`만 보인다면 무슨 뜻일까?

## Q4. 허용 rule을 지웠는데 200

본인 TCP 8080 허용 rule 하나를 제거한 뒤 새 요청이 200이다. 모든 적용 그룹의 어떤 조건을 확인해야 할까? 기존 연결/전파 조건과 관리 경로를 건드리지 않는 복구까지 설명한다.

## Q5. 전후·복구 근거

제공 C1\~C3의 client/message·종료 코드·서버 LISTEN·GET 로그·규칙을 대조한다. 새 rule ID가 달라도 무엇이 같으면 정책 조건을 복구했다고 말할까? 이 제공 분석을 O03 직접 운영 완료로 쓸 수 있을까?

## Q6. 이름과 TLS

`--resolve study.test:8443:주소`로 검증을 켠 200을 받았다. 실제 DNS 성공을 확인한 것일까? 같은 주소/포트/CA에서 URL을 `wrong.test`로 바꿨을 때 실패하면 어떤 신원 조건과 HTTP 로그를 확인할까?

## Q7. 캡슐화와 MSS 계산

M0의 외부 IP MTU 1500·추가 비용 50bytes에서 내부 IP 1500은 들어갈까? 내부 IP 한도를 구하고 옵션 없는 IPv4/TCP·IPv6/TCP의 데이터 예산을 각각 계산한다. 실제 IPv4 TCP 옵션 12bytes가 있으면 해당 세그먼트의 데이터와 MSS 광고값 계산을 어떻게 구별할까?

## Q8. IPv4 조각과 IPv6

M2의 원래 IPv4는 total 1500/header 20이다. 첫 조각 payload 1424·둘째 56이면 각 total과 둘째 offset, 원래 payload와의 합을 검산한다. DF=1이라면 어떻게 달라질까? IPv6 라우터의 처리와도 비교한다.

## Q9. 작은 요청이 되는 장애

작은 요청은 되지만 큰 전송이 멈췄다. MTU를 확정할 수 있을까? 크기/방향/ICMP와 서버 처리 중 원인을 구별할 다음 관찰을 고르고 현재 VM의 물리 터널 방식까지 알 수 있는지 설명한다.

## 근거로 돌아가기

Q1\~Q6은 실습 A/O01\~O03, Q7\~Q9는 제공 B다. 실제 자원/양끝 요청·정책 변경/복구가 없으면 그 항목을 보충한다. 읽기·문항 정답·한 사람의 실행은 전원의 직접 수행을 대신하지 않는다. 입력은 자동 저장되지 않으므로 필요하면 답안을 내려받아 보관한다.
