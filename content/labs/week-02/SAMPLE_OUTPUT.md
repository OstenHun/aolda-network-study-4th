# 2주차 제공 출력과 주소 카드

요약: 아래 터미널 줄은 학습용으로 구성한 미측정 예시다. 실제 아올다 VM·참가자 Linux의 출력이 아니며, 예제 분석과 본인 직접 실행을 기록에서 구분한다.

## 읽는 법

명령 뒤의 출력은 한 가지 가능한 형태를 설명하려고 만든 **교육용 합성 자료**다. 인터페이스 이름, 주소, 경로, 오류 문구, `ping` 시간은 환경마다 다르다. 자신이 직접 관찰한 출력과 구별해서 읽는다. Python 카드 계산 값도 실제 네트워크 도달·응답의 증거는 아니다.

## E1. 인터페이스와 경로 — 미측정 합성 예시

```text
$ ip -br -4 addr
lo       UNKNOWN        127.0.0.1/8
eth0     UP             192.168.10.23/24

$ ip -4 route
default via 192.168.10.1 dev eth0
192.168.10.0/24 dev eth0 proto kernel scope link src 192.168.10.23

$ ip -4 route get 127.0.0.1
local 127.0.0.1 dev lo src 127.0.0.1
```

읽을 값: `lo`는 같은 Linux 안의 루프백, `eth0`은 예시 VM의 다른 인터페이스다. `192.168.10.23/24`의 직접 연결 범위는 `192.168.10.0/24`, 기본 경로의 다음 전달 상대는 `192.168.10.1`이다. 실제 VM에 `eth0`이나 기본 경로가 반드시 있다는 뜻이 아니다. 경로 조회는 응답 확인이 아니다.

## C1. 양쪽 `/24` — 계산 예시, 통신 미측정

```text
$ python3 labs/week-02/subnet_check.py 192.0.2.10/24 192.0.2.70/24
A: 192.0.2.10/24
  네트워크: 192.0.2.0/24
  서브넷 마스크: 255.255.255.0
  범위 끝 주소: 192.0.2.255
  호스트 주소 범위: 192.0.2.1 ~ 192.0.2.254
B: 192.0.2.70/24
  네트워크: 192.0.2.0/24
  서브넷 마스크: 255.255.255.0
  범위 끝 주소: 192.0.2.255
  호스트 주소 범위: 192.0.2.1 ~ 192.0.2.254
A 기준으로 B 포함: 예
B 기준으로 A 포함: 예
주의: 주소 포함 계산은 경로·링크·방화벽·상대 상태를 확인하지 않습니다.
```

예측 질문: 두 방향 모두 주소 범위에 들어가도 통신 성공이라고 쓸 수 없는 이유는? 상대가 꺼졌거나 링크가 끊기거나, 경로·정책·왕복 조건이 다를 수 있다.

## C2. A만 `/26` — 계산 예시, 통신 미측정

```text
$ python3 labs/week-02/subnet_check.py 192.0.2.10/26 192.0.2.70/24
A: 192.0.2.10/26
  네트워크: 192.0.2.0/26
  서브넷 마스크: 255.255.255.192
  범위 끝 주소: 192.0.2.63
  호스트 주소 범위: 192.0.2.1 ~ 192.0.2.62
B: 192.0.2.70/24
  네트워크: 192.0.2.0/24
  서브넷 마스크: 255.255.255.0
  범위 끝 주소: 192.0.2.255
  호스트 주소 범위: 192.0.2.1 ~ 192.0.2.254
A 기준으로 B 포함: 아니요
B 기준으로 A 포함: 예
주의: 주소 포함 계산은 경로·링크·방화벽·상대 상태를 확인하지 않습니다.
```

`/26`의 마지막 옥텟 구간은 0~63, 64~127, 128~191, 192~255다. A의 `.10`과 B의 `.70`은 A 기준으로 다른 구간이다. B는 `/24`이므로 `.10`을 자기 범위로 본다. 이 비대칭은 주소 계산이고, 실제 경로표·패킷 측정 결과가 아니다.

## D1. 격리 데모를 읽는 예시 — 미실행 예상 형태

아래는 [선택 스크립트](isolated_demo.sh)의 설명용 **합성 요약**이며 명령을 실제 Linux에서 실행해 얻은 로그가 아니다. 실제 스크립트는 각 단계에서 실행한 명령과 A·B의 주소·경로를 출력하고, `ping` 종료 상태도 표시한다. 실행 시 네임스페이스·veth 이름, `ping` 시간·문구는 달라진다.

| 단계 | A에서 기대하는 경로 | A에서 B로 `ping` 기대 | 판독 |
| --- | --- | --- | --- |
| A `.10/24`, B `.70/24` | `192.0.2.70 dev <이번 실행 veth> src 192.0.2.10` 형태 | 응답 | 두 노드가 직접 연결된 격리 데모의 조건 |
| A만 `.10/26`, B는 `.70/24` | 게이트웨이·별도 경로가 없으므로 조회 실패 | 실패 | A의 직접 연결 범위가 `.0~.63`으로 줄어듦 |
| A `.10/24` 복구 | 첫 단계와 같은 직접 경로 | 응답 복구 | 변경한 한 조건을 되돌림 |

실제 실행에서는 표의 기대와 자신의 `ip route get`·`ping` 출력이 일치하는지 확인한다. 이 표를 아올다 VM의 현재 주소·라우터·보안 정책 증거로 사용하지 않는다.
