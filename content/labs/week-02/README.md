# 2주차 IPv4 실습 키트

요약: 공동 질문의 답을 기존 VM의 P1 주소·경로 조회와 P2 주소 카드 손계산·검산으로 확인한다. 격리 마스크 변경은 선택이며 미실시는 필수 미완료가 아니다. 기본 실습은 읽기 전용 조회·계산이며 격리 데모는 권한과 환경을 먼저 확인한다.

## 시작 순서

1. [공동 질문](../../materials/week-02/WORKSHEET.md)·[핵심 개념](../../materials/week-02/ESSENTIALS.md)을 읽고 [Linux 실행 안내](LINUX.md)의 P1 관찰 → P2 계산/검산 → 자기 설명 → [분리 해설](../../materials/week-02/ANSWERS.md#공동-질문-해설)을 따른다. 기본 활동에는 관리자 권한이 필요하지 않다.
2. 온라인 자료에서는 [subnet_check.py](subnet_check.py) 링크로 파일을 내려받아 허가된 방법으로 Linux VM에 옮긴다. 오프라인 공유 묶음에는 파일이 들어 있다. 이 파일로 손계산을 검산하며 Python 표준 라이브러리만 사용한다.
3. 환경과 권한이 확인된 경우에만 [격리 데모](isolated_demo.sh)를 선택 실행한다. 운영 중인 VM의 인터페이스·경로를 바꾸지 않는다.
4. 접속·도구가 없으면 [제공 예제](SAMPLE_OUTPUT.md)를 분석하고 **예제 분석**으로 표시한다. 자기 Linux 관찰·선택 데모 수행과 구분한다.

Python·셸 입문자는 [코드 읽기](CODE_READING.md)에서 단계·문법·실패와 정리 흐름을 먼저 확인한다. 명령의 원문과 도구 채택 근거는 [실습 출처](../../materials/week-02/LAB_SOURCES.md)를 읽는다.

팀에서 함께 주소 카드를 계산하고 설명할 때는 [함께 찾을 질문](../../materials/week-02/WORKSHEET.md)을 사용한다. 각자의 Linux 조회·손계산·검산은 [개인 실습 증거](LINUX.md#개인-실습-증거-보관)에 한 번만 보관하고 함께 설명할 때 필요한 출력·풀이를 보여 준다. 제공 예제 분석 여부와 본인 직접 실행은 수행자별로 구분한다.

## 파일의 역할

| 파일 | 사용 범위 |
| --- | --- |
| `LINUX.md` | 참가자용 필수 명령, 예측, 판독, 증거, 대안 |
| `subnet_check.py` | 두 IPv4 주소/접두사의 범위와 서로 포함하는지 계산; 통신 여부는 판정하지 않음 |
| `isolated_demo.sh` | 선택: Linux 네트워크 네임스페이스와 veth를 일시 생성하고 종료 시 정리 |
| `SAMPLE_OUTPUT.md` | **미측정 교육용 예시**. 직접 관찰 증거가 아님 |
| `CODE_READING.md` | Python의 입력·판단·출력, 셸의 실험 순서·명령·오류 처리·정리 읽기 |

## 완료 증거

개인별로 조회 대상 Linux의 주소·접두사와 경로 출력, C1 양쪽 `/24`·C2 A만 `/26`의 손계산·검산을 남긴다. 짝이 바꾼 카드 조건 하나를 독립 재현하고, 다른 망일 때 게이트웨이나 별도 경로가 필요한 이유를 자기 근거로 소그룹에서 1~2분 설명하거나 출력을 읽으며 짝의 질문을 받는다. 예상·직접 실행·제공 예제를 구분한다. 선택 데모를 실행했다면 조건 변경 전·후·복구의 경로와 `ping` 결과를 별도로 기록한다. 주소 계산만으로 실제 도달을 보장한다고 쓰지 않는다.
