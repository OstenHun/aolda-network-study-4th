W13-MTU: 자체 계산/가공 사례. 실제 아올다 캡슐화나 실측이 아니다.
byte 단위. MTU는 해당 링크가 운반하는 IP 패킷 크기 기준이다.
옵션/IPv6 확장 헤더는 아래 별도 표시 외에는 없다고 가정한다.

[M0: 캡슐화 예산]
underlay IPv4 MTU=1500
가상 터널의 추가 바이트 H=50 (내부 Ethernet 헤더+터널/UDP/외부IPv4 합계라는 주어진 가정)
외부 Ethernet 헤더/FCS는 이 underlay IP MTU 바깥이라 다시 빼지 않는다.
inner IP=1450 -> outer IP=1500
inner IP=1500 -> outer IP=1550
터널 방식/추가 바이트는 실제 설정으로 확인하기 전 일반화하지 않는다.

[M1: IPv4 DF=1, 경로의 더 작은 링크]
sender interface MTU=1500, path bottleneck MTU=1450
small total IP length=100: 통과
large total IP length=1500, DF=1: router 폐기
router -> sender: ICMPv4 destination unreachable, type3 code4, next-hop MTU1450
sender가 관련 PMTU를1450으로 낮추고 더 작은 패킷을 보내면 통과하는 사례.
ICMP가 사라지면 큰 전송이 멈출 수 있음. 그것만으로 차단 위치/원인 확정 불가.

[M2: IPv4 DF=0, 같은 링크]
original IPv4 total length1500 = header20 + payload1480
fragment1: header20 + payload1424 =1444, offset0, MF1
fragment2: header20 + payload56 =76, offset178, MF0
조각의 마지막을 제외한 데이터 길이는8바이트 배수, offset단위8바이트.
재조립은 목적지에서 한다. 경로 정책은 조각을 버릴 수도 있다.

[M3: IPv6, 같은 크기 조건]
original IPv6 total length1500, bottleneck1450
router는 단편화하지 않고 폐기/ICMPv6 Packet Too Big(type2 code0), MTU1450.
송신자가 크기를 줄이거나 필요한 경우 Fragment 헤더로 출발지 단편화한다.
IPv6 기본 헤더40, TCP 기본20.

[M4: TCP 데이터 예산]
유효 IP MTU1450, IPv4 기본20, TCP 기본20 -> 데이터1410
유효 IP MTU1450, IPv6 기본40, TCP 기본20 -> 데이터1390
IPv4 TCP 옵션12를 실제로 넣으면 해당 세그먼트 데이터1398.
RFC6691의 MSS 광고값 계산은 고정 IP/TCP 헤더만 뺀다.
실제 송신 데이터는 상대 MSS/PMTU/옵션 등 제약을 함께 받는다.
MSS는 HTTP 본문 크기나 Ethernet 프레임 크기가 아니다. UDP에는 TCP MSS가 없다.
