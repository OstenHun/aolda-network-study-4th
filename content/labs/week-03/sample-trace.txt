3주차 설명용 합성 trace — 실제 캡처 아님
아래 IP/MAC/시각/패킷 번호는 교육용으로 만든 값이다. 이 파일은 pcap이 아니며 아올다 VM, 참가자 또는 진행자의 관찰 결과가 아니다.
192.0.2.0/24와 198.51.100.0/24는 문서 예제 주소다. 명령의 TARGET으로 복사하지 않는다.

사례 A: 같은 링크의 192.0.2.20으로 보내기
가정: VM A 192.0.2.10/24, MAC 02:00:00:00:00:10, dev eth0
경로 모형: 192.0.2.20 dev eth0 src 192.0.2.10 (via 없음)
초기 이웃 모형: 192.0.2.20 행 없음
A01 10:00:00.000000 02:00:00:00:00:10 > ff:ff:ff:ff:ff:ff, ethertype ARP: Request who-has 192.0.2.20 tell 192.0.2.10
A02 10:00:00.001000 02:00:00:00:00:20 > 02:00:00:00:00:10, ethertype ARP: Reply 192.0.2.20 is-at 02:00:00:00:00:20
A03 10:00:00.002000 02:00:00:00:00:10 > 02:00:00:00:00:20, ethertype IPv4: IP 192.0.2.10 > 192.0.2.20: ICMP echo request, id 100, seq 1
A04 10:00:00.003000 02:00:00:00:00:20 > 02:00:00:00:00:10, ethertype IPv4: IP 192.0.2.20 > 192.0.2.10: ICMP echo reply, id 100, seq 1
A05 10:00:01.002000 02:00:00:00:00:10 > 02:00:00:00:00:20, ethertype IPv4: IP 192.0.2.10 > 192.0.2.20: ICMP echo request, id 100, seq 2
A06 10:00:01.003000 02:00:00:00:00:20 > 02:00:00:00:00:10, ethertype IPv4: IP 192.0.2.20 > 192.0.2.10: ICMP echo reply, id 100, seq 2
이후 이웃 모형: 192.0.2.20 dev eth0 lladdr 02:00:00:00:00:20 REACHABLE

사례 B: 다른 링크의 198.51.100.8로 보내기
가정: VM A 192.0.2.10/24, MAC 02:00:00:00:00:10, dev eth0
경로 모형: 198.51.100.8 via 192.0.2.1 dev eth0 src 192.0.2.10
초기 이웃 모형: 192.0.2.1 행 없음
B01 10:05:00.000000 02:00:00:00:00:10 > ff:ff:ff:ff:ff:ff, ethertype ARP: Request who-has 192.0.2.1 tell 192.0.2.10
B02 10:05:00.001000 02:00:00:00:00:01 > 02:00:00:00:00:10, ethertype ARP: Reply 192.0.2.1 is-at 02:00:00:00:00:01
B03 10:05:00.002000 02:00:00:00:00:10 > 02:00:00:00:00:01, ethertype IPv4: IP 192.0.2.10 > 198.51.100.8: ICMP echo request, id 200, seq 1
B04 10:05:00.025000 02:00:00:00:00:01 > 02:00:00:00:00:10, ethertype IPv4: IP 198.51.100.8 > 192.0.2.10: ICMP echo reply, id 200, seq 1
이후 이웃 모형: 192.0.2.1 dev eth0 lladdr 02:00:00:00:00:01 REACHABLE
읽을 점: B03의 IP 목적지는 198.51.100.8이고 Ethernet 목적 MAC은 게이트웨이의 02:00:00:00:00:01이다. B04만으로 실제 중간 경로·상대 서비스의 상태까지 알 수 없다.

이 두 사례는 ARP가 반드시 나타난다는 예측이 아니다. 실제 VM의 캐시에 이웃이 있으면 ARP 없이 ICMP만 보일 수 있다. ICMP 응답이 없을 수도 있다.
